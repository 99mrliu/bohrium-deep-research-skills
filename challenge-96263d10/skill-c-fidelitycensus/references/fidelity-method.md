# 内容保真方法论（fidelity-census）

核心主张：**格式可以全部重排，内容单元一个不许无声增减。**
"转得全"的判据不是两份文件看起来差不多，而是普查-差异-声明三件事闭合：
普查给出内容清单，差异给出逐条定位，声明账本覆盖每一处差异。

## 内容单元的口径

| 单元 | 口径 | 为什么 |
|---|---|---|
| 文本单元 | 段落/表格（DOCX）、空行分块（文本型），比对前归一化空白 | 适配允许重排空白，不允许改字 |
| 数字 token | `\d+(\.\d+)?(%|‰)?`，避开标识符内部 | 数字漂移是格式适配最危险的事故（0.85 → 0.86 必须有任务依据） |
| 引用 token | `[12]`/`[1-3]`、`(Author, 2020)`、`（作者，2020）` | 引用号错位、年份丢失必须零发生 |
| 对象计数 | 图（drawing/pict）、OMML 公式、表格、脚注/尾注/批注、超链接、域、书签 | 图和公式最易在转换中被丢弃或图片化 |

脚注/尾注/批注的正文参与 token 统计（它们的数字同样是内容）。
DOCX 的 separator/continuationSeparator 伪脚注不计数。

## 三道工序的契约

1. `census.py` 对**源稿**和**交付产物**各跑一份（必须对交付目录里的最终文件跑，
   不许对工作中间件跑完就当交付证据）。
2. `census_diff.py` 报全等或逐条差异。identical=false 不是失败——
   任务本来就要求改动；失败是差异没有声明。
3. `change_ledger.py verify` 裁决覆盖：每个差异至少一条账本条目兜底。
   覆盖判定是**保守启发式**（见下），边界情况由 Agent 人工裁定，
   裁不定的进 result.json 的 manual_confirm。

## 覆盖判定口径（保守）

- text_mismatch：条目的 before 出现在源文本里（或 after 出现在产物文本里）。
- numeric/citation token 增减：条目的 before/after 含该 token。
- object_count：条目的 unit/reason 点名该对象类型（如 "tables"）。
- unit_count：必须有显式删除/插入声明（after 空为删、before 空为增）——
  "整体少了一段"永远不许被模糊条目覆盖。

## 边界与已知限制

- 判同不判序的例外：适配正常重排章节顺序时，文本序列比对会报大量
  text_mismatch——这时应先在账本声明"整章移动"（unit=章节标题，before/after
  为章节首尾句），再人工确认 diff 报告的剩余项。
- OMML ↔ LaTeX 公式互转属于内容改写：本工具只数个数，公式语义等价性
  必须人工核对并进 manual_confirm。
- 图片内容本身（像素）不比对——图片是否被替换靠对象计数 + 渲染目检。
