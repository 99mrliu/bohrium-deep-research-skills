# 「各写各的」失败模式与裁定口径

开题稿最高发的失败不是写得差，而是**要素之间对不上**：七个要素各自成立、合起来互相
不认识。本手册列出六类典型错配、对应的裁定规则与修复动作。裁定只认矩阵结构，不认
措辞好听——先把矩阵修过门，措辞问题才轮到 Agent 处理。

## F1 目标不挂问题（OBJ-FIELDS / RQ-COVER）

- 形态：研究目标写「阐明……机制」「揭示……规律」，不对应任何可证伪的研究问题；
  或 RQ 列表里有一个问题从头到尾没有目标去回答。
- 裁定：OBJ 缺 metric/threshold/threshold_basis/time_point 任一字段即 fail；
  RQ 无 OBJ 引用即 fail。
- 修复：把目标改写成「在 T 时点，用 M 指标判定是否达到阈值 θ（依据 B）」；
  回答不了任何 RQ 的目标删除，没有目标回答的 RQ 要么补 OBJ 要么删 RQ。

## F2 路线不服务目标（STEP-SERVE）

- 形态：技术路线里塞进「顺便做」的观测/实验，产出无人考核；常见于把课题组既有
  设备能力罗列成研究内容。
- 裁定：STEP 的 `serves` 为空即 fail，**不接受**「对后续研究有价值」之类口头辩护。
- 修复：要么给该步骤补上它服务的 OBJ（连带补 VAL 与 OUT，意味着扩大承诺），
  要么从路线中删去。预算与工期紧张时优先删。

## F3 成果无法考核（OBJ-COVER / OUT-FIELDS）

- 形态：预期成果写「发表论文 1–2 篇」「形成研究报告」，不挂目标、无验收判据。
- 裁定：OBJ 无 OUT 即 fail；OUT 缺 acceptance_criterion 即 fail。
- 修复：成果改写成可检查的交付物（数据集覆盖度、模型精度、报告章节），
  验收判据写成评审人可复核的条件句。

## F4 指标阈值无依据（OBJ-FIELDS: threshold_basis）

- 形态：阈值拍脑袋（「准确率达 90%」为什么是 90% 说不清）。
- 裁定：`threshold_basis` 为空即 fail；内容为「经验估计」「一般认为」视同为空，
  Agent 在填矩阵阶段就应打回。
- 修复：阈值必须锚定到前期数据、已发表基线或经费/工期约束的具体出处，
  并在 fact_source_map 中建条。

## F5 风险三连缺（RSK-FIELDS）

- 形态：风险段落写「可能存在数据不足、进度延迟等风险，将积极应对」。
- 裁定：trigger_signal / fallback / decision_point 缺任一即 fail。
- 修复：每个风险改写成「当观察到〈信号〉时，于〈时点〉前切换到〈备选方案〉」。

## F6 悬空引用（REF-INT）

- 形态：矩阵修订过程中删了实体没清引用——VAL 指向已删的 OBJ，RSK 指向改名的 STEP。
- 裁定：任何 id 引用无法解析即 fail；重复 id 同样 fail。
- 修复：按裁定报告逐条修正引用，不要靠通读排查。

## 裁定后的执笔纪律

矩阵过门后，开题稿各章节**从矩阵展开**：研究问题章=RQ 表，目标章=OBJ 表逐条成段，
技术路线章=STEP 按 depends_on 拓扑排序成图成文，风险章=RSK 表。稿中每个目标句必须
标注对应 OBJ id，收尾时逐句回查矩阵——这是「各写各的不可能发生」的机制保证。
