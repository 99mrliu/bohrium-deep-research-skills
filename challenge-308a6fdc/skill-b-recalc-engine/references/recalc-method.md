# 重算方法与核验规则（方法细节与限制）

## 1. 数据摄入

- 扫描输入目录中的 `.csv` / `.tsv`（`#` 开头的行视为注释跳过）；TSV 按制表符、CSV 按逗号解析（Python `csv` 模块）。
- 列类型判定：整列可解析为浮点 → `numeric`；取值重复且作为分组键 → `group`；唯一取值 → `identifier`；其余 → `text`。缺失值（空串/NA/NaN）计数后剔除。
- 输出 `dataset_profile.json`：每张表的行数、列类型、缺失计数。

## 2. 重算派生量（全部确定性、仅标准库 statistics）

对每张表的每个 `group` 列 × 每个 `numeric` 列组合：

| kind | 公式 | 说明 |
|---|---|---|
| n | count(x) | 组内非缺失行数 |
| mean | sum(x)/n | 算术均值 |
| median | statistics.median | 中位数 |
| SD | statistics.stdev | 样本标准差（n−1） |
| SEM | SD/√n | 均值标准误 |
| min / max | min(x) / max(x) | 极值 |

两分组派生量（基线 A = 组在数据中首次出现顺序的第一组，报告中注明）：

| kind | 公式 |
|---|---|
| diff | mean(B) − mean(A) |
| ratio | mean(B) / mean(A) |
| pct_change | (mean(B) − mean(A)) / mean(A) × 100% |

每条派生量写入 `derived_values.json`：`id`（D0001…）、`kind`、`formula`、
`inputs`（表、列、组、行数）、`value`。这是全案唯一合法的派生数字来源。

## 3. 三态核验的匹配规则

1. **RAW-SUPPORTED**：数字字符串在材料原文（排除草稿自身）某一行中出现，记录文件与行号。形如 `p = 0.032` 的数字先查原文；查不到直接判 `UNSUPPORTED-PVALUE`。
2. **DERIVED-SUPPORTED**：数字与某条重算值满足相对误差 ≤ `--rel-tol`（默认 0.005），或按重算值有效位数舍入后相等（誊写舍入豁免）。
3. **语义就近匹配**：数字上下文（±60 字符）中出现语义线索（均值/平均、标准差、百分比/%、比值/倍、n=/样本量……）时，只在**离数字最近**的那条线索对应的 kind 内匹配，防止"均值 4.79"误中 max=4.8 这类同值不同义的容差误报；无线索时在全部派生量中匹配。
4. **UNSUPPORTED**：上述均不命中。报告给出限定 kind 内最接近的重算值及其公式与输入，供改写。

## 4. 已知限制（如实声明）

- 不做统计推断：无 t 检验、方差分析、p 值计算（标准库无对应实现，绝不近似伪造）。材料给出的 p 值只做字符串核对。
- 只识别整表等宽 CSV/TSV；合并单元格、多级表头、嵌套 JSON 数据需人工先整理。
- 多分组（>2 组）只重算相对基线的两两派生量；其他对比由模型按公式手工重算并在 change_log 声明推导。
- 单位换算不做；稿件单位必须与材料一致，确需换算在 change_log 写明公式。
