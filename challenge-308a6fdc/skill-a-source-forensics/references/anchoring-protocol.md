# 锚定溯源协议（Anchoring Protocol）

本协议规定写作时如何给事实性论断挂锚，使 `anchor_audit.py` 能把每条论断解析回材料真实位置。

## 1. 锚语法

| 形式 | 含义 | 适用材料 |
|---|---|---|
| `[M2:L18]` | 材料 M2 第 18 行 | 文本类（txt/md/csv/json…） |
| `[M2:L4-L6]` | 材料 M2 第 4–6 行（区间） | 文本类 |
| `[M1:p3]` | 材料 M1 第 3 页 | PDF（需 pdftotext 抽取成功） |
| `[M1:p3-p4]` | 材料 M1 第 3–4 页 | PDF |

- 材料编号 `M1、M2…` 以 `/app/work/manifest.json` 为准（按相对路径排序分配，确定性）。
- 行号以 `/app/work/extracted/Mx.txt` 为准（与原文件行号一致）；页号以 `Mx.pages.json` 为准（与 PDF 物理页一致）。
- 锚写在**论断句句尾**（标点之前或紧邻标点之后均可，审计会把句后纯锚碎片并回前句）。
- 一句可挂多个锚：`……[M2:L7][M3:L5]`；每个锚独立核验。

## 2. 哪些句子必须挂锚

满足任一条件即视为"事实句"，必须挂锚（否则被判 UNANCHORED-CLAIM）：

1. 句中含任何数字（含年份、百分比、编号）；
2. 句中含事实线索词：表明、显示、证明、证实、指出、提升、提高、下降、降低、达到、占比、约为、超过。

观点、过渡句、无数字无线索词的句子不要求挂锚，但挂了也会被核验。

## 3. 核验规则（audit 如何判）

对每个锚：

1. **存在性**：材料号存在、锚种类匹配（文本材料用 `L`，PDF 用 `p`）、行/页号在有效范围内；否则 `ANCHOR-INVALID:*`。
2. **内容共振**：论断句与锚位原文（行锚取 ±2 行上下文，页锚取该页前 200 字符）须共享至少一个**关键 token**：
   - 数字（可带小数与 `%`）；
   - ≥4 字符的英文词（大小写不敏感）；
   - 中文 4 字滑窗（论断句中任意连续 4 个汉字出现在锚位原文即算）。
   不满足 → `ANCHOR-MISMATCH`。
3. **漏锚**：事实句无锚 → `UNANCHORED-CLAIM`。

结论 PASS 的条件：`ANCHOR-MISMATCH/INVALID = 0` 且 `UNANCHORED-CLAIM = 0`。

## 4. 写作时的挂锚手法

1. 先跑 intake，打开 `/app/work/extracted/Mx.txt`，**带着行号读材料**。
2. 写事实句时立即把所依据的行/页号写进句尾锚；数字务必与原文逐字一致。
3. 跨行/跨页依据用区间锚；多处依据用多锚。
4. 无法从材料证实的句子：删除，或保留并标 `【待确认】`（审计豁免但会在报告中公示，并计入 result.json 的 pending 数）。
5. 确实不需要审计的辅助行（如图例说明），可在行内加 `<!-- audit-skip -->`；代码块、标题、引用块、表格默认跳过。**禁止滥用 audit-skip 隐藏事实句**。

## 5. 误报处理

| 误报场景 | 正确处理 |
|---|---|
| 论断是原文数字的换算（如"约六成"对应 64%） | 在句中保留原数字（如"64%，约六成"），让数字 token 共振 |
| 中文措辞与原文完全不同（同义改写） | 改写论断句使其与原文共享 ≥4 字片段，或加挂第二个锚 |
| 英文术语被大小写/连字符拆开 | 调整措辞与原文一致（如 `RoBERTa` 照抄原文拼写） |
| 合理引用但确实无共同 token | 标 `【待确认】` 并在 change_log 说明；**不得**换一个不相干的锚充数 |

红线：锚只能指向论断真实依据的位置。为通过核验而移动锚、编造区间、或在锚位原文中"埋字"，均属伪造溯源，违反本 skill 的存在意义。
