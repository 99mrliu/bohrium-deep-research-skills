# 单位口径与编码嗅探

## 单位来源优先级

1. **task.md 显式声明**：正则 `name（unit）` / `name (unit)`（如 `strength（MPa）`）；
   全文级声明（"单位 cm"）作为该数据集所有测量列的兜底。
2. **已知指纹提示**：形状唯一命中注册表时的单位提示（如 iris→cm、concrete→MPa/kg·m⁻³/天），
   标注 `fingerprint_hint` 来源。
3. **unknown**：如实标注，进 digest 待确认；**禁止编造单位**。

## 常见单位/量级陷阱（只提示，不擅自换算）

- 10³ / 10⁶ 量级差：kg↔t、g↔kg、mm↔cm↔m；同一变量跨源均值差约 10³/10⁶ 倍时写 warning。
- 12 / 2.54 因子：英尺/英寸 ↔ 米/厘米。
- 百分数 0–1 vs 0–100 两种口径。
- 日期/龄期单位混用（天 vs 月 vs 年）：分组前必须确认，如 concrete 的 age 是天。
- 判别动作：自动化审计靠逐值比对发现（量级不同必然体现为 value mismatch）；agent 在读 digest 时若见跨源值不一致，先按本清单核对是否量级因子，再决定覆盖 `primary_source` 或在 limitations 注明，**不擅自换算**。

## 编码嗅探顺序（确定性）

`utf-8-sig`（覆盖 BOM 与纯 UTF-8）→ `gbk`（中文 Windows 导出常见）→ `latin-1`（永不失败兜底）。
选中的编码写入审计结果； latin-1 兜底命中时提示"编码不确定，请人工确认"。

## 分隔符与表头

- 分隔符：`csv.Sniffer`（候选 `, ; \t |`）→ 失败时按首行候选计数取最大，默认 `,`。
- 表头判定：存在至少一列，其首行不可解析为数值而 ≥90% 数据行可解析 → 有表头。
  全数值首行（如 bezdek iris 首行就是数据）→ 无表头，列名走指纹提示或 c0..cN。
- 全文本首行但数据也全文本 → 判定可能出错，写入 uncertainty。

## 缺失 token 清单（大小写不敏感）

`""`, `NA`, `N/A`, `NaN`, `null`, `-`, `none`。
注意 `-` 在某些数据里是合法值（如方向标记）——若该列非数值列，`-` 仍按缺失处理并在报告中明示；有异议用 decide 覆盖或在 limitations 注明。
