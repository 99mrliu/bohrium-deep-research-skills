# 确认项清单模板（confirmation_checklist.md）

**用途**：凡无法由 Agent 自主证实的事项，一律进 `confirmation_items`，不得写成可执行事实
（SPEC 科学诚实条款）。`risk_fmea.py audit` 机械检查四类覆盖：**安全 / 伦理 / 设备可用性 /
专家确认**，缺任何一类即 verdict=GAP。

每条确认项结构：

```json
{"category": "安全|伦理|设备可用性|专家确认",
 "item": "需要确认的具体事项",
 "why": "为什么不能自主证实（证据缺口）",
 "blocking": true,
 "status": "pending"}
```

## 一、安全类（每个方案至少 1 条，永远第一类）

- [ ] 涉及化学品清单已核对实验室 MSDS 与管制目录（如 DMF 有毒、Pb 化合物重金属管控）
- [ ] PPE 配置与应急处置卡已张贴（冲淋器/灭火器位置已确认）
- [ ] 手套箱/通风橱运行状态与应急断电流程已确认
- [ ] 高温设备（加热台/烘箱/马弗炉）周边可燃物清理与值守制度已确认
- [ ] 废弃物分类处置渠道（含重金属废液）已确认

## 二、伦理类

- [ ] 不涉及人体/动物实验；若涉及，伦理批件编号与有效期已确认
- [ ] 数据采集不涉及个人信息；若涉及，知情同意与脱敏方案已确认
- [ ] 材料/样本来源合规（如生物材料转移协议 MTA）已确认
- [ ] 无伦理风险时也要显式写一条："本方案不涉及伦理敏感对象，已自查确认"

## 三、设备可用性类（组织方合同为前瞻约定，必须确认而非引用为事实）

- [ ] 每台设备的预约状态已查预约系统（对照 case.json `booking.slots_per_week/slot_hours`
      估算所需 slot 数，缺口 >1 周即触发 FM-EQBUSY 升级流程）
- [ ] `equipment_domain_note` 文本内嵌设备（不在 equipment 列表者）的可用性与计价已单独确认
- [ ] 设备校准有效期覆盖实验窗口（对照 spec 允差，如加热台 ±2°C）
- [ ] 关键试剂库存/货期已确认（前瞻合同的 unit_price/pack_size 仅为计划性约定，
      不是实际供应商报价）
- [ ] 关键试剂双供应商备选渠道已确认可下单

## 四、专家确认类

- [ ] 高 RPN 失效模式的设计修改（预实验、双供应商、替代设备）已经导师/领域专家过目
- [ ] 有限参数域外的任何参数变更已经专家批准（组织方参数域是硬约束）
- [ ] 连续异常触发的升级结论（如 FM-CONTAM 连续 2 批污染）已获专家签字确认
- [ ] 预算/时间不足以补足统计功效时的研究目标缩减，已获 PI 书面确认

## 填写规则

1. 四类每类至少 1 条；确认前 `status` 保持 `pending`，方案对应步骤标记为"待确认后执行"。
2. 确认项的结论回填后，同步更新 `result.json` 的 `change_log`。
3. audit 连续 3 轮仍缺类 → 不伪造确认，result.json 标 `status: "partial"` 并写明缺口。
