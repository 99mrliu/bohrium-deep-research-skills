# 检索式构造方法：概念块、意图标签与 R1–R9 规则

（本文件所有示例均为合成示例/虚构内容。）

## 1. 概念块设计

把研究问题分解为**必须同时成立**的概念面（facet），每个概念面一个块：

- 块与块之间默认 AND（研究问题 = 各概念面的交集）；块内词项为同义/近义表述，
  以 OR 连接。`operator` 字段声明该块与前一块的连接方式，只允许 AND/OR。
- 块数 ≥2（R1）：单块检索式无法表达"交集约束"，召回噪音不可控。
- 每块至少保留 1 个 `core` 或 `variant` 词项（R8）：纯分类号块没有文本锚点，
  在字面匹配引擎上会退化为空约束；分类块也必须带一个描述性词项
  （如"金属空气电池"之于 "H01M 12/06"）。
- 空块（无词项或词项文本为空）一律拒绝（R3）：空块语义不明，宁可报错也不猜。

典型三块结构（以虚构的"柔性锌空气电池"为例）：

1. **体系块**：锌空气电池（core）、锌-空气电池（variant，连字符变体）。
2. **特征块**：柔性（core）、可穿戴（variant，应用场景近义面）。
3. **上位/分类块**：金属空气电池（core）、H01M 12/06（classification）。

## 2. 意图标签语义（R2）

| intent | 语义 | 渲染/执行中的作用 |
| --- | --- | --- |
| core | 概念面的规范表述 | 参与块内 OR；统计其文档命中数 |
| variant | 拼写/连字符/上下位/场景变体 | 与 core 等同参与 OR；扩充召回的首选手段 |
| classification | 分类号类词项 | 参与块内 OR；同时在 patent 轨经 classification_codes 形成独立过滤 |
| exclusion | （仅作为合法标签值保留） | **块内禁止使用**——一经出现即报 R4；排除必须走顶层 exclusion_terms |

R2 要求每个词项显式携带 intent，因为 intent 是检索式可解释性的最小单位：
没有 intent 的词项无法回答"这个词为什么在检索式里"。

## 3. R1–R9 规则与设计理由

| 规则 | 内容 | 理由 |
| --- | --- | --- |
| R1 | ≥2 个概念块 | 交集约束是主题检索召回控制的基本手段 |
| R2 | 每词标 intent | 可解释性；也是 R8 与遗漏统计的前提 |
| R3 | 禁止空块/空词 | 空约束语义不明，报错优于猜测 |
| R4 | 禁止裸 NOT；排除仅走 exclusion_terms 且附 reason | 裸 NOT 是召回杀手且不可审计；集中管理排除词才能产出"排除理由"证据 |
| R5 | classification_codes 仅 patent 轨生效 | 论文没有专利分类体系；npl 渲染丢弃并记录 NOTE，避免静默语义漂移 |
| R6 | research_question 必填 | 检索式必须可追溯到问题；否则无法判断召回相关性 |
| R7 | date_range 为合法 ISO 且 start ≤ end | 日期是渲染输出的一部分，非法日期会污染可复现性 |
| R8 | 每块 ≥1 个 core/variant 词 | 保证每块都有文本锚点（见 §1） |
| R9 | 渲染可复现：同 spec → 同串 | 块内词项按 (intent 优先级, 文本 casefold) 规范排序并去重；差异排查只比对字符串即可 |

## 4. patent 轨与 npl 轨的检索逻辑差异

| 维度 | patent 轨 | npl 轨 |
| --- | --- | --- |
| 分类号 | classification_codes 作为硬过滤（文档前 matter `classification:` 与规格求交） | 无此概念，渲染时丢弃并输出 NOTE |
| 去重键 | 同族号 family；无则规范化公开号（去非字母数字、大写） | DOI（小写）；无则规范化标题（去标点、压缩空白） |
| 同族/版本语义 | 同一发明的多国/多阶段文本视为一条记录 | 同一论文的预印本/期刊版靠 DOI 或标题归并 |
| 排除词 | 与 npl 相同：命中即整篇排除并记录理由 | 同左 |

两轨共享：字面词组匹配（大小写不敏感、连续子串；ASCII 词项附加字母数字边界
以防 "H01M" 误中 "H01M12"）、块间 AND 语义、排除词机制。

## 5. 召回调优纪律

- 召回不足时优先增补 `variant` 词项（连字符、缩写、中英文、上下位词），
  每次增补记录到 `change_records` 并重跑全管线——计数会变，必须脚本重算。
- 召回过宽时优先收紧块（把过宽的 variant 移出）或增加概念块，**不要**引入裸 NOT；
  确需排除时把词加入 `exclusion_terms` 并写清理由。
- 任何"凭经验觉得应该有"的命中都必须能落到 file+line 定位，否则视为不存在。
