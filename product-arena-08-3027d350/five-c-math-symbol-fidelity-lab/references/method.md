# 方法说明:基线分组与上下标阈值的推导

## 1. 为什么用 origin.y 而不是 bbox.y0 做基线锚

PyMuPDF `rawdict` 给出的 char 级 `bbox` 是**字体 ascent/descent 盒**按字号缩放的结果,
不是紧包字形盒。实测(合成示例,12pt Helvetica):

- 主字号字符: `bbox = [x0, 169.10, x1, 185.59]`,高 16.49pt ≈ 1.374 × 字号;
- 上标 "2"(7pt,基线升起 6pt): `bbox = [121, 168.48, 124.89, 178.09]`;
- 若比 bbox.y0: 169.10 − 168.48 = 0.62pt,远小于真实升起量 6pt —— 大部分位移
  被"字号变小 → 盒变矮"抵消。

而 `origin` 是字符基线起点,直接携带文本位移(Tm/Td/Ts)信息:主行 origin.y=182,
上标 origin.y=176,差 6pt = 内容流里的真实升起量。因此本 Skill 以 **origin.y 中位数**
作为基线锚,`bbox` 高度仅用于估计"组字高 H"。这与任务书"y0 比基线组高"的语义一致
(y0 即字符相对基线的竖直位置),只是改用不受字号混淆的测量量。

## 2. 阈值推导

三个阈值(代码与 SKILL.md、本文件保持一致):

| 参数 | 值 | 推导 |
|---|---|---|
| `SCRIPT_SIZE_RATIO` | 0.8 | 排版惯例上下标字号为正文的 58%–70%(TeX 默认 scriptstyle≈70%、scriptscriptstyle≈50%)。取 0.8 作为上界:≤0.8×行中位字号才可能是上下标,留出对 75% 缩放排版的容忍,同时把偶发的 90% 字号波动排除 |
| `SCRIPT_OFFSET_RATIO` | 0.25 | 上标基线升起量惯例为 x 高度的 60%–100% 或字号 20%–35%。以组字高 H(bbox 高度中位 ≈1.37×字号)为分母,0.25×H ≈ 0.34×字号,落在惯例区间下沿;过小会把抗锯齿/舍入抖动(±1pt)误判为上标,过大会漏判浅升起排版 |
| `BASELINE_TOL_RATIO` | 0.3 | 同组判据:y 中心差 < 0.3×中位字高。行内字符 origin.y 的抖动主要来自子像素定位与多行重叠合并,经验值 <0.15×H;取 0.3×H 留一倍余量,又小于上下标判据 0.25×H+字号差带来的最小偏移,避免把上标吸回基线组 |

判定流程(`linearize_math.py: classify_baseline`):

1. 行内字号中位 `med_size`;主组 = 字号 > 0.8×med_size 且有 origin 的字符;
2. `H` = 主组 bbox 高度中位,`base_y` = 主组 origin.y 中位;
3. 对每个字符算 `dy = base_y − origin.y`(坐标系原点在左上,y 向下为正):
   - 字号 ≤0.8×med_size 且 dy ≥ 0.25×H → **上标** `^{...}`;
   - 字号 ≤0.8×med_size 且 −dy ≥ 0.25×H → **下标** `_{...}`;
   - 字号 ≤0.8×med_size 但 |dy| < 0.25×H → 按基线处理 + `small-size-no-offset` 告警;
   - 主字号但 |dy| > 0.3×H → `baseline-drift` 告警(仍按基线输出)。

合成示例实测:上标 dy=6pt ≥ 0.25×16.49=4.12 ✓;下标 dy=−5pt,|dy|=5 ≥ 4.12 ✓;
7pt ≤ 0.8×12=9.6 ✓。正文 12pt 字符 dy≈0 ✓。

## 3. 行分组(detect_math_zones)

按 y 区间重叠聚合:两字符 bbox 竖直区间相交则同行;聚合后做链式合并直到不动点。
上下标的 bbox 与主行区间必相交(它们嵌在行高之内),因此同行;相邻正文行间距
(≥1.2×字号)远大于区间重叠,不会误并。行内字符再按 x0 排序恢复阅读顺序。

## 4. 编号配对

行右端 `(n)`(n 为 1–4 位数字):正则 `\((\d{1,4})\)$` 命中行尾串,且编号串首字符
x0 ≥ 行 x 跨度的 60%(排除行内括号如 `f(x)`)。命中则从公式体剥离,存入
`number` 字段;verbatim 保留原样(含编号),linear 为剥离后的公式体。

## 5. 已知局限

- 多行公式(如对齐方程组)按行切分,不跨行重组;
- 上下标链(E_i^2 同基元双标)按 x 序分别输出 `_{i}^{2}`,不保证语义绑定;
- 分式、根号等二维结构不做结构重建,只线性化字符序;
- word 级降级页(pdftotext 引擎)无字号信息,上下标判定整体跳过并标 partial。
