# OCR 混淆对表与上下文判定规则

本表是 `scripts/ocr_postcheck.py` 的规则来源；代码与本表必须一致。
原则：**宁可不改，不可改错**——只有唯一解才改正，其余一律进 suspects 台账。

## 1. 单字符混淆对

| 字符 | 易混淆为 | 典型场景 |
|------|----------|----------|
| `1`（数字一） | `l`（小写 L）、`i`、`I`（大写 i） | 无衬线字体中字形几乎相同 |
| `l`（小写 L） | `1`、`I` | 同上 |
| `I`（大写 i） | `1`、`l` | 同上 |
| `\|`（竖线） | `l`、`1` | 表格线/扫描伪影被识别为字符 |
| `0`（数字零） | `o`、`O` | 圆/椭圆字形混淆 |
| `O`（大写 o） | `0` | 同上 |
| `o`（小写 o） | `0` | 同上（公式与编号中常见） |
| `5`（数字五） | `s`、`S` | 顶部横画断裂时混淆 |
| `S` | `5` | 同上 |
| `s` | `5` | 同上 |

## 2. 多字符混淆对

| 序列 | 易混淆为 | 典型场景 |
|------|----------|----------|
| `rn` | `m` | 低分辨率下 r+n 粘连成 m（如 infrared→infrarred 类之外的 `rnicrowave`→`microwave`） |
| `m` | `rn` | 反向，m 中缝断裂成 rn |
| `cl` | `d` | c+l 粘连成 d |
| `d` | `cl` | 反向，d 的竖画与圆弧分离 |
| `vv` | `w` | 两个 v 连写成 w |
| `w` | `vv` | 反向，w 中缝断裂 |

## 3. 上下文判定规则

对不在词典中的 token，逐位置（或逐多字符窗口）做单点替换，得到候选集后：

1. **字母上下文**：token 其余部分皆为字母 → 偏向字母形替换
   （如 `1nfrared` → `infrared`，而不是保留数字）。
2. **数字上下文**：token 仅含一个非数字字符、其两侧皆数字 → 偏向数字形替换
   （如 `2O25` → `2025`，规则名 `numeric_context`）。
3. **词典唯一解**：替换候选的小写形式【恰好一个】在词典中 → 改正，
   记 `corrections` 台账（page、line、from、to、rule）。
4. **多解**：≥2 个不同小写形式都在词典（如 `ha1l` → `hall` / `hail`）→
   进 `suspects`，原文保留，不改。
5. **无解但字母数字混排**（如 `x9z`）→ 进 `suspects`，原文保留，不改。
6. **无解且为正常字母词**（词典未收录的专名、术语）→ 仅计入
   `unknown_words` 统计，不改、不报 suspect。

## 4. 大小写处理

- 词典为小写集合；命中判断对 token 小写后进行。
- 同一小写形式有多个大小写变体（如 `1`→`i`/`I` 都得到 `infrared`）时
  视为同一解，不构成分歧；按原 token 的大小写风格选替换形式
  （原 token 全小写 → 选全小写变体）。

## 5. 保守性底线

- 不做双点及以上替换，不做编辑距离模糊的"近似纠错"。
- 所有改正逐条记账（corrections），所有拿不准逐条列出（suspects），
  `corrected.txt` 与原文同结构，除台账记载的替换外无任何其他改动。
