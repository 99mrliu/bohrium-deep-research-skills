# 易混字段与口径陷阱清单（confusable fields）

判断字段含义时的常见陷阱与取舍规则。命中任一条都必须在报告或异常清单
中写明取舍理由。

## 1. 编码型数值字段（最危险）

整数类型、取值水平少（≤10）的列通常是**编码**而非度量：Wine 的
`class`(1/2/3)、问卷量表、状态码。对它们做 AVG/SUM 得到的"平均值"没有
物理意义。规则：只报计数与比例；任务坚持要均值时，给出计数/比例并在
异常清单中说明拒绝数值聚合的理由。

## 2. 状态类近义字段

`sample_status` vs `experiment_status`、`state` vs `status`：一个描述样本
（材料是否合格），一个描述流程（实验是否完成）。两者同时存在时，分组/
筛选用哪个必须按任务方数据字典取舍并写明；无字典时列入歧义队列，不得
任选其一。

## 3. 0 与 NULL 的对立

配料类数据（Concrete 的 slag/fly_ash/superplasticizer）中 **0 是真实的
"未掺加"**，不是缺失；而 NULL 才是缺失。清洗时把 0 当缺失删掉会系统性
高估均值。规则：0 与 NULL 分别计数、分别报告；口径中写明 0 的处理方式。

## 4. 单位量级差异

同一表内量纲量级可差两个数量级（Wine 的 proline ~10³ vs hue ~10⁰）。
跨列比较、距离计算、绘图同轴之前必须声明是否归一化及方法。

## 5. 时间字段的"离散测试点"

Concrete 的 `age` 是离散的测试龄期（1/3/7/28/...天），不是连续日历。
按天做连续插值或按日频聚合都是口径错误；按测试点分组。

## 6. ID 列

distinct == 行数的列是标识符：可作连接键与溯源键，**永不进入聚合**；
对 ID 求均值/作图是无意义产物，属质量事故。

## 7. 类别标签的多套拼写

`Iris-setosa` vs `setosa` vs `SETOSA`：分组前先做标签归一化检查
（distinct 列表见 field_profile.json 的 levels），发现多套拼写时报告
并按显式映射表合并，映射表本身作为交付证据。
