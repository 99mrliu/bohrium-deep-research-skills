# 分歧裁决协议

本协议约束 `adjudicate.py` 的书面裁决链。目标不是让两个通道“投票平均”，而是让每个最终分都能追溯到行为锚点、源文证据与明确理由。

## 1. 分歧分类

| 类型 | 识别特征 | 首要处置 | 示例 |
|---|---|---|---|
| 抽取层错误 | 引文、行号、字段名、单位或符号读取错误 | 回到源材料重新机检；以可复核原文为准 | 连字归一化后仍找不到 quote；把 18.4 读成 184 |
| 锚点歧义 | 引文真实存在，但“声称锚点”过宽、错位或一节多名 | 缩小到节/行区间；不能定位则证据锚定降档 | quote 在全文出现，却不在声明的“表征结果”节 |
| 档位边界 | 两通道对 0/1/2 中相邻档的严重程度判断不同 | 对照行为锚点，写清触发哪一条升/降档条件 | “主体正确但一处无源扩展”应判 1 而非 2 |
| 规则盲区 | rubric 未覆盖新情况，或两个锚点要求冲突 | 临时裁决并记录规则补丁；影响结果可靠性时升人工 | 表格单位与正文单位冲突且任务未规定优先级 |

## 2. 裁决记录格式

每个分歧必须有如下对象；缺 `rationale` 或缺可定位 `evidence_anchor` 时，脚本必须拒绝该记录并保持 `pending`：

```json
{
  "item": "Q2",
  "dimension": "correctness",
  "pass1": 2,
  "pass2": 1,
  "final": 1,
  "rationale": "参考答案主体数值正确，但包含源文未报告的应用推断，命中正确性 1 分锚点。",
  "evidence_anchor": {
    "source": "source_excerpt.txt",
    "locator": {"line_start": 7, "line_end": 10},
    "quote": "紫外-可见吸收边拟合得到光学带隙 3.21 eV。"
  }
}
```

写作要求：

1. 先引用分歧双方的分数，再说明最终分。
2. 理由必须指向行为锚点，例如“命中正确性 1 分：主体正确但一处无源扩展”。
3. 证据锚点必须能让第三方回到源材料；不得只写“见原文”。
4. 不得为了清零 pending 而无理由选择一个通道；不得取两个档位的平均。
5. 若裁决修改了机器可判项，应说明机器检查为何失效，并给出可复算输入。

## 3. 何时必须升人工

出现以下任一情况，应把项目加入 `human_review.md` 队列，并将 `result.json.status` 保持为“部分完成”：

- 裁决后仍有 pending 分歧；
- κ < 0.4，或同一维度出现多项分歧，提示规则无法稳定执行；
- 边际分布单类别退化且观察一致率也低；
- 源材料冲突、缺页、OCR/PDF 抽取失败，且冲突影响参考答案；
- 题卡要求材料外专业知识，而任务没有明确允许；
- 两个通道的 `rationale` 都空泛，无法定位到行为锚点；
- 裁决需要判断知识产权、授权或许可证真实性，而材料中没有授权信息。

`human_review.md` 队列条目的最小字段：`item`、`dimension`、两个通道分值、待决问题、已核验证据、建议人工查看的源位置。

## 4. 最终状态铁律

- 存在任何 pending 分歧时，`result.json.status` 只能是“部分完成”，且 `status_reason` 必须指明 pending 数与限制。
- pending 清零后才可标记“成功”；这表示流程完成，不表示每题都满分。
- 若源材料不可用、contract 无法解析或评分对象缺失，应标“无法判断”；若任务要求编造材料外事实，应标“拒答”。
