# alignment.json 格式与状态分类

## 1. 文件结构

```json
{
  "pairs": [
    {"src_id": "P0001", "tgt_ids": [0], "status": "aligned", "anchor_score": 1.0}
  ],
  "coverage": {
    "source_paragraphs": 6,
    "aligned": 5,
    "missing": ["P0006"],
    "extra": [5],
    "anchor_mismatch": ["P0005"],
    "order_swaps": ["P0005"]
  }
}
```

- `pairs`:按源段落顺序排列的对齐记录;`tgt_ids` 是目标文件中的**块下标**(从 0 起)。
- `extra-translation` 记录的 `src_id` 为 `null`;`missing-translation` 记录的 `tgt_ids` 为 `[]`。
- `coverage.aligned` = 已配对的源段落数(不含 missing);
  恒有 `source_paragraphs == aligned + len(missing)`。

## 2. 锚点定义

每段提取的锚点集合:

| 锚点 | 正则 | token 形式 |
| --- | --- | --- |
| 数字 | `\d+(?:\.\d+)?` | `n:<数字>` |
| 引用标记 | `[n]` / `[n, m]` / `[n-m]` | 每个数字一个 `n:<数字>` |
| 图表引用 | `Fig\.?\s*\d+|Table\s*\d+|图\s*\d+|表\s*\d+` | `ft:<原文>` |

引用数字被并入 `n:` 锚点,因为引用编号在翻译中几乎原样保留,是跨语言最可靠的锚点。
匹配分数为锚点集合的 Jaccard 相似度。

## 3. 状态分类表

| 状态 | 严重程度 | 含义 | 必要的人工动作 |
| --- | --- | --- | --- |
| `aligned` | 正常 | 锚点匹配成功(或有标签硬对齐) | 无需 |
| `anchor-mismatch` | 警告 | 两侧都有锚点但重叠为 0,仍强行配对 | 人工核对该段译文是否对应 |
| `merged-in-target` | 提示 | 多个连续源段落被译文合并为一个块 | 确认合并是有意的;若合同要求逐段,需拆开重译 |
| `split-in-target` | 提示 | 一个源段落被译文拆成连续多块 | 确认拆分是有意的;通常可接受 |
| `missing-translation` | **阻断** | 源段落没有任何译文块 | **必须补译**;脚本以退出码 1 阻断交付 |
| `extra-translation` | 警告 | 译文块没有对应源段落 | 人工确认是译者注还是多余内容;不得静默删除 |
| `order-swap` | 警告 | 该对使用的目标块下标小于此前用过的最大下标(乱序) | 人工核对译文顺序,还原正确段落次序 |

规则:**任何缺口/多余/乱序只登记、不静默修补**。修复必须发生在翻译环节
(补译、调序),然后重跑对齐,而不是在渲染环节掩盖。

## 4. `[[PXXXX]]` 标签约定

- 译文文件(`target_zh.txt`)中,每个段落块**首行**可写 `[[P0001]]` 形式的标签,
  声明该块是源段落 `P0001` 的译文。
- 带标签的块被**无条件**接受(hard alignment),跳过锚点匹配;
  同一标签出现两次即判定为 `split-in-target`。
- 推荐工作流:翻译时逐段复制 seg_id 作为标签 → 对齐 100% 确定;
  无标签时回退到锚点贪心对齐,用于审查他人译文或粗分块译文。
- 标签必须独占一行首,形如 `[[P0001]]`(四位数字,允许前导空格)。
