# 严重级别判据与人工队列契约

## Blocker vs Warning 判据

| code | 级别 | 判据 | 理由 |
|---|---|---|---|
| number-dropped | BLOCKER | 源文数值（含归一化形式）在译文中不存在 | 数值缺失直接改变事实陈述，不能放行 |
| number-changed | BLOCKER | 译文出现与源文同单位但取值不同、且未见于源文的数字 | 数字被篡改（如 21.3%→23.1%）属高危静默错误 |
| unit-changed | BLOCKER | 数值在，但相邻单位归一化后与源文单位不同（mM→μM 等） | 单位错误等价于数量级错误 |
| citation-lost | BLOCKER | 源文引文多重集 ⊄ 译文多重集（有缺失） | 证据链断裂，学术交付不可接受 |
| ref-lost | BLOCKER | 图/表/公式引用多重集有缺失 | 读者无法定位证据，且常伴随内容漏译 |
| negation-lost | BLOCKER | 源文含否定提示而译文无任何中文否定标记 | 否定翻转 = 结论反转，最高危语义错误之一 |
| hedge-lost | WARNING | 源文含模糊/转折提示而译文未体现 | 语气弱化影响严谨性但通常不改事实，可由人工确认放行 |
| number-format | WARNING | 数字仅以归一化形式匹配（千分位/空格差异） | 格式层面提示，防误报升级 |
| target-missing | BLOCKER | pairs 中缺少该段译文 | 无法核验 = 不得静默通过 |
| unable_to_determine | BLOCKER（流程上） | 图片内数字、OCR 乱码、单位词典外形式等机器不可判定 | 必须人工比对，禁止默认放行 |

原则：**机器无法判定的，一律显式升级给人，绝不默认通过**；只有“明确通过”才算通过。

## 人工确认队列契约（对应挑战的“需要人工确认的清单”）

1. **覆盖范围**：全部 BLOCKER（修复前）+ 全部 WARNING + 一切 `unable_to_determine` 项，逐条列出，无静默丢弃。
2. **条目格式**：`- [ ] [seg_id] code — reason`，附源文/译文逐字片段与建议动作。
3. **谁可关闭**：
   - BLOCKER：由修复译文的人重跑 `check_fidelity.py` 直至该项消失，或经具备领域资质的人工书面确认“源文/抽取误判”后关闭；
   - WARNING / 无法判断项：只能由人工审阅者关闭，机器无权关闭。
4. **关闭证据**：每条关闭必须在“处理记录”行注明处理人、关闭方式（修复译文 / 人工确认 + 依据）、并关联重跑后的报告；无记录的关闭无效。
5. **放行条件**：交付状态为 `success` 当且仅当 blockers == 0 且队列中无未处理的 BLOCKER；WARNING 可携带交付，但必须保留在队列中供最终签收。

## 与流水线的关系
`check_fidelity.py` 退出码 1 ⇔ 存在 BLOCKER ⇔ 禁止交付；`review_queue.py` 把报告原样转写为 checklist，不增删条目，保证“报告 = 队列”一一对应。
