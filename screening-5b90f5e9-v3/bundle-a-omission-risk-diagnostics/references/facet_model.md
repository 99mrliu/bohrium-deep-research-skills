# 主题面（facet）模型与覆盖核查语义

## 1. 为什么需要 facet 覆盖核查

逐条判定再仔细，也可能出现**系统性盲区**：某一主题面（人群、干预、对照、结局、设计……）
在纳入集中整体缺席。缺席有两种相反的解释——该面真的没有合格文献（真空），或检索式未覆盖 /
筛选过严（遗漏）。仅靠排除队列看不到这种结构性风险，因此需要从研究问题分解出的 facet
与纳入集做正交比对。

## 2. facet 分解方法

在 case.json 中以结构化形式给出，建议遵循 PICOS 思路并按研究问题裁剪：

```json
{
  "facet_id": "F2_intervention",
  "label": "GLP-1 receptor agonist",
  "keywords": ["glp-1", "glucagon-like peptide", "liraglutide", "semaglutide", "exenatide"]
}
```

编写要点：

1. **facet_id / label**：稳定、可读；facet_id 会被报告与报警引用。
2. **keywords**：该面在题录中可能出现的表层词形，含同义词、缩写、常见拼写变体
   （如 randomized / randomised）。关键词越宽，假阴性（漏报命中）越少，但零纳入报警的
   灵敏度越依赖词表质量——词表本身要在 uncertainty 中声明为人工构造。
3. facet 数量建议 4–7 个：过少失去分辨力，过多则零命中噪音增大。
4. 分解应由研究问题驱动，不得从纳入集反推（否则核查失去独立性）。

## 3. 覆盖核查的匹配语义（facet_coverage.py）

- 比对对象：**纳入集**（judgments 中 decision=include 的记录）的 标题+摘要。
- 匹配方式：大小写不敏感的子串匹配；一条记录命中某 facet 任一 keyword 即计一次
  `included_hits`，并记录 `matched_keywords` 以便人工复核命中是否合理。
- 该匹配是表层词法近似，**不是语义覆盖判断**：同义改写、上下位词、否定语境都可能造成
  误报/漏报。结论只用于"报警"，不用于"定性"。

## 4. 零纳入报警（zero_inclusion_alarm）的解释边界

当某 facet 的 `included_hits = 0`：

- **可以说**：纳入集在该主题面命中为零，存在检索或筛选遗漏的可能性，须人工回查。
- **不可以说**：该主题面一定没有合格文献（真空）；也不可以说遗漏一定发生在检索环节
  或一定发生在筛选环节。
- **人工回查路径**（写进遗漏说明第 6 节）：
  1. 回查检索式是否覆盖该 facet 的关键词（检索侧）；
  2. 回查排除记录中是否有该 facet 的命中却被排除（筛选侧），结合险漏队列定位误伤；
  3. 必要时补充检索或放宽对应判据后重跑上游流程。

## 5. 与其他方向的分工

- facet 分解与判据可判定化属"标准落到可判定判据"的上游工作；本模型只消费分解结果。
- 各环节计数闭合（records = included + excluded + 未判定）属计数闭合审计方向，
  本技能不重复实现，仅在 selfcheck 中校验合同字段与证据锚定真实性。
