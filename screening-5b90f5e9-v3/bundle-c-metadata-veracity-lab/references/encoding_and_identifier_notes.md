# 编码与标识符处置细则

## 1. Mojibake（乱码）启发式

### 成因

数据库导出（尤其老 EndNote/Reference Manager、部分中文库的西文题录）常把
UTF-8 字节流按 Latin-1（或 CP1252）解码再存回，于是每个非 ASCII 字符
变成 2–4 个"拉丁高区"字符：

| 原字符 | UTF-8 字节 | 按 Latin-1 误读为 |
| --- | --- | --- |
| é | 0xC3 0xA9 | `Ã©` |
| í | 0xC3 0xAD | `Ã­` |
| ç | 0xC3 0xA7 | `Ã§` |
| ã | 0xC3 0xA3 | `Ã£` |
| ’ | 0xE2 0x80 0x99 | `â€™` |
| — | 0xE2 0x80 0x94 | `â€”` |
| 😀（emoji） | 0xF0 0x9F 0x98 0x80 | `ðŸ˜€` |

### 检测指纹（text_health.py 的 MOJIBAKE_RE）

- `\u00c3[\u0080-\u00bf]`：`Ã` + 续字节（拉丁附加符号最常见）；
- `\u00c2[\u0080-\u00bf]`：`Â` + 续字节（如 `Â©`）；
- `\u00e2[\u0080-\u00bf]{2}`：`â€™`/`â€”` 型三字节序列；
- `\u00f0[\u0080-\u00bf]{3}`：emoji 残骸；
- `\ufffd`：替换符，说明上游已发生过一次失败解码。

### 修复与验收

1. **整串 round-trip**：`s.encode("latin-1").decode("utf-8")`。
   纯拉丁脚本文本的乱码几乎都能这样还原。
2. **逐簇修复**：整串失败（例如合法 `é` 与乱码混杂，或含 U+FFFD）时，
   只对 Latin-1 高区字符簇（`[\u0080-\u00ff]{2,}`）逐个 round-trip。
3. **验收（两条同时满足才接受）**：
   - 修复后指纹命中数严格下降；
   - 修复结果不含 U+FFFD（不允许"修出新的坏"）。

验收失败 → 保留原值、标 `mojibake_unrepairable` → 该字段 untrusted，
关键字段（title/abstract）不可修复时整记录进 quarantine。**绝不猜改**。

### 已知盲区（保守方向）

- GBK/Big5 被按 Latin-1 误读（中文库导出偶发）不在指纹内 → 不会被误修，
  也不会被识别，依赖画像阶段的人工复核提示。
- CP1252 智能引号映射（0x93/0x94 → `“”`）与 Latin-1 差异极小，
  round-trip 一般仍成功；个别字符会落入不可修复 → 标 untrusted 而非硬改。

## 2. HTML 实体残留

Crossref/PubMed 的 XML 导出经多次中转后常见 `&amp;`、`&lt;`、`&#8212;`、
`&eacute;`。处置：`html.unescape`（Python 标准库，确定性映射），
仅当字段中确实出现实体模式（`&(name|#NN|#xNN);`）时才动手并留痕。
注意反转义后再无二次反转义（`&amp;lt;` 只解一层），避免过度解码。

## 3. 控制字符与不可见字符

- 删除 C0 控制字符（保留 `\t \n \r`）、DEL(0x7F)；
- 删除零宽字符 U+200B/U+200C/U+200D 与字段中部的 BOM(U+FEFF)。
  这些字符不承载文献语义，却会破坏下游匹配与题名规范化（不可见差异
  会让"同一题名"匹配失败），删除即安全修复，留痕 old/new。

## 4. DOI 形态校验与规范化（不联网）

规范化顺序（repair_fields.normalize_doi）：

1. 去 `https?://(dx.)?doi.org/` 前缀（大小写不敏感）；
2. 去 `doi:` 前缀；
3. 去首尾空白与尾部标点 `.,;)]}>"'”’`（RIS/CSV 拼接常带出尾点）；
4. 小写化（DOI 注册规则：ASCII 不区分大小写）。

形态校验：规范化后须匹配 `^10\.\d{4,9}/\S+$`（Crossref/DataCite 注册
前缀段为 4–9 位数字）。**不通过则保留原值并登记 `doi_flags`，不臆造、
不联网解析。** 规范化后的合法 DOI 用作跨源补全的强键之一。

### 为什么不联网验证

挑战运行时为离线快照（有限快照、无实时库）；即使联网，DOI 可解析也
只证明注册存在，不证明该题录与 DOI 的绑定正确。形态合法 + 快照内
强键一致是本技能能诚实声称的全部。

## 5. 数据库导出格式不一致的常见表现（字段级）

本技能不解析原始导出（那是上游职责），但字段层面常见的跨库不一致
及其归一：DOI 前缀/尾标点/大小写（规则 4）；年份 int 与 str 混用
（画像阶段两种都接受）；作者列表与字符串混用（补全比较时统一归一化）；
页码文章号（`e55`）与区间（`112-120`）并存（页码形态规则同时放行）。
