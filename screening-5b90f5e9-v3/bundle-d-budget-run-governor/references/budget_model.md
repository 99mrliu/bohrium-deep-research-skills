# 预算模型：64 请求 / 900 秒 / 16384 tokens 下的筛选运行估算

> 本文件是 `scripts/plan_run.py` 估算逻辑的说明书。所有数字为经验估值，
> 用于**预先选档与风险预警**，不用于替代运行中的台账实测。

## 1. 硬预算

| 资源 | 上限 | 调度含义 |
|---|---|---|
| 模型请求 | 64 次 | 一切 [模型] 阶段计入台账；确定性处理（盘点/归一）免费 |
| 墙钟 | 900 秒 | 按 12 秒/请求 + 每阶段 5 秒开销预估；75% / 90% 两档预警 |
| 单次响应 | 16384 tokens | 批量判定的批量上限 ≈ 16384 ÷ 700 ≈ 23 条/批 |
| 预留 reserve | 2 次请求 | `fill`(1) + `final_check`(1)，**任何阶段不得挪用** |

预留是铁律：没有 fill 与 final_check，result.json 就无法合法组装与终检，
等于整场运行白跑。因此可用预算 = 64 − 2 = 62 次。

## 2. 阶段请求估算公式

设题录数 N，判定批量 b（规模自适应，见 §3）：

| 阶段 | 类型 | 请求估算 | 说明 |
|---|---|---|---|
| inventory 盘点 | 确定性 | 0 | 读 case.json 计数、列 sources |
| scaffold 骨架 | 模型 | 1 | 按 output_contract 生成 result.json 骨架 |
| normalize 归一 | 确定性 | 0 | title_key/年份/作者键归一 |
| dedupe 去重 | 模型 | 1 | 重复导出簇 + 冲突双人意见标记 |
| decide 判定 | 模型 | ceil(N/b) | 批量判定，预算主要消耗点 |
| diagnose 诊断 | 模型 | L0: N；L1: ceil(N/3)；L2/L3: 0 | 逐条深度诊断，最先被砍 |
| fill 填充 | 模型 | 1 | 自由文本字段填充（预留内） |
| final_check 终检 | 模型 | 1 | 合同字段在位性核对（预留内） |

总请求（L0）= 1 + 1 + ceil(N/b) + N + 2。

## 3. 规模自适应批量

| N 区间 | b | 理由 |
|---|---|---|
| ≤ 15 | 3 | 小样本走小批量，逐条备注可以写深 |
| ≤ 40 | 5 | 平衡备注质量与请求数 |
| ≤ 100 | 8 | 大批量压缩逐条备注，保覆盖 |
| > 100 | 12 | 覆盖优先，备注最短化 |

批量同时受 token 上限约束：b ≤ 16384 ÷ 700 ≈ 23，本表均未触顶。

## 4. 两个工作算例

**算例 A：N = 9（挑战案例规模），b = 3**
- L0 总请求 = 1(scaffold) + 1(dedupe) + 3(decide) + 9(diagnose) + 2(预留) = **16 ≤ 64** → 选 L0。
- 预估墙钟 = 14 × 12 + 8 × 5 ≈ 208 秒，远低于 900 秒。N 小时预算是充裕的，
  风险不在预算而在**中断**：检查点 + 增量落盘是主要保险。

**算例 B：N = 120，b = 8**
- L0 总请求 = 1 + 1 + 15 + 120 + 2 = 139 > 64 → 不可行。
- L1（诊断砍到 40）= 1 + 1 + 15 + 40 + 2 = 59 ≤ 64 → 选 L1，
  并在 result.json 的 uncertainty 中如实声明"仅 1/3 记录获得深度诊断"。

**算例 C：N = 120 且预算被压到 24（异常场景）**
- L1 = 59 > 22；L2（无诊断）= 1 + 1 + 15 + 2 = 19 ≤ 22 → 选 L2：
  仅核心判定 + 骨架证据，diagnostics 字段为 null 并附说明。

## 5. 运行中信号（budget_ledger.py status）

- `remaining ≤ reserve` → **critical**：立即降 L3，只用预留请求收尾。
- `remaining < reserve + 未完成阶段最小请求` → **warn**：建议降一级。
- `elapsed ≥ 75% / 90% 墙钟预算` → warn / critical（与请求信号取严重者）。

信号只建议动作，不伪造进度：降级必须写进 result.json 的 status/uncertainty，
模板见 `references/degradation_ladder.md`。
