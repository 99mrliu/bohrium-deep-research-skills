# 停止规则手册（STOP-1 / STOP-2 / STOP-3）

补检执行在每批次结束后按固定顺序判定以下三条规则，触发其一即停；
触发规则、判据与依据全部写入 supplement_state.json，供确定性复跑比对。

## 判定顺序

1. 批次执行完毕后先核算该批边际覆盖率收益；
2. 依次判定 STOP-1 → STOP-2 → STOP-3（STOP-3 也在每批开始前预检）；
3. 全部触发条件与数值如实记录，禁止事后改写。

## STOP-1：连续两批边际收益为零

**触发条件**：连续两个补检批次的 `marginal_coverage_gain` 均为 0，
即 |C_b − C_{b−1}| = 0 连续成立两次。

**判定程序**：

- 每批结束用冻结参考集重匹配全部候选，计算该批新增覆盖集合；
- 维护 zero_streak 计数：批次收益为 0 时 +1，否则清零；
- zero_streak ≥ 2 时触发 STOP-1。

**必填日志字段**：批次号、原型、queries_run、newly_covered_ids（空）、
marginal_coverage_gain（0.0）、stop_rule=STOP-1 及连续零收益批次清单。

**含义**：继续按现有四类原型与本地材料查询无法带来新增覆盖，
再投入查询属于空转。

## STOP-2：执行预算耗尽

**触发条件**：查询数达到 `max_queries` 或累计耗时达到 `max_seconds`。

**判定程序**：

- 每条查询执行前检查查询数预算；每批结束检查时间预算；
- 耗尽即触发，必须注明耗尽的是“查询数”还是“秒数”以及具体数值。

**必填日志字段**：stop_rule=STOP-2、detail（预算类型与实际消耗，
如“查询数预算耗尽（37/64）”）、已执行批次的完整账本。

**含义**：不是“漏检已解决”，而是预算内无法继续；残余遗漏必须照常归因，
不得因预算耗尽而省略残余遗漏报告。

## STOP-3：残余漏检全部具备探针证据的归因

**触发条件**：对当前全部残余漏检，探针结果显示其可归因为
`来源库未收录` 或 `记录异常`，且每条归因附探针证据。

**探针证据（必填）**：

- `files_probed`：被探针的本地文件总数；
- `doi_hits` / `pmid_hits`：标识符命中的具体文件路径清单；
- `title_token_hits`：标题判别词项的命中计数（逐词）；
- `what_would_be_needed`：检回该记录所需的具体条件
  （如“需获取出版商原始响应文件”“需人工核对题录”），禁止模糊表述。

**判定程序**：对每条残余漏检执行 probe；全部满足归因条件时触发 STOP-3。
若存在 `需人工核查` 或 `标识符冲突` 类残余，STOP-3 不成立，
须继续执行下一原型批次或如实以“仍需人工介入”收尾。

**含义**：本地材料的证据面已经穷尽；继续查询同一材料面是数学上的空转。

## 触发后的义务

无论以哪条规则停止，都必须：

1. 输出残余遗漏报告（residual_misses.json + 报告章节）；
2. 输出完整逐查询账本（supplement_log.csv），含全部零收益查询；
3. 进入确定性复跑与抽检复核，复核结论写入 audit_report.json；
4. 在 result.json 的 `supplement.stop_rule` 中如实标注触发规则。
