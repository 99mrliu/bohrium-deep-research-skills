# Minimal invocation example — SYNTHETIC, not a formal case result

The outputs below were produced by **actually running this exact skill version**
on the synthetic fixture in `examples/synthetic-case/` (all records fictional,
DOIs under the reserved `10.0000` prefix). They demonstrate the interface
end-to-end; they are **not** results of any organizer test case. The real
artifacts are kept under `examples/synthetic-output/` so a reviewer can diff
them against a fresh run.

## Input

`examples/synthetic-case/case.json` (excerpt):

```json
{"case_id": "SYNTH-D-001",
 "research_question": "Reconcile a newly arrived Crossref snapshot page against the organizer-local import state of a living literature library on offline scholarly-import workflows.",
 "output_contract": {"import_manifest": "...", "updated_import_state": "...",
                     "reconciliation_report": "...", "change_records": "..."}}
```

`examples/synthetic-case/import_state.json` — the organizer-local prior state,
2 already-imported records (`10.0000/synth.d.001` year 2022,
`10.0000/synth.d.002` year **2021**).

`examples/synthetic-case/snapshots/crossref_page1.json` — a Crossref-shaped
page with 5 records, each designed to exercise one classification:

| # | record | expected classification |
|-|-|-|
| 1 | `10.0000/synth.d.001`, metadata identical to state | ALREADY_IMPORTED (skip) |
| 2 | `10.0000/synth.d.002`, year corrected 2021 → 2020 | UPDATED (year diff) |
| 3 | `10.0000/synth.d.003`, brand new | NEW (add) |
| 4 | `10.0000/synth.d.001` but a contradictory title | CONFLICT (DOI match, title mismatch) |
| 5 | title of `10.0000/synth.d.002` but DOI `10.0000/synth.d.777` | CONFLICT (title match, DOI mismatch) |

## Invocation (exactly what was run)

```
python3 scripts/make_result.py --case examples/synthetic-case/case.json \
    --out examples/synthetic-output/result.json --status partial \
    --uncertainty "..."
python3 scripts/reconcile.py --case examples/synthetic-case/case.json \
    --input examples/synthetic-case \
    --out examples/synthetic-output --verify-idempotent
python3 scripts/make_result.py --case examples/synthetic-case/case.json \
    --out examples/synthetic-output/result.json --status partial \
    --uncertainty "..."
python3 scripts/make_result.py --case examples/synthetic-case/case.json \
    --out examples/synthetic-output/result.json --validate
```

```json

```

```

```

The idempotency line is the product of a **real second execution**: the engine
reloaded the just-written `updated_state.json` from disk, re-walked the pool
and re-classified all 5 candidates; record 1 stayed ALREADY_IMPORTED, records 2
and 3 (applied in pass 1) now matched the updated state fingerprint-identically,
and the 2 conflicts recurred as queued items (expected — they were never
applied, hence are not state changes).

Validator output:

```
VALIDATE OK: 4 contract fields, case_id=SYNTH-D-001, status=partial
```

## What the run demonstrates

- **All 5 records classify exactly as designed** (see
  `synthetic-output/import_manifest.json`): 1 skip with
  `DOI_MATCH_IDENTICAL`, 1 update with `DOI_MATCH_CONTENT_CHANGED` and the diff
  `year: 2021 → 2020`, 1 add with `NO_STATE_MATCH`, 2 conflicts
  (`DOI_MATCH_TITLE_MISMATCH`, `TITLE_MATCH_DOI_MISMATCH`).
- **Conflicts were not merged**: `updated_state.json` still holds the original
  titles/DOIs for both conflicted identities; both conflicts are rendered side
  by side in `reconciliation_report.md`'s conflict queue.
- **Every applied change is ledgered**: `change_records.jsonl` holds exactly 2
  lines (CHG-0001 update with the year diff, CHG-0002 add), each with
  provenance `{file, json_index}`.
- **The update preserved history**: the updated state entry keeps its original
  `imported_at` (2025-08-14T09:31:02Z) and gains `updated_at` plus
  `previous_fingerprint` (`95319c5d9ce8` → `66424527fcbc`).
- **Honest status**: `result.json` stays `partial` because 2 identity
  conflicts remain queued awaiting human resolution — exactly the behavior
  expected on a real case with contradictory identifiers.

## Output files (real, regenerated by the commands above)

- `synthetic-output/import_manifest.json` — ordered decision ledger, reason
  codes, fingerprints, diffs, both conflict records
- `synthetic-output/updated_state.json` — prior state + applied add/update,
  schema `incremental-import-reconciler/state/v1`
- `synthetic-output/reconciliation_report.md` — counts, readable diffs,
  conflict queue, honest notes
- `synthetic-output/change_records.jsonl` — one JSON object per applied change
- `synthetic-output/evidence/evidence_index.json` — sha256 manifest of every
  consulted file (case, state, pool)
- `synthetic-output/result.json` — contract-filled, validated, `partial`
