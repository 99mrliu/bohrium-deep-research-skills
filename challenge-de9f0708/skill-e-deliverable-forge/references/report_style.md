# 人读报告写作规范

`report_render.py` 机械渲染版式；**内容质量由 findings 本身决定**。本规范约束 findings 的写法，
使渲染出的每张问题卡片都能被第三方在同一份材料上复核。

## 问题卡片必备六要素

渲染后每条卡片含：定位 / 原文摘录 / 依据 / 严重度 / 修改建议 / 判定状态。缺一不可：

1. **定位**：file + page + section。页码以材料实际分页为准，禁止"见全文""见附录"这类粗定位。
2. **原文摘录（quote）**：逐字引用，保持原文错别字与标点；不得用省略号拼接两段话；
   不得转述。读者拿 quote 回原文检索必须能命中。
3. **依据（evidence）**：可核对的依据——规范条款（写明规范全名与条款号，且必须真实存在）、
   目标期刊要求（写明来源 URL 或文件名）、外部数据库记录（写明检索到的原文）、
   或本地规则名。禁止编造条款与文献元数据。
4. **严重度**：只用四级，用语固定：
   - `critical`：足以推翻结论或构成学术不端嫌疑（数据与结论矛盾、疑似捏造文献、抄袭）；
   - `major`：影响结论可靠性或合规性（缺伦理声明、关键方法信息缺失、疑似 PII 泄露）；
   - `minor`：不动摇结论但需修正（图表编号错误、无依据的夸大表述、元数据错误）；
   - `info`：建议性改进（补局限性讨论、补图注单位）。
5. **修改建议（suggestion）**：可执行动作，格式"把 X 改成 Y"或"在 Z 处补充 W"。
   优先级清单一栏直接截取建议首句，所以**第一句必须是动作本身**。
6. **判定状态（verdict_status）**：`确认` 或 `待复核：〈理由〉`。

## 待复核表述

- 写清"待复核什么、缺什么手段"，如：`待复核：参考文献[2]在本地材料无法核实，需联网查 Crossref 记录`。
- 待复核不是垃圾桶：凡能本地确认的都必须确认；只有确实需要不可用手段（断网、缺材料）的才挂待复核。
- 报告中待复核卡片会以醒目样式标出，数量进概要——挂得越多，交付可信度越低。

## 不得出现的表述（反例清单）

| 禁止写法 | 问题 | 正确写法 |
|---|---|---|
| 建议检查格式是否规范 | 无定位、无动作 | 将第3页表2标题"Table 2"改为期刊要求的"表 2"格式 |
| 某处可能有误 | 无 quote、无依据 | F03：第2页"准确率达97.3%"与表1合计值93.7%矛盾（附两边逐字摘录） |
| 参考文献似乎有问题 | 无条目、无手段 | 待复核：文献[2]"Zhang & Lee, 2021"需查 Crossref 验证是否存在 |
| 建议进一步完善 | 空话 | 在讨论节末尾补充"本研究样本量有限（n=12），结论外推需谨慎" |
| 全文风格不统一 | 不可复核定位 | 第2页用"图1"、第4页用"Figure 2"，统一为"图 N" |

## 概要段纪律

- 概要里的数字由渲染器从 findings 机械统计——**不要**在 summary 文本里写与 findings
  矛盾的计数（如 findings 有 1 条 critical 而 summary 写"无严重问题"）。
- `not_reviewed` 非空时，summary 必须点名哪个审查面没查、为什么；报告的"未检查面"一节
  会原样展示，不得依赖读者忽略它。
