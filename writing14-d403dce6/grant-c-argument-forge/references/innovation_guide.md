# 创新点四要件写法指南（rhetoric_lint.py 规则 L4 与 innovation_diff.py 的依据）

## 一、四要件

每条创新点必须同时回答四个问题，缺一不可：

1. **新在哪（差异定位）**：与谁不同、不同在哪个具体环节。
   - 差异标记词（脚本据此识别）：不同于 / 区别于 / 相比 / 而现有 / 相较于 / 有别于。
2. **与谁不同（点名已有工作）**：必须点名至少一项具体已有工作，禁止只说"现有方法"。
   - 点名标记（脚本据此识别）：作者＋年份（如"Li 等（2022）""（Wang, 2021）"）、
     文献编号引用（如 [3]、〔3〕）、或成果名称书名号（如《XXX数据集》）。
3. **为什么难（难点表述）**：说明该差异为何不是随手可做——难点在哪、别人为何没做或没做成。
   - 难点标记词：难点 / 难在 / 挑战 / 困难 / 瓶颈 / 难以 / 风险。
4. **凭什么成（可行性凭据）**：给出可核验的凭据——前期数据、已建平台、已验证原理、
   已发表方法学积累；凭据必须区分"已完成[申请人]"与"外部工作"。
   - 凭据标记词：已验证 / 可行性 / 前期 / 预实验 / 已有数据 / 初步结果 / 已搭建 / 已建立 /
     已发表 / 平台 / 试点 / 积累。

## 二、写作模板

> 创新点 N：<一句话陈述创新内容>。不同于/区别于 <已有工作：作者、年份、方法> 在
> <环节> 上的 <其做法及其局限>，本研究 <具体差异做法>；其难点在于 <为什么难>；
> 可行性凭据：<已完成的前期证据/平台/预实验数据>。

## 三、反例（以下为合成示例，非正式案例结果）

**反例 1（无差异、无点名）**

> 创新点 2：构建大规模高质量等离子体催化数据集。该数据集体量大、质量高，构建过程面临标注
> 一致性难点，团队具备多年数据工程经验与成熟标注流程，可保障按期完成。

诊断：体量大、质量高是相对谁？"大规模"不可核验；未点名任何一个已有数据集；只有难点与
笼统的"经验"，没有可核验凭据。L4 会报：缺【差异定位】【点名已有工作】。

**反例 2（有差异、无凭据）**

> 创新点 1：不同于 Wang 等（2022）的逐层扫描策略，本研究提出整体求解框架，难点在于耦合
> 项的非凸性。

诊断：差异与点名齐备，但"凭什么做得成"没有任何凭据，评审无法判断风险。L4 会报：
缺【可行性凭据】。

**正例**

> 创新点 1：不同于 Wang 等（2022）在介质阻挡放电体系中的逐层参数扫描策略，本研究将
> 放电–催化耦合过程建模为统一的多目标优化问题；其难点在于气相动力学与表面动力学时间
> 尺度跨越 8 个数量级导致的刚性求解困难；可行性凭据：申请人前期已将降维机理求解器在
> CH₄/He 等离子体体系验证（相对误差 <5%，已完成[申请人，有材料证据]），可直接迁移至
> 本体系。

## 四、与脚本的关系

- `innovation_diff.py --generate` 依据材料中梳理出的已有工作清单生成"差异定位表"
  （已有工作 | 其局限(引原文) | 本研究差异 | 难点 | 可行性凭据），逐行填写即为四要件的
  素材来源；
- `innovation_diff.py --check` 校验表中不得有空单元格或【待填】占位；
- `rhetoric_lint.py` 规则 L4 在成稿上复查四要件标记是否齐全。
