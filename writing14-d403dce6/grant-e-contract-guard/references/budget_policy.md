# 预算策略（budget policy）

总预算：**64 次模型请求 / 900 秒 / 每次响应 16384 tokens（含 reasoning）**。

## 1. 分阶段预算分配（建议比例）

| 阶段 | 请求占比 | 耗时占比 | 目标 |
| --- | --- | --- | --- |
| 读材料 | 20%（≈13 次） | 25%（≈225s） | 读完 case/task/全部材料，建材料清单与来源台账骨架 |
| 成稿 | 45%（≈29 次） | 40%（≈360s） | 按要素清单逐章成稿，每节完成就地更新 result.json |
| 回检 | 20%（≈13 次） | 20%（≈180s） | 合同字段、四态标注、要素对照、引用溯源逐项回检 |
| 保底余量 | 15%（≈9 次） | 15%（≈135s） | 异常处置、最终校验、交付 |

比例是建议而非硬限制；但"保底余量"不得挪用干净——任何时刻都要保证还有余量执行保底交付。

## 2. 记账方式

- 每次模型请求后：`budget_ledger.py tick --kind model_request --elapsed <秒>`；
- 纯本地处理（读文件、跑脚本）后：`budget_ledger.py tick --kind stage --elapsed <秒>`；
- 时间由调用方（Agent）估计传入，脚本不读墙钟，保证可复现。

## 3. 降级触发条件

| 级别 | 触发 | 动作 |
| --- | --- | --- |
| ok | 两维度均 <70% | 正常工作 |
| warn | 任一维度 ≥70% | 脚本退出码 2。启动降级评估：停止非必要扩写，优先完成合同字段与缺口清单 |
| critical | 任一维度 ≥90% | 脚本退出码 3。**立即进入保底交付模式**（见下） |

## 4. 保底交付模式动作清单（critical 时逐条执行）

1. 立即停止新增扩写与额外检索，不再发起非必要模型请求；
2. 对已写完章节只做合同字段补全与四态标注检查，不重写；
3. 未完成章节以 `【待申请人确认：…】` 占位，逐条写入缺口清单（`gaps`/`uncertainty`）；
4. 就地更新 `result.json`：`status=partial`、`reason` 说明预算边界、列出已完成与缺口；
5. `checkpoint.py save --stage budget-guard` 保存快照；
6. `contract_probe.py --validate` 复核通过（退出码 0）后交付。

## 5. 截断恢复

若运行被截断：账本与检查点在 `/app/work`，最近合法 `result.json` 在 `/app/output`。
续跑时先 `checkpoint.py list` 看时间线，必要时 `checkpoint.py restore --stage <名>` 回到最近快照，再按 runbook 续跑。
