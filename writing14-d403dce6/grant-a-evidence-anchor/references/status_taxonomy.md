# 四态标注判定规则与常见误判

本文件定义 evidence_map 条目 `status` 字段的判定规则，供 anchor_audit.py 与人工核对共同使用。

## 四态定义

| status | 含义 | 证据要求 |
|---|---|---|
| 已完成 | 申请人（团队）已经完成的工作 | 必须锚定到**申请人证据类**材料（实验记录、前期数据、已受理材料等）的逐字 quote |
| 外部工作 | 原论文、既有公开成果 | 归外部作者；只能写"已有研究报道/某人报道了…"，不得写成申请人的成果 |
| 拟开展 | 本研究计划将要开展的工作 | 锚定到 task/工单/计划类材料中的相应表述；不得使用"已实现/已证明" |
| 待确认 | 材料中查不到、需要申请人人工确认 | 不编造；章节稿对应位置放【待申请人确认：…】占位符并列入缺口清单 |

## 来源类别（source_class）判定规则

anchor_audit.py 按以下**确定顺序**判定条目来源类别：

1. 条目自带 `source_class` 字段（`applicant` / `external`）——优先采用；
2. 缺省时查 materials_inventory.json 中该文件的 `source_class_guess`，其由角色猜测映射而来：
   - 文件名含"记录 / 前期 / record / notebook / logbook"的 md/txt → `applicant-record` → `applicant`；
   - PDF → `external-pdf` → `external`（PDF 多为外部论文/资料，默认外部，除非条目显式声明并确有依据）；
   - 其他 → `unknown`；
3. 仍为 `unknown` 时，`status=已完成` 触发 warning（需人工确认），不直接判错。

**硬规则**：`status=已完成` 且来源类别判定为 `external` → error（退出码 1）。原论文与既有成果归外部作者，即使申请人是该论文作者之一、即使内容与申请方向完全一致，只要材料是外部出版物，就不得记为"已完成"，应标"外部工作"或以申请人自有记录另行举证。

## 常见误判（反面清单）

1. **把原论文成果写成申请人已完成**：章节稿写"本团队已实现 87% 转化率"，而 87% 出自外部论文节选。这是本 bundle 针对的头号失败模式，anchor_audit 以 error 拦截。
2. **凭印象引用**：quote 与原文存在同义改写、语序调整、数字四舍五入（87.28% 写成 87.3%）。一律视为未命中，必须复制原文逐字片段。
3. **"拟开展"写成"已完成"的时态污染**：技术路线中的计划步骤被写进研究基础。检查谓词：已完成用"已/完成了"，拟开展用"拟/将/计划"。
4. **待确认条目被悄悄填实**：材料缺口不得以"合理估计"补齐；保持【待申请人确认：…】占位，并在 result.json 的 uncertainty 中说明。
5. **申请人证据缺失时从文件名/领域标签补造**：组织方声明证据缺失时按缺失处理（见 SPEC 组织方输入修订 v1），文件名不是证据。

## quote 摘录规范

- 逐字复制，允许跨越换行（空白折叠不影响命中）；
- 全角/半角差异由 NFKC 归一化吸收，但**不得**借此改写任何字符；
- 长度以能独立支持 claim 为准，建议 15–200 字；过长易引入无关数字干扰 orphan_scan 的豁免集合；
- quote 中出现的数字即成为章节稿对应数字的合法出处。
