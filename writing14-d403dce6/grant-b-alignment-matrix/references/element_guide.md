# 七要素厚度配比经验值与常见错位案例

供判断 M7（厚度平衡）warning 是否需要人工干预，以及评审视角下「对得上」
问题的常见形态。经验值不是硬性指标，案例 workorder 另有要求时以案例为准。

## 1. 厚度配比经验值（以全部七要素正文总字数为 100%）

| 要素 | 建议占比 | 过薄信号 | 过厚信号 |
| --- | --- | --- | --- |
| 立项依据 | 20–25% | 只有口号无文献与瓶颈分析 | 写成文献综述，淹没自己的问题 |
| 科学问题 | 6–10% | 问题大于一个学科方向、无边界 | 把研究内容复述一遍 |
| 研究目标 | 6–10% | 目标不可考核、无编号 | 目标写成内容清单 |
| 研究内容 | 15–20% | 内容与目标对不上号 | 写成实验记录 |
| 技术路线 | 15–20% | 只罗列方法名、无步骤编号 | 与方法学教材雷同 |
| 创新点 | 6–10% | 依赖「首次/领先/填补空白」 | 把特色当创新逐条注水 |
| 研究基础与可行性 | 12–18% | 只列论文清单无证据链 | 吹嘘平台与资历 |

M7 默认阈值 0.35×均值即「任一要素不足平均水平的三分之一」即预警；
落到上表范围之外的显著偏离，即使脚本未报警也应人工复核。

## 2. 常见错位案例（基础 Agent 真实失败模式）

### 2.1 目标三个、路线两条
目标列了 G1/G2/G3，技术路线只写了覆盖前两条的步骤，G3 悬空。
矩阵表现：C3 无 R→C 入边（M2 error）。
对策：先把 G→C→R 链在矩阵里闭合，再动笔写路线。

### 2.2 指标另说一套
考核指标段落出现「发表高水平论文若干」等表述，却不挂接任何具体目标；
或指标编号挂到不存在的目标（K1→G4 而目标只有 G1–G3）。
矩阵表现：K 无出边（M2/M3 error）或悬空引用（M4 error）。
对策：每条 K 必须写明「用于检验 Gn 的达成」，矩阵先建 K→G 边。

### 2.3 矩阵写在文档里但正文对不上
文档附录画了一张漂亮对照表，正文却从没出现 G2、C3 等编号；
或正文临时冒出矩阵里没有的编号（「拓展 C4」）。
矩阵表现：M5 正向（矩阵 ID 未在正文出现）或反向（正文编号未登记）error。
对策：正文写作时引用编号是义务不是装饰；改稿必须稿矩阵同步改。

### 2.4 要素缺斤短两
「创新点」整节缺失，或「研究基础」只有标题没有正文。
矩阵表现：M6 error（标题缺失）、M7 error（空要素）。
对策：以 plan.json 的七要素清单为骨架搭标题，先齐后写。

### 2.5 计数表述与清单不符
正文写「研究目标共 3 个」实际列了 4 条（或矩阵改了正文没改）。
矩阵表现：M8 error。
对策：计数句以矩阵节点数为准；矩阵是单一事实来源。

### 2.6 科学问题无人认领
增设的 G3 不回应任何 Q，或某个 Q 没有任何 G 承接。
矩阵表现：M3（G3 孤儿）或 M2（Q 无 G 回应）error。
对策：每个 Q 至少拆出一个 G；每个 G 必须能回答「它回应哪个 Q」。

## 3. 使用建议

1. 写稿前：用 matrix_scaffold.py 生成 plan 与空矩阵，先填节点和边。
2. 写稿中：正文引用编号，随时 matrix_check.py 回检。
3. 交付前：exit 0 才允许交付；用 matrix_render.py 生成附录对照表，
  连同 check_report.json 一并留档，作为「对得上」的可核验证据。
