# Q/G/C/R/K 编号与正文写法约定

本约定是 matrix_check.py 规则 M5（矩阵 ID 与正文双向一致）的判定依据。
写作与检查必须使用同一套约定，否则机器回检会出现误报或漏报。

## 1. 编号体系

| 前缀 | 含义 | 节点类别 | 示例 |
| --- | --- | --- | --- |
| Q | 科学问题 | q | Q1, Q2 |
| G | 研究目标 | g | G1, G2, G3 |
| C | 研究内容 | c | C1, C2, C3 |
| R | 技术路线步骤 | r | R1, R2, R3 |
| K | 考核指标 | k | K1, K2 |

- 编号 = 单个大写字母前缀 + 阿拉伯数字，从 1 开始连续编号，不跳号、不复用。
- 全文（含图题、表题、附录）使用同一套编号；删除某条时后续条目重新编号，
  矩阵与正文同步更新。
- 子步骤写作 R1.1、R1.2 时，矩阵只登记主编号 R1；子编号不参与矩阵校验。

## 2. 正文写法约定

- 首次出现写全称加编号，例如「科学问题 Q1（……）」「研究目标 G2」「技术路线
  步骤 R3」；此后可直接引用编号。
- 正文中每个编号必须与矩阵 nodes 中登记的 id 完全一致（大小写敏感，必须大写）。
- 禁止在正文使用矩阵未登记的编号（例如矩阵只有 C1–C3 时出现「拓展 C4」），
  M5 反向校验会将其判为 error。
- 矩阵中登记的每个编号必须在正文真实出现至少一次，M5 正向校验缺失判 error。

## 3. 识别正则（词边界）

中文语境下 Python 的 `\b` 把汉字也视为单词字符，「目标G1」这类写法会导致
`\bG1\b` 失配。因此脚本统一使用仅排除 ASCII 字母数字的边界：

```
(?<![A-Za-z0-9])Q[0-9]+(?![A-Za-z0-9])     （其余前缀同理）
```

含义：编号前后不允许紧邻 ASCII 字母或数字，但允许紧邻汉字、标点、空白。
推论：「目标G1」「见G1条」可被识别；「G10」不会被「G1」误吞；「Q1a」「Q12」
是不同于「Q1」的标记（「Q1a」整体不匹配任何合法编号，写作时禁止使用）。

## 4. 七要素标题别名（M6 匹配用）

| 标准要素 | 认可的标题别名（包含匹配） |
| --- | --- |
| 立项依据 | 立项依据；立项依据与研究意义；研究意义 |
| 科学问题 | 科学问题；拟解决的关键科学问题；关键科学问题 |
| 研究目标 | 研究目标；总体目标；研究总体目标 |
| 研究内容 | 研究内容 |
| 技术路线 | 技术路线；研究方案与技术路线；技术路线与研究方案；研究方案 |
| 创新点 | 创新点；特色与创新；创新之处；项目特色与创新 |
| 研究基础与可行性 | 研究基础与可行性；研究基础；可行性分析；工作基础 |

- 匹配对象是 markdown 标题行（`^#{1,6}\s+…`），匹配前剥离「一、」「（二）」
  「3.」「第一章」等前置序号。
- 案例 workorder 另行指定要素清单时以案例为准（经 plan.json 传入），别名表不变。
- 考核指标未单列标题时按 SPEC 约定并入研究目标，K 编号仍须独立存在并挂接到 G。

## 5. 计数表述写法（M8 匹配用）

- 允许写法：「研究目标共 3 个」「设置研究内容 3 项」「技术路线分为 2 步」
  「考核指标 1 项」「凝练科学问题 2 个」（阿拉伯数字或中文数字均可）。
- 出现此类表述时，数字必须与矩阵对应类别节点数一致，否则 M8 判 error。
- 拿不准时不要写计数句；矩阵是唯一事实来源，正文计数句只是派生表述。
