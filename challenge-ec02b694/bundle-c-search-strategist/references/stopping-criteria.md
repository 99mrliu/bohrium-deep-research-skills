# 停止判据：定义、触发条件与已知失效场景

每条判据在 `next_batch.py` 的每次决策中都计算状态并写入决策日志的
`criterion_states` 字段（包括"未触发"），因此"为什么没停"和"为什么停"
同样可复核。STOP 决策必须写明触发了哪一条。

## 1. budget_exhausted（预算耗尽）

- **定义**：已评估的新实验点数 ≥ budget。历史点不消耗预算。
- **触发**：`next_batch.py` 最先检查；触发即 STOP，优先级高于一切。
- **失效场景**：
  - 实验方把失败/作废的实验也写进了 results.csv ⇒ 预算被"烧掉"却没有有效信息。缓解：作废行不要进 results.csv，或先用 `search_log.py verify --results` 交叉核对；
  - 预算口径不一致（budget 指"新点"还是"含历史点"）⇒ 本技能固定为"新点"，历史点只登记。

## 2. low_improvement（连续两轮相对改进 < 2%）

- **定义**：最近两个已完成搜索轮的最优响应相对改进
  `|best_k − best_{k−1}| / max(|best_{k−1}|, 1e-12) < 0.02`
  （maximize 取增量、minimize 取减量）。确认轮不计入"搜索轮"。
- **触发**：筛选→加密改进不足 2% 时，在进入确认轮之前 STOP；≥2 次确认重复仍被推荐，但作为**待确认事项**（confirmation items）列出，而不是继续烧预算。
- **失效场景**：
  - **平台区误判**：响应面在最优点附近有宽平台，两轮改进天然 < 2%，但平台外还有更高峰 ⇒ 过早停。缓解：筛选轮覆盖越均匀，风险越小；
  - **噪声淹没**：噪声幅度 > 2% 时改进量主要是噪声，判据变成"掷硬币"。缓解：阈值应随噪声水平调整（本技能固定 2%，改动必须写入决策日志）；
  - **响应值过零**：best 接近 0 时相对改进爆炸/失真，分母用 `max(|best|, 1e-12)` 兜底，但解释时须看绝对量。

## 3. boundary_constrained（所有维度抵近约束边界）

- **定义**：当前最优点在**每一个**维度上都距 lower 或 upper 不足 1 个 step。
- **触发**：进入局部加密轮前检查；触发即 STOP——坐标步进已无处可走。
- **失效场景**：
  - **真最优在边界外**：STOP 是对的，但结论必须写成"最优位于参数空间边界，建议扩大边界"，不能写成"找到全局最优"；
  - **单维度贴边不算**：判据要求所有维度同时贴边；只有部分维度贴边时坐标步进仍能沿其余维度移动（越界方向被裁剪）。

## 4. all_candidates_duplicate（全部候选点重复）

- **定义**：本轮生成的候选点全部已被评估，且"最近未访问网格点"回退扫描也找不到任何未访问点（空间已被扫完）。
- **触发**：STOP；通常只在 budget 接近可行组合数时出现。
- **失效场景**：
  - 结果 CSV 里坐标写成不同精度（400 vs 400.0）被当成不同点 ⇒ 本技能统一 `round(x, 10)` 规范化后比较；
  - 确认轮的点**本来就重复**（同坐标重复是设计的一部分）⇒ 判据只对筛选/加密轮生效，确认轮不适用。

## 5. plan_complete（计划内轮次全部完成）

- **定义**：所有计划轮次的点数都已评估而预算尚未耗尽（预算 > 计划点数时出现）。
- **触发**：STOP 并注明"计划完成"；剩余预算如何使用属于新决策，必须新开日志记录。

## 复核方式

```bash
python3 scripts/search_log.py verify --log decision_log.jsonl \
    --results results.csv --output verify_report.json
```

- 逐条重放：seq 必须从 1 严格递增；`results_digest` 必须与内嵌结果快照重算的 sha256 一致；给出 `--results` 时，每条快照行必须仍能在原始 results.csv 中找到。
- 任何一处不一致 → 退出码 1 + 问题清单（见 `examples/synthetic-output/verify_tampered.json` 的负例）。
