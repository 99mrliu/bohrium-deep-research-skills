# 追踪策略规范（traversal policy）

## 1. 方向定义

- **后向边（backward / reference）**：A 的参考文献列表中出现 B，记 A→B，语义为"citing work → cited work"。用于找方法、数据与理论出处。
- **前向边（forward / citation）**：B 被 A 引用，记 B→A，语义为"cited work → citing work"。用于找后续改进、应用与批评。
- 数据源只给被引列表不给方向时，方向由"该列表出现在哪篇文献的记录里"决定：references 字段产生后向边，citations/cited-by 字段产生前向边。绝不允许把两种边混存后猜方向。
- 反向索引补方向：本地语料中任何记录的参考文献指针解析到工作 W，即产生一条 W 的前向边。该机制使只含参考文献的库（如部分 Crossref 导出）也能做前向追踪，是本 Skill 相对基础 Agent 的关键能力。

## 2. 扩展规则

- BFS 逐层扩展，层号 = 与种子的最短跳数（首次到达时确定，不被后续路径覆盖）。
- 第 1 层从种子同时做后向与前向；第 2 层起，节点沿其到达方向继续扩展（后向链继续向后、前向链继续向前），避免方向交替造成的组合爆炸与语义不清。
- 默认 `max_depth=3`、`max_nodes=250`、`max_branch=40`。900 秒预算下此规模可在数秒内完成；不要为了覆盖而放宽到无法逐边核验的规模。

## 3. 剪枝规则（全部记录 pruning_log）

| 规则 | 触发 | 动作 |
|-|-|-|
| max_branch | 单节点待扩展分支 > 40 | 按 被引提示 desc → 任务关键词重叠 → 年份 desc 排序，保留前 40，其余记 `rule=max_branch` |
| year_window | 后向目标年份 < (种子年份 − 45) 且被引提示 < 200 | 剪除并记 `rule=year_window`；被引 ≥200 的老文献视为奠基性经典保留 |
| 已访问 | 目标已在 visited | 跳过（不记日志，避免噪声） |

## 4. 停止判据（全部记录 stop_log）

- `max_nodes`：节点预算耗尽。
- `diminishing_yield`：整层零新增（含全部被剪），立即停，不再尝试更深层。

## 5. 证据与诚实性

- 每个节点、每条边必须有 locator：`{file, pointer}`，pointer 为 JSON 路径或行号。复核人可用 `jq`/`sed` 直接回指原始记录。
- 解析失败的文件、截断的列表写入 parse notes 并体现在 `sources`/`uncertainty`。
- 引用目标在本地语料中无完整记录时，建 `stub=true` 节点：只携带原始指针里的字段（DOI/arXiv/标题片段），**禁止**推断年份、作者、期刊。
- 多次出现的同一工作按规范键（DOI > arXiv > 标题+年份）合并；合并只补空字段，不覆盖已有字段。

## 6. 相关性说明

本 Skill 的相关性证据是**结构性**的：节点通过哪条引用链到达种子（via 字段可逐级回溯）。任务文本关键词仅用于剪枝排序，不用于捏造"主题相关"断言；如需主题判读，由 Agent 在 evidence_table.md 之上人工标注，并与结构证据分列。
