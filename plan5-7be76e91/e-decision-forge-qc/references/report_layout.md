# 报告版式约定（report_render.py 渲染产物）

`report_render.py` 产出 `report.html`（自包含）与 `report.md`，节序固定、确定性
渲染（默认无时间戳；`--generated-at` 可显式传入固定标注）。两产物结构一一对应。

## 全局约定

- **自包含 HTML**：内联 `<style>`，无外部 CSS/字体/图片/脚本；不依赖 JavaScript，
  浏览器直接打开即可目检；`<meta charset="utf-8">`。
- **合成示例横幅**：决策包 `synthetic: true` 时，正文顶部渲染黄色横幅
  「合成示例 / SYNTHETIC EXAMPLE」，页脚同样标注；正式案例无此横幅。
- **页脚**（固定文案）：标注生成方式（decision-forge-qc/scripts/report_render.py、
  Python 标准库、确定性渲染、双跑逐字节一致）与案例 id。
- **确定性**：节序、表内行序（plan_id 字典序 / 维度名排序 / 情景固定序）全部确定；
  浮点数统一 `%.6f` 显示。

## 节序

| # | 节 | 内容 | 复核要点 |
|---|----|------|---------|
| — | 页头 | 标题 + 案例 id（+ 合成示例横幅） | 案例对账 |
| 1 | 选择结论 | 选定方案、结论状态（final/provisional，provisional 时明示「不得作为最终执行依据」）、选择理由、未选方案及放弃原因表 | 结论强度是否匹配确认项状态 |
| 2 | 确认项状态 | **confirmed 分区表**与 **pending 分区表**（表头明示 pending「不得写成已确认事实」），含 id/类别（安全/伦理/设备可用性/专家确认）/事项/备注 | 确认项隔离是否落地可见 |
| 3 | 七类字段比较矩阵 | 七个子节（假设/变量/对照/步骤/参数/资源/判读标准），每节一张「方案 × 条目」表，条目前带 `[id]` | 完整性；证据 id 可回查 |
| 4 | 决策日志 | 淘汰表：被淘汰方案 / 淘汰规则（`<code>`）/ 证据引用（逗号分隔 id）；无硬规则淘汰时显式说明 | 「谁被淘汰、依据哪条规则哪条证据」一屏可读 |
| 5 | 评分与权重 | 归一化权重表；方案维度分 + 加权总分 + 排名表（平局按 plan_id 字典序，确定性） | 排名可手算复算 |
| 6 | 敏感性分析 | （提供 sensitivity.json 时）verdict 段、扰动情景表（翻转行高亮 `flip` 样式）、翻转阈值表（下调/上调两方向） | 稳健性结论与翻转点可见 |
| — | 页脚 | 生成方式 + 案例 id（+ 可选生成时间标注） | 来源与可复核性声明 |

## Markdown 版

节序与表格内容与 HTML 完全对应（矩阵节在 MD 中按方案分组的嵌套列表呈现），
便于贴入文本评测或版本 diff。

## 为何这样排版

题目点名的失败是「结论强度靠语气不靠证据、方案一换就说不清为什么改选」。版式
把**决策日志（第 4 节）**与**敏感性翻转点（第 6 节）**提升为独立章节，与选择
结论（第 1 节）并列，使复核者无需翻原始材料即可回答三个问题：选谁、谁被淘汰
凭什么、权重改多少结论会翻。
