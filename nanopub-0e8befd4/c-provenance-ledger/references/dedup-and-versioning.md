# 去重合并与版本对照规则

## 1. 语义键（去重键）

`subject + relation + object + 排序后的 qualifiers + polarity + modality`
全部 NFKC 归一化、小写化、空白折叠。键相同 → 同一断言；键不同 → 不同断言。

刻意排除在键外：

- **证据与来源**：同一断言被多来源/多处证据支持时合并为一条，绑定全部来源；
- **断言文本措辞**：同义改写不改变键（但键由结构化字段构成，措辞差异不会误合并）；
- **confidence**：不同来源证据强度不同，合并条目保留各自证据，confidence 取
  绑定中最强一档并在报告中留痕。

## 2. 合并规则

- 保留全部 `sources[]` 绑定（来源身份 + 证据），不丢弃佐证；
- 合并事件逐条写入 `merges[]`：保留的 claim_uri、被并入的 claim id 与来源；
- 合并不改变任何绑定中的证据内容。

## 3. 冲突检测（只报告、不裁定）

同 `subject + relation + qualifiers`、客体不同 → 冲突项。典型形态：

- 版本间数值修订（v1 写 94.1%，v2 写 94.6%）；
- 正文与补充材料不一致；
- 引文转录错误（此时应修断言而非登记冲突）。

冲突项进入 `conflicts[]`，交付时在 result.json 标注双方断言与来源，
等待人工裁定；不得静默取新、取多数或取先读到的。

## 4. 版本对照

沿 `supersedes` 链逐对比较：

- `both`：两版共证（语义键一致），是跨版本稳定结论；
- `only_old`：仅旧版有——可能在新版被删改，保留并标注；
- `only_new`：仅新版有——新增或修订结论，保留并标注。

版本对照不蕴含「新版正确」；它是可追溯性记录，裁定交人或任务规则。

## 5. 指纹纪律

- `sha256` 永远以文件重算为准；声明值仅用于比对；
- 指纹不一致（`E_SOURCE_MISMATCH`）：停止交付该来源支撑的结论为已核实，
  状态转 `partial`，提示文件被替换的可能；
- 同名文件用指纹区分身份，不用路径或文件名。

## 6. 重跑确定性

相同输入（claims + sources + 文件字节）→ 相同 claim_uri 集合与相同
nanopubs.jsonl；TriG 仅 `dcterms:created` 不同。可用此性质做幂等回归：
重跑后 diff 除 created 外应为空。
