# 同稿双程对照协议（增益可验证性的诚实做法）

评分项「增益可验证性」要求「用同稿、同版本、同评分口径的对照证明改善」。平台自己的官方对照（基础 Agent vs 加载 Skill 的 Agent）由组织方运行；本协议是 **Skill 自带的内部消融**，两者不可混淆。

## 协议

1. **同稿**：基线与 Skill 管线处理同一输入文件，一字不差。
2. **同口径**：两份诊断用同一 finding schema（`dimension/location/quote/action/severity`），由 `gain_compare.py` 用同一组指标计算。
3. **机械基线**：`base_pass.py` 生成的基线是**程序化的**（零模型判断），代表「不做锚定、不做判据、不做操作化」时的下限。它刻意不含任何模型能力，因此任何人重跑都得到同一基线。
4. **Skill 一程**：Agent 按 SKILL.md 工作流产出的真实诊断。
5. **报告**：`gain_report.md` 必须保留顶部声明——基线不代表平台基础 Agent。

## 诚实性红线

- 禁止把内部消融数字写成「优于基础 Agent X%」；只能说「相对机械消融基线的增量为 …」。
- 禁止挑选有利的合成稿展示；正式案例上的对照报告必须基于当次真实输入。
- 若 Skill 一程某指标低于基线（理论上可能），如实保留，不删报告。

## 预算说明

机械基线是零模型请求的程序，双程对照不额外消耗模型预算；它只增加一次脚本运行（<1 秒）。在 64 请求预算下，这是成本最低的增益证据。
