# 降级阶梯（预算或材料不足时的保序收缩）

预算告急或材料残缺时，按阶梯逐级放弃，**每级都保证剩余交付物完整自洽**。降级决定必须写入 `degradation_log`（原因 + 阶段），并在 result.json `status` 反映。

## 阶梯（自上而下逐级降级）

| 级 | 放弃什么 | 保留什么 | status |
|---|---|---|---|
| L0 完整 | — | 六维诊断 + 校验 + 全部产物 | ok |
| L1 | 决策表/决策辅助类增值产物 | 六维诊断 + 编辑计划 + 校验 | ok |
| L2 | low severity 维度（段落关系/重复内容的低危项） | high/medium 全覆盖 + 校验 | ok |
| L3 | 编辑计划的完整展开（只给 op 清单不给长文） | 六维诊断 + 可执行 op 清单 | partial |
| L4 | 机器校验环节的逐条复核（只做抽验） | 诊断 + 已抽验的引文 | partial |
| L5 | 低优先维度诊断 | high 三维（研究问题/论证链/结论边界） | partial |
| L6 | 一切诊断 | 诚实的结果骨架 + 输入清单 + 失败原因 | failed |

## 触发器

- 阶段实际请求 > 预算 150% → 降一级
- 剩余秒数 < 120 且未进入 finalize → 直接跳到当前能完成的最高级
- 材料部分不可读 → 对受影响维度按 L5 处理（不拖垮整体）

## 红线

- 任何级别都不许伪造未完成的检查：跳过的校验在 uncertainty 点名。
- L4 的抽验比例不得低于 30%，且必须覆盖全部 high severity finding。
- 降级后预算回补（如发现误判）可以升级，升级也要记 degradation_log（reason 注明 recovery）。
