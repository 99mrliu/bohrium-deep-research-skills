# 意见分类法（taxonomy）：类型 / 严重程度 / 动作 / 关系 / 裁决

本文件是覆盖矩阵的填写规范。分类只影响统计与证据要求，**裁决与理由才是评分核心**。

## 1. 类型（type，六选一）

| 类型 | 判定规则 | 示例关键词 |
|---|---|---|
| 方法 | 涉及研究设计、模型、算法、参数选择、实验设置、对照 | 「主成分数依据」「为什么用 SNV」「缺少消融」 |
| 数据 | 涉及样本量、数据集、统计显著性、数据质量、外部验证 | 「样本量不足」「补统计检验」「外部验证集」 |
| 写作 | 涉及表述、结构、逻辑、讨论深度、摘要/结论写法 | 「结论过简」「术语不一致」「逻辑跳跃」 |
| 格式 | 纯排版、模板、图表编号、参考文献格式 | 「图 3 缺单位」「按期刊模板」 |
| 伦理 | 知情同意、伦理审批、数据隐私、利益冲突 | 「伦理批号」「数据公开许可」 |
| 其他 | 以上皆非 | — |

一条子要求只取一个主类型；跨类型时按「评审真正想要的产出」归类（要补统计 → 数据；要改写法 → 写作）。

## 2. 严重程度（severity）

- **major**：不处理则结论不成立或稿件不可接收。补做类动作（补实验/补数据/补文献/重做分析）默认 major；「必须/严重/缺乏/根本」等措辞 → major。
- **minor**：润色级别，不撼动结论。「建议/可考虑/typo/minor」等 → minor。
- 拿不准时：影响「结论可信度」→ major；影响「阅读体验」→ minor。

## 3. 可执行动作（action，六选一）

| 动作 | 判定规则 | 证据要求 |
|---|---|---|
| 修改文本 | 可通过改写基线文本完成 | 采纳后必须有 CHG 或 no_change_explanation |
| 澄清解释 | 评审要的是解释/依据，正文可补一句说明 | 解释写进 response_summary；若同时改文本，也要 CHG |
| 补实验 | 要求新实验、新对照、外部验证实验 | **强制** evidence.status |
| 补数据 | 要求更多样本/数据/统计量 | **强制** evidence.status |
| 补文献 | 要求新增/核对引用 | **强制** evidence.status；只引用材料中已出现的来源，不新编文献 |
| 重做分析 | 要求重新统计、换方法重跑、对比/敏感性分析 | **强制** evidence.status |

判定优先级：补实验 > 补数据 > 补文献 > 重做分析 > 澄清解释 > 修改文本（按评审要求的「最重产出」归）。

## 4. 子要求关系（relation）

- **并列**：默认同一条意见内各子要求并列。
- **前置依赖**：B 要先做 A（如「先补数据，再重画图表」），在 B 的 `depends_on` 里写 A 的 sub_id。
- **互斥**：两条意见（或两条子要求）冲突，只能满足其一。在两条上都标 `互斥`，在 decision_reason 里写取舍依据。

## 5. 裁决矩阵决策指南

| 情形 | 建议裁决 | 理由要点 |
|---|---|---|
| 意见合理且可执行 | 采纳 | 一句话说明怎么改、落在哪 |
| 部分合理 / 只能做一半 | 部分采纳 | 说清做了哪半、没做哪半及原因 |
| 意见基于误解 / 与基线事实冲突 | 不采纳 | 礼貌反驳：引基线原文为证，给出澄清，不指责 |
| 意见正确但本演练无法补做（缺数据/摘要基线） | 部分采纳 | evidence.status=无法补做 + alternative_explanation；文本层面能做的仍要做（如加局限声明） |
| 意见含义不明 | 按最稳妥解读裁决 | 列两种解读于矩阵，decision_reason 注明「待人工确认」 |

禁止：无理由采纳（「感谢意见，已修改」空话）、无证据的「已补做」、对无法补做项沉默跳过。

## 6. 常见漏拆模式（核对清单）

1. **连接词藏新要求**：「请说明依据，**同时**增加对比实验」= 2 条（澄清 + 重做分析）。
2. **问号即要求**：「为什么选择 5 个主成分？」即使没写「请」，也是子要求（澄清解释）。
3. **建议句即要求**：「建议补充外部验证」= 补实验，不是可忽略的客套。
4. **一句两件事**：「图 2 缺单位且图注过简」= 格式 + 写作两条。
5. **意见尾巴的附带要求**：「……另外请统一术语」中的「另外」后内容最易漏。
6. **隐含格式要求**：「请按期刊模板调整」可能同时含格式（模板）与写作（重述）两个子要求。
7. **多轮返修的旧承诺**：上一轮「将在修改稿中说明」的承诺，本轮要核查兑现，漏兑现按未覆盖计。
