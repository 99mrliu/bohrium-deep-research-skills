# 问题矩阵：先定义闭合条件，再定向阅读

## 1. 唯一工作顺序

1. 从 `/input/task.md` 提取逐字问题、比较对象、时间/群体/结局限定和 `output_contract`。
2. 在任何全文通读前建立 requirement matrix。根问题可含子问题，但每个最小可答单元必须独占一行。
3. 给每行预登记所需证据种类、允许的回答模式、目标论文区域、断言链接和答案槽。
4. 只按行定位摘要、方法、结果、图表、补充材料及其邻近限定语；找到证据后回到矩阵销项。
5. 反向审计：每个根问题与子问题都有答案或诚实未报告结论，每个答案都有 claim ID，每条 claim 都有 evidence ID。

不要把“读完 PDF”当作完成条件。完成条件是矩阵闭合且答案真正回应任务。

## 2. 最小矩阵列

| 列 | 必填内容 | 失败信号 |
|---|---|---|
| `question_id` / `subquestion_id` | 稳定、唯一、由任务语义命名 | 只有页码或 nanopub ID，没有原问题 |
| `question` | 原问题或不可分割子问题 | 把多个结局塞入一行 |
| `requirement.evidence_kinds` | 如人群定义、效应估计、不确定区间、模型设定、限制 | 只写“相关证据” |
| `requirement.assertion_links` | 预计要支持/排除的断言或任务断言 ID | 结论先行、只找支持材料 |
| 目标区域 | 摘要/方法/结果/表图/补充材料，可带关键词 | 全文平均用力 |
| `answer_mode` | `direct_report`、`computed`、`inferred`、`unreported` 之一 | 把推断写成原文报告 |
| `answer` | 对问题的直接回答；未报告也要明确写“未报告” | 只贴引文或 RDF |
| `claim_ids` | 回答中的可核查原子断言 | 有答案但不能追溯 |
| `evidence_ids` | 支持断言/计算/推断的具体定位 | 悬空 ID、只有论文标题 |
| `status` / `progress_percent` | 闭合状态及不高于状态上限的进度 | 未回答却标 100% |
| `confidence` / uncertainty | 0–1 及限制、异质性、缺失等 | 虚假确定 |

本目录的 JSON 示例使用上述键，但键名不是官方固定 schema。对未见任务，应复制并修改 manifest 的指针和键名，不要更改问题优先原则。

## 3. 拆分规则

- **按疑问词拆**：是什么、多少、为何、何时、在何人群分别建行。
- **按比较轴拆**：不同干预、对照、时间点、亚组、结局分别建行；确需合并时保留显式列表答案。
- **按证据行为拆**：原文直接数值、由多个数值计算、跨段解释推断必须分开。不要用一个 `inferred` 掩盖直接报告缺口。
- **按输出契约拆**：契约要求的 sources、uncertainty、change_records 等工作信息不能代替答案字段。
- **保留父子关系**：父问题给出简要综合回答；子问题保留各自断言和证据。父级状态不得高于未闭合子级允许的整体状态。

## 4. 定向阅读循环

### A. 定位

用问题中的同义词、缩写、结局名称、表图标题和补充材料索引检索。优先读命中的完整语义段落及其定义/脚注，而不是只截取匹配句。

### B. 最小扩读

- 效应值：扩读到人群、干预/对照、时间点和区间。
- 计算：扩读每个输入的定义、单位、分母与来源；保留公式。
- 推断：扩读替代解释、机制证据和作者限制。
- 未报告：扩读摘要、方法、结果、相关图表、补充材料入口及全文同义词命中处。

### C. 链接

每条 evidence 至少含 source ID、稳定 locator、必要引文/数据和 `support`。计算写 `derivation`，推断写 `rationale`。引用证据不能自动证明 answer mode：证据性质与回答者所做推理是两件事。

### D. 销项

只有答案、模式、断言和证据全部一致才闭合。单有检索记录不代表 answered；单有 nanopub 也不代表任务回答完成。

## 5. asked-but-unreported 协议

`unreported` 是“任务问了、来源没有充分报告”，不是“我尚未搜索”，也不是把零、阴性、无显著性或空字符串改写为未报告。

答案应包含：哪个限定问题未报告、已经搜过的来源与区域、使用的关键词/同义词、图表/补充材料检查情况、最近的邻近信息（若给，必须标明不可当作答案）。`searched_scope` 至少一项，推荐结构化记录 `source_id`、`regions` 和 `actions`。

若来源明确写 “not reported”，可将其定位与引文记录到 `searched_scope` 的 actions/披露检查中，但答案模式仍为 `unreported`，不要凭空生成效应 claim，也不要把披露引文当作问题实证答案填入该行的 factual claim/evidence 数组。

## 6. 最终反向检查

从任务逐字朗读一遍，每问指向矩阵行，再从每行跳到 result 中对应答案。之后从 result 的每个 claim ID 跳到断言注册表，再跳到 evidence/source/locator。最后检查：缺失答案、重复 ID、悬空 ID、无范围未报告、错误模式、超上限状态、未披露的 uncertainty/change_records，以及 EXACT 顶层偏差。
