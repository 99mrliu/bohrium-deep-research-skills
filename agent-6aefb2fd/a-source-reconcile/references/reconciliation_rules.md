# 对账与主源裁决规则（source_audit.py 实现的确切规则）

本文件是裁决依据的完整记录：报告中关于"两个来源是否一致、以哪个为准"的每一句话
都必须能指回本文件的具体条款。

## 1. 配对规则

两张表参与对账的条件：列名集合的 Jaccard 相似度 ≥ 0.8。列集合不同（Jaccard < 1.0）
但仍 ≥ 0.8 时，裁决直接为 `schema_divergent` 并列出各自独有列，不做单元格级比较。

## 2. 单元格等价规则

- 数值列：`numpy.isclose(rtol=1e-9, atol=1e-12, equal_nan=True)`。CSV 经文本解析的
  浮点与 SQLite 的 REAL 在该容差内视为同一值；超出容差即记为差异。
- 非数值列：转为字符串并去除首尾空白后逐字符比较。
- 缺失：一侧缺失另一侧非缺失即差异（记入 diff，类型为 NA-mismatch）。

## 3. 裁决等级

| verdict | 含义 | 处置 |
|-|-|-|
| content_identical | 行数相同且全部共同列零差异 | 任一来源可作主源，按 §4 得分取高者 |
| row_count_divergent | 行数不同 | 禁止静默并集/截断；查行数少的来源是否快照不全，在报告中定位缺失行段 |
| content_divergent | 行数相同但存在差异单元格 | 按列报告差异数与示例行；若差异集中在某列，核对该列单位/精度 |
| schema_divergent | 列集合不一致 | 以声明的 materials 与数据字典为准核对字段语义，不得擅自对齐 |

## 4. 主源裁决（得分制，取最高）

- 快照文件（.csv/.tsv/.tab）+2；数据库（.sqlite/.db）+1。
  理由：快照可用 git/diff 工具独立存证，哈希稳定，评审可离线复核。
- 含任意缺失值 −1；含完全重复行 −1。
- 平局时取表 ID 字典序靠前者（确定性规则，与文件遍历顺序无关），并在报告中说明为平局裁决。

## 5. 诚实条款

- 任何非 `content_identical` 的裁决都必须写入最终报告的"数据来源与一致性"一节，
  并进入 result.json 的 `uncertainty`。
- 禁止因为"差异看起来很小"而忽略：差异单元格计数由机器给出，不接受目测豁免。
- 若声明的 materials 有缺失文件，属案例材料异常，必须显式记录，不得用同名猜测文件顶替。

## 6. 已知边界

- 对账按行序对齐；若两来源行序不同（如 SQL 查询未排序），可能出现大量"伪差异"。
  此时先用共同键排序后重跑（脚本按读入顺序对齐，行序敏感是刻意设计：行序差异本身
  也是来源不一致的一种表现，须在报告中说明后再处理）。
- 浮点容差不适用于"单位不同但数值巧合接近"的情形；单位核验属于字段语义核对，
  需结合 task.md 与数据字典人工确认。
