# 清洗规则优先级与会计规则（clean_ledger.py 实现的确切规则）

## 为什么必须有固定优先级

清洗规则会互相影响：先填补缺失再判重复，与先判重复再填补缺失，得到的"完全重复行数"
不同；异常值若先删除，中位数和 IQR 都会移动。没有固定顺序，两次运行或两个人的结果
就不一致。本文件固定顺序如下，任何偏离都必须在台账 notes 中声明理由。

## 规则顺序与论证

| 序 | 规则 | 行动 | 论证 |
|-|-|-|-|
| R1 | 结构修复（列名 strip、登记全空列） | 不改行 | 后续所有规则按列名工作，必须先消除列名噪声 |
| R2 | 完全重复行 | 删（保留首条） | 重复行会污染中位数/众数/分位数，必须先于 R4/R5；UCI Concrete 原始数据含 25 条完全重复记录，属已知情形 |
| R3 | 主键冲突 | 删（保留首条，仅当指定主键） | 语义级重复，晚于语法级重复 R2；无主键信息时跳过而非猜测 |
| R4 | 缺失值 | ≤5% 填补（数值=中位数，类别=众数）；>5% 保留并登记 | 中位数对偏态稳健；>5% 填补会显著扭曲分布，只能保留并声明 |
| R5 | 异常值 | 1.5×IQR 只标记不删除 | 科研数据中极端值可能是真实观测（如高强混凝土）；删除权属于领域判断，不属于通用规则 |

## 会计规则（不可违反）

1. 每条规则登记 `rows_in, rows_out, rows_removed, cells_modified`；不改行的规则
   `rows_removed=0`。
2. 交付前必须满足 `初始行数 − 最终行数 = Σ rows_removed`，不满足即失败（退出码 4），
   禁止交付不平衡台账。
3. `cells_modified` 只统计值被改写的单元格（填补），行删除不计入。
4. 异常值标记以 CSV 行号（首行数据=2）记录，便于人工回查原表。

## 异常分级

- 缺失：≤5% ok；5–20% watch；>20% critical。
- 异常值：0 → ok；≤5% 行数 → watch；>5% → critical。
- watch/critical 条目必须出现在最终报告的"异常说明"与 result.json 的 `exceptions`。

## 已知边界

- "完全重复"按全部列逐值比较；含浮点噪声的近重复不在范围（需要领域容差时，先声明
  容差再扩展 R2）。
- 中位数填补对 MAR/MCAR 合理，对 MNAR 有偏；缺失机制无法在通用规则内判定，
  缺失率 >5% 的列一律不填补正是为此。
- ledger_check.py 的独立重算实现的是默认规则；若通过 rules.json 修改了阈值，
  复核器的 R4/R5 比对需相应说明（恒等式核对与 R2 比对仍然有效）。
