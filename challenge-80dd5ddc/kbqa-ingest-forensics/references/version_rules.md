# 版本判定规则（行政备注优先）

科研资料库中"哪个版本有效"经常不能从文件内容推断——文件名会撒谎、mtime
会被复制操作打乱。本规则给出确定性的优先级，并记录每一步依据。

## 优先级（高 → 低）

1. **行政版本备注**：库内名称含 说明/备注/notes/readme/版本/manifest 等
   字样的文件，其正文中"以 X 为准 / X 为当前有效版本 / Y 已作废"类指认。
   指认必须带原文引文与坐标（`Fxx:L行`），解析不到的措辞不作数。
   同一文件被多条指认冲突时，current 指认优先于作废指认，并在
   lineage.json 的 admin_note_claims 中并列保留全部指认供人工裁定。
2. **文件名版本标记**：`v2 > v1`、`final/最新 > 无标记 > draft/草稿/旧版`、
   文件名内日期（YYYY[MM]）按时间排序。
3. **mtime**：仅在前两级都缺失时使用，并在依据字符串中注明
   "仅 mtime，可信度低"（复制、解包会重置 mtime）。

## 冲突处置

- 行政备注与文件名标记冲突：以行政备注为准，把冲突写入
  repair_ledger（action=needs_attention）并在答案 uncertainty 中复述。
- 两个版本内容关键数值不一致：回答相关问题时并列两个版本的数值与各自
  哈希坐标，注明哪个是当前版本；不得只取其一而不说明。
- 版本组内 text_status 非 ok 的成员：不参与 current 竞争，直接进
  needs_attention。

## 引用版本坐标

任何引用都必须指明所引版本的坐标 `[Fxx|sha256前8位]`。当存在多版本时，
只引用 role=current / current_copy 的文件作为事实依据；引用历史版本
必须明示"历史版本"并说明用途（如对比变更）。
