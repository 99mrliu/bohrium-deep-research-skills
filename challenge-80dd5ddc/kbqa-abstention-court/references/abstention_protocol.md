# 拒答协议（abstention protocol）

"敢说没有"是本 bundle 的核心交付。拒答不是失败，**没有拒答依据的作答
才是失败**。本协议规定拒答的合法形态。

## 拒答的四个必备成分

1. 明确的拒答句："库中无充分依据回答该问题"（禁止含糊措辞如"可能""
   一般认为"）。
2. 检索留痕：引用 coverage_matrix.json 的覆盖率与未命中证据面清单，
   说明"查过哪里"。
3. 缺口说明：缺什么——哪类文件（如"无循环伏安原始数据"）、哪个版本
   （如"仅有 v1，v2 备注称已更新但未入库"）、哪个字段（如"CSV 缺
   scan_rate 列"）。
4. 补救路径：补充什么材料后本问题可答。

## 分级提示的触发场景

- 证据不足 → L2 拒答。
- 证据冲突 → L4 作答但并列冲突双方坐标，或 L3 仅答无冲突部分。
- 文件不可读 / 无文本层 → uncertainty 记录 + 该文件相关证据面按未命中
  处理；若因此跌至 L2，缺口说明中必须点名该文件与所需工具/权限。
- 权限受限 → 同不可读，另在 repair 建议中注明。
- 行政备注与文件内容矛盾 → 冲突登记，以行政备注为准作答并明示矛盾。

## model_verdicts.json（可选申报）

```json
{"verdicts": [{"question_id": "q1", "level": 4,
               "reason": "覆盖率 0.83，唯一冲突为版本差异，已按行政备注消解"}]}
```

申报低于机器等级是允许的（保守方向不惩罚）；申报高于机器等级 ≥2 级
会被回降并留痕。留痕记录进入 result.json 的 uncertainty，评审可见。
