# 核验政策：状态机、处置规程与失败分类学

本文件是 source-truth-gate 的政策层定义。脚本是它的机械执行者；模型是它的
执行代理人。政策与脚本输出冲突时，以脚本输出为事实、以本政策为处置依据。

## 1. 条目核验状态机

### 1.1 状态定义

| 状态 | 触发条件 | 语义 |
| --- | --- | --- |
| verified_identity | (a) DOI 语法合法且命中快照，title/year/first_author 逐字段一致；或 (b) 无 DOI，归一化标题命中快照且 year/first_author 一致（note: by_title） | 条目身份确认，可进入候选文献集 |
| metadata_conflict | DOI 命中快照记录，但 title（归一化比较）/year/first_author 中至少一项不一致 | 身份可定位但元数据有矛盾，需以快照为准修正或隔离 |
| not_found_in_snapshot | DOI 语法合法，快照中既无该 DOI，也无标题匹配的记录 | 快照覆盖不全的信号；**不等于伪造** |
| not_checked | 无 DOI，且归一化标题未命中快照；或标题命中但 year/author 不一致 | 未经核验；任何位置不得写"已核实" |
| suspected_fabricated | (a) DOI 语法非法（不符合 `10.\d{4,9}/\S+` 或含空白）；或 (b) 条目元数据（标题）匹配到的快照记录持有**不同**的 DOI | 疑似伪造或张冠李戴；禁止引用 |
| invalid_input | 输入行不是合法 JSON，或缺少 id/title 必填字段 | 输入级缺陷，先修正输入再重验 |

### 1.2 转移与重验

- 状态由 verify_entries.py 一次性判定；唯一的"转移"途径是修正输入后重新运行
  （修正 entries.jsonl 或更换更全的 snapshot）。
- 允许的修正：以快照为准改写条目的 title/year/first_author（metadata_conflict
  情形），且必须在不确定性说明中记录 old/new/field 三元组。
- 禁止的修正：凭模型记忆给条目补 DOI、补年份、换 DOI；把 suspected_fabricated
  条目"换个写法"重新提交；删除快照记录以消除冲突。

## 2. 各状态处置规程

1. **verified_identity**：进入候选文献集。by_title 确认的条目在使用时注明核验
   路径（无 DOI，按标题核验）。
2. **metadata_conflict**：隔离登记。若任务允许且快照可信，以快照值修正后重验；
   修正前不得引用。冲突字段表（field/entry_value/snapshot_value）原样保留进
   不确定性说明。
3. **not_found_in_snapshot**：隔离登记并标注"未经快照确认"。默认不作为关键
   论断的支撑文献；若 task.md 明确豁免，可使用但必须在成品中显式标注核验
   状态。不得据此删除条目——快照不是全集。
4. **not_checked**：不得写"已核实"；不得作为关键论断支撑；在 result.json 的
   不确定性说明中列出。快照缺失时全库均为本状态。
5. **suspected_fabricated**：隔离登记，禁止引用，禁止修复后复用（除非在输入
   材料中找到该条目真实存在的独立证据，如另一份可信导出、原文 PDF，且该证据
   同样登记入册）。
6. **invalid_input**：回到条目抽取步骤修正 entries.jsonl，重跑脚本。

## 3. DOI 失败分类学

运行脚本只依赖快照，但理解失败谱系有助于正确处置（尤其在评测方提供在线
核验结果作为输入材料时）：

| 类别 | 含义 | 处置 |
| --- | --- | --- |
| transport_error | 网络/解析服务层失败（超时、5xx、DNS） | **零信息量**。不得作为任何判定依据；重试或降级为 not_checked |
| invalid_syntax | DOI 不符合语法规范 | suspected_fabricated（在本工具内） |
| not_found | 注册机构 404：DOI 合法但未注册 | 单独看**不等于伪造**（可能是前瞻性 DOI、注册延迟）；结合元数据交叉验证：若标题/作者/年份与某真实记录高度吻合而 DOI 不同，升级为 suspected_fabricated |
| metadata_conflict | DOI 可解析但返回记录的元数据与条目不符 | metadata_conflict；常见成因：DOI 串号、出版社迁移、条目张冠李戴 |
| redirected | DOI 重定向到另一作品 | 视同 metadata_conflict，检查目标记录元数据 |
| coverage_gap | 快照/数据库未收录 | not_found_in_snapshot；零删除效力 |

核心原则：**任何单一的 DOI 层面失败都不是删除理由**；删除裁决只可能来自
task.md 的明确指令，且证据不足时仍应保留并说明（见 SKILL.md 异常处理表）。

## 4. 何时允许引用未核验条目

默认**不允许**。唯一例外：task.md 以明确文字豁免特定条目或特定类别（例如
"经典教材条目可免于快照核验"），且成品中对该条目显式标注核验状态
（如"该条目按任务豁免未做快照核验"）。豁免条款必须逐字引用进不确定性说明，
不得由模型自行扩大解释。"时间不够""快照太旧""这条显然是真的"均不构成豁免。

## 5. 论断-来源锚点审计的判定语义

- **PASS**：quote 经 NFKC+空白折叠归一化后，是来源文本同样归一化后的子串；
  char_offset 为归一化文本中的命中偏移。locator 若提供，报告其是否在来源中
  出现（仅供参考，不影响 PASS）。
- **FAIL 诊断**：
  - paraphrase_or_minor_alteration：最相似窗口相似度 ≥ 0.80 但非逐字。常见于
    "顺手续写"式引文、标点/虚词改动、删字。处置：改逐字，或改写成明确转述。
  - cross_segment_splice：引文前后两半分别命中来源中相距较远的位置。常见于
    把两句话缝成一句引文。处置：拆成两处引用或改为转述。
  - source_mismatch：来源中无相近文本。常见于记错出处（论断实际来自另一篇）。
    处置：回阶段 0/1 寻找真实出处；找不到则论断降级为证据不足。
- **ERROR**：来源文件缺失/不可读/路径逃逸/字段缺失。先查明来源真伪，查不清
  则论断降级。

## 6. 常见失败模式与修复手册

| 失败模式 | 症状 | 修复 |
| --- | --- | --- |
| 伪造 DOI | DOI 语法非法或指向他文 | 隔离；查输入材料中的独立证据；无则按 suspected_fabricated 结案 |
| 元数据错配 | 条目年份/作者与快照不符 | 以快照为准修正并记录 old/new/field；重验 |
| 转述冒充引文 | claim 带引号但非逐字 | 改逐字引文或去引号改转述，重跑锚点审计 |
| 跨段拼接 | 一句"引文"拼自两处 | 拆分引用或改写 |
| 记错出处 | quote 在声称的来源中不存在 | 全库来源中检索真实出处；改 source 重验；找不到则降级 |
| 悬空引用标记 | 正文有 [n] 但文献表无第 n 条 | 阶段 3 重编号时消除；无法对应到已核验条目的标记删除 |
| 未引用条目 | 文献表有条目但正文从未引用 | 按 task.md 要求处理（删除或移入"延伸阅读"）；删除裁决同上 |
| 快照覆盖不全 | 大量 not_found_in_snapshot | 写明覆盖边界；结论限定在快照覆盖范围内；不得"脑补"核验结果 |
| 模型记忆污染 | 条目中出现了文献库里没有的字段 | 回到文献库原文核对，删去一切无出处字段 |
