# 证据定位符规范（locator-spec）

本规范定义 evidence-anchor 中每条证据（evidence）的定位词汇表与语义，供思维导图节点锚定与审计使用。

## 定位词汇表

| 字段 | 含义 | 取值约定 |
|---|---|---|
| `file` | 材料文件标识 | 必须与 material_intake.py 生成的 pages.jsonl 中 `file` 字段**完全一致**的字符串（通常为命令行传入的相对路径）。审计按此字符串精确匹配文件，不解析路径、不做归一化。 |
| `pdf_page` | PDF 物理页码 | pages.jsonl 中的 `page` 字段，从 1 起按 PDF 页序编号。锚定与审计的**唯一页码基准**。 |
| `printed_page` | 印刷页码 | 材料正文页眉页脚标注的页码，仅供人类阅读与交叉引用，可写入 `section` 或节点 `note`，**不参与校验**。 |
| `section` | 章节定位 | 材料中的章节标题（如"3.2 催化性能测试"），可依据上下文推断，用于缩小人工复核范围；不参与逐字校验。 |
| `quote` | 逐字引文 | 从所引 `file` + `pdf_page` 页文本中逐字复制的**连续子串**。 |

## PDF 页与印刷页的区别

学术 PDF 常含封面、目录、图表页等未编页，导致印刷页码与 PDF 物理页码存在固定偏移（例如印刷第 5 页可能是 PDF 第 7 页）。两种页码各有用途：

- **锚定与机器校验一律使用 `pdf_page`**：它是可复现的物理位置，material_intake.py 与 anchor_audit.py 均以它为准。
- **`printed_page` 仅用于展示与引用**：当任务要求按论文惯例引用"第 N 页"时，可在导图节点的 `note` 中同时给出两种页码，例如"PDF 第 7 页（印刷页 5）"。
- 若发现两者不一致，应在 result.json 的 uncertainties 中注明页码口径，避免下游误用。

## 逐字校验的规范化规则

anchor_audit.py 在比对引文与页文本之前，对两侧施加同一组规范化变换：

1. **空白压缩**：任意连续空白字符（空格、制表符、换行等）折叠为单个 ASCII 空格，并去除首尾空白。由此可容忍 PDF 换行、`pdftotext -layout` 的对齐空格等排版差异。
2. **破折号统一**：Unicode 各类连字符与破折号（‐ ‑ ‒ – — ― −）统一替换为 ASCII 连字符 `-`。
3. **引号统一**：弯引号（“ ” ‘ ’）、角引号（« »）、撇号/秒记号（′ ″）统一替换为 ASCII 直引号（`"` 与 `'`）。

规范化之后执行**子串包含**判定：规范化后的 `quote` 必须是规范化后页文本的连续子串。

## 为什么引文必须是逐字子串

1. **可证伪性**：逐字子串是机器可精确复核的最强证据形式；任何"大意如此"的改写都无法被确定性算法复核，只能依赖信任。
2. **防杜撰**：要求引文逐字出现，使得凭空编造或凭记忆改写的"证据"必然在审计中暴露为 fabricated。
3. **定位唯一性**：逐字匹配失败但能在同文件其他页找到时，可确定性地区分"内容存在但页码标错"（mislocated）与"内容不存在"（fabricated），从而把两类缺陷分开处置。
4. **防污染传导**：思维导图一旦进入下游写作，未锚定的陈述会被当作事实复用；逐字锚定在源头上切断这一污染链。

因此，凡需转述的内容应放入节点 `label`/`note` 并将 basis 标为 summary 或 inference（见 claim-typing.md），而不是改写 `quote`。
