# 关系边证据闸门规则

本文件规定 relation-web 技能中"何种材料依据足以支撑一条关系边"，由 `scripts/relation_gate.py` 机械执行其中可形式化部分，其余由工作流程人工把关。

## 一、依据类型（basis）及其充分条件

### basis = "fact"（材料直述）

充分条件（缺一不可）：
1. `evidence` 非空，含 `file`、`page`、`quote` 三字段；
2. `quote` 在指定 `file` 的指定 `page` 中**逐字出现**（比对前仅做规范化：折叠连续空白、统一 Unicode 破折号与弯引号为直引号；不做同义改写）；
3. 引句须实际陈述所连关系（由人工在摘句时判定：引句中应能找到与关系类型对应的措辞，见 relation-vocabulary.md 的证据模式）。

判定制裁：
- 引句在全部材料中均不存在 → **fabricated**（虚构证据）：拒绝该边，闸门退出码 1；
- 引句存在于同文件的其他页 → **mislocated**（定位错误）：拒绝该边并提示正确页码，修正后可重提；
- `evidence` 缺失或引句为空 → 拒绝（无证据连边）。

### basis = "inference"（综合推断）

充分条件：
1. `note` 非空，写明推断链：由哪些材料事实、经何种推理、得到该关系；
2. `evidence` 可为 `null`；若有支撑性原文亦可附上；
3. 推断边在导图中应与直述边在呈现上可区分（由下游渲染负责，本模式以 basis 字段承载）。

判定制裁：`note` 为空 → 拒绝。推断不得伪装为直述：凡材料确有明文者，应以 fact 连边并附逐字引句。

## 二、层级与横链分离原则

- 主题树（nodes.json 的 `parent` 指针）表达"属于/细分"关系；
- 横向边（relations.json）表达跨分支语义关系；
- 若 `from` 是 `to` 的祖先或后代（沿 parent 链任一方向可达），则该关系内容**属于树而非横链**，闸门按"层级冗余"拒绝；
- 处置：删除横边，必要时在树内调整层级或在节点标签/备注中体现该内容。

## 三、对称规则

- `contrasts_with` 与 `conflicts_with` 为对称关系：连了 A→B 即应连 B→A；
- 缺互逆边不拒绝（可能是图幅取舍），但闸门记 **warning**，应在 result.json 的 uncertainty 或边的 note 中说明取舍理由；
- 其余八种类型均为有向关系，方向须与材料措辞一致（详见词表"方向性"条目）；方向错误不触发闸门机械判定，属于工作流程第 4 步的人工责任。

## 四、时间无环规则（DAG 规则）

- 全部被接受的 `precedes` 边构成的有向子图必须是无环图；
- 任何环（如 A→B→C→A）意味着至少一条边的方向或依据有误：材料中的真实时序不可能成环；
- 闸门检出环时报 **error**，退出码 1；处置：复核环上各边的材料依据，删除或反转错误边后复跑。

## 五、其他形式规则（闸门执行）

1. **端点存在**：`from`、`to` 必须出现在 nodes.json 中，否则拒绝；
2. **类型合法**：`type` 必须属于十元词表，否则拒绝；
3. **无自环**：`from == to` 拒绝；
4. **重复边**：相同 `(from, to, type)` 保留首条，其余拒绝并标注首条 id。

## 六、数值冲突处置（conflict_scan.py 辅助）

- 同一 `(键, 单位)` 在不同节点或材料页出现 ≥2 个不同数值 → 冲突候选；
- 处置二选一：
  a. 两侧陈述均可逐字定位 → 建立（宜双向的）`conflicts_with` 边，`basis=fact`；
  b. 无法判定孰是或语境不明 → 在 result.json 的 uncertainty 列表登记键、全部取值及出处；
- 候选为启发式产物，可能误报（语境不同）或漏报（非数值冲突），须经人工裁定后方可落边。
