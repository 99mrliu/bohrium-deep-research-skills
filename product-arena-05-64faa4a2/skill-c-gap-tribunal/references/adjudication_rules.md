# 冲突裁决规则

本文件定义 gap-tribunal 对"同一参数多来源取值不一致"的裁决规则。
`scripts/conflict_matrix.py` 的建议输出与本文件一致；最终裁决可因材料性质调整，
但**任何偏离都必须留记录**。

## 1. 来源优先级（高 → 低）

1. **运行日志**（.log/.out）：实际发生的运行，证据力最强。
2. **配置文件**（.yaml/.yml/.json/.toml/.ini/.cfg）：意图的显式声明。
3. **脚本默认值**（.py/.sh 中的默认参数）：未被覆盖时的取值。
4. **草稿/转述**（.md/.txt/.tex）：二手陈述，最易失真。

助记：**日志优先于草稿，配置优先于记忆**。
注意例外：若日志时间早于配置修改时间，或日志明确标注 `override`，
应按时间线与 override 标注裁决，并在记录中说明。

## 2. 冲突与观测的区分

- 同一文件内同一键的多个取值（逐 epoch 的 loss、acc、学习率调度等）
  是**观测（时间序列/计数器）**，不是冲突，不参与裁决。
- 同一键在 ≥2 个文件各为单值且取值不同，才是**冲突**。

## 3. 双值并陈的条件

满足以下任一条件时，正文必须双值并陈（同时写出两个值及各自来源），
再给裁决结论，禁止悄悄选边：

- 冲突参数属于关键参数（epochs、lr、batch_size、seed、数据划分比例等，
  脚本中 blocking=true）；
- 较高优先级来源本身可信度存疑（如日志截断、配置被注释）；
- 两来源优先级相邻（如日志 vs 配置）。

非关键参数且优先级差距明显时（如草稿笔误 vs 日志），可在正文用裁决值，
但脚注或修改记录中仍须注明被否决值及其来源。

## 4. 裁决记录格式

每条裁决必须在章节产物（或 result.json 的修改记录）中留痕：

```
【裁决】参数 epochs：config.yaml:5 = 300 与 train.log:1 = 500 冲突。
        按规则"运行日志 > 配置文件"取 500。
        依据：train.log:1 为实际运行记录；config 可能未同步。
        状态：待作者确认（G00x）。
```

字段：参数名、各来源值与 file:line、采用的规则、理由、确认状态。

## 5. 阻断性冲突

blocking=true 的冲突未裁决前，相应小节结论一律标注 partial，
不得写成确定性陈述。若作者确认通道不可用，按第 1 节优先级暂取，
并在 uncertainty 字段显式列出。
