# 缺口分类学与标准追问措辞

本文件定义 gap-tribunal 的缺口分类、证据状态阈值与追问措辞模板。
脚本 `scripts/gap_audit.py` 的判定阈值以本文件为准。

## 1. 证据状态阈值（六要素通用）

对每一要素（步骤 / 实验设置 / 参数与来源 / 数据集与划分 / 对照 / 复现与限制）：

| 状态 | 判定 |
| --- | --- |
| sufficient | 命中证据 ≥3 条，且覆盖 ≥2 类探针，且该要素的 must 面向（若定义）有命中 |
| thin | 有命中但不满足 sufficient 条件；或 must 面向（如"数据集版本与获取"）无命中 |
| missing | 命中 0 条 |

must 面向的设计意图：某要素"看似有证据"但关键面向缺失时（如只出现数据集名字、
没有版本号与获取方式），不得判 sufficient，必须降级为 thin 并生成针对性追问。

## 2. 缺口分类

| 类别 | 含义 | 典型信号 |
| --- | --- | --- |
| 材料缺失 | 所需材料根本不在输入中 | 无论文 PDF、无数据说明、无配置 |
| 版本不明 | 有名称无版本 | dataset: cifar10 但无 version/url/sha；torch 无次版本 |
| 冲突未决 | 多来源取值不一致 | config 300 轮 vs log 500 轮（交 conflict_matrix） |
| 权限不足 | 材料存在但不可读/不可得 | 数据需申请、私有仓库、PDF 解析失败 |
| 无法判断 | 材料之间不构成可判证据 | 草稿称"按官方设置"但未给官方出处 |

## 3. 标准追问措辞模板（写入"待作者确认"段）

编号规则：G001、G002……，按六要素顺序生成，正文与 gaps.json 中保持一致。

- 材料缺失：`【{G编号}】材料中未见{要素}的任何证据。请提供{具体材料}，否则本章相应小节只能标注"材料缺失，无法撰写"。`
- 版本不明：`【{G编号}】{对象}仅见名称"{名称}"，未见版本/获取方式。请提供版本号、下载链接或校验值（file:line 定位）。`
- 冲突未决：`【{G编号}】参数 {参数名} 在 {来源A}（{值A}）与 {来源B}（{值B}）间冲突。本章按{裁决规则}暂取 {值}，请作者确认。`
- 权限不足：`【{G编号}】{材料}因{原因}不可获取。请提供可访问副本或授权说明；在此之前相应结论标记为 partial。`
- 无法判断：`【{G编号}】现有材料不足以判断{事项}（{理由}）。请补充{所需证据}。`

## 4. 诚实 partial 的写法

当整体任务只能部分完成时（result.json 的 status 应为 partial）：

1. **明示边界**：在 uncertainty 字段逐条列出所有缺口（G 编号）与未决冲突，
   说明每条对章节哪一小节造成影响。
2. **可用部分照交**：证据充足的要素正常成文，并给出来源定位（file:line）。
3. **缺口处留白而非填平**：缺证据处写"待作者确认（见 G00x）"，
   禁止用"典型值""一般认为"补齐。
4. **失败与缺失分开陈述**：运行失败（脚本非零退出、解析异常）与材料缺失
   是两类状态，分别说明原因与已尝试的补救。
5. **禁止编造**：任何无法定位到材料的数值、版本、引用，一律不得进入正文
   陈述句；只能出现在"待作者确认"段。
