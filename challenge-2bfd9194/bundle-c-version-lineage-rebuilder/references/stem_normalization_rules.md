# 词干规范化规则（stem normalization）

E3 候选版本分组的第一步：把文件名剥离成"词干 + 扩展名"。规则实现见 `scripts/lineage.py` 的
`normalize_stem()`，与本文档一一对应。所有比较先做一次 Unicode NFC 规范化。

## 处理顺序

1. NFC 规范化文件名，按最后一个 `.` 拆出扩展名（转小写）。
2. 扩展名为 `.bak`：剥掉 `.bak` 后再取一层扩展名（`a.txt.bak` → stem=`a`, ext=`txt`）。
3. 剥掉末尾的 `~`（编辑器备份尾巴）。
4. 循环套用下列"尾巴剥离"正则直到稳定（每条命中即剥，剥空则停）：

| 规则 | 正则 | 示例 |
|---|---|---|
| 尾序号 | `[ _\-]?\(\d+\)$` | `报告(1).txt` → `报告` |
| 尾日期 ISO | `[ _\-]?\d{4}-\d{2}-\d{2}$` | `log_2024-05-01.txt` → `log` |
| 尾日期紧凑 | `[ _\-]?\d{8}$` | `log_20240501.txt` → `log` |
| 版本号 | `[ _\-]?[vV]\s?\d+(\.\d+)?$` | `report_v2` / `report_V 2` → `report` |
| 中文版本词 | `[ _\-]?(最终版|定稿|副本|备份)$` | `report_最终版` / `数据 备份` → `report` / `数据` |

## 分组与连边

- 分组键 = `(词干, 扩展名)`。组内 ≥2 个成员且 SHA-256 **不全相同** → 候选版本组。
- 组内按 `(mtime, 文件名)` 升序排序（mtime 被拷贝拉平时退化为文件名字典序，确定性），
  相邻对连候选 supersedes 边（旧→新），evidence 记 `size_delta` 与 `mtime_delta`。
- **备注类文件**（文件名含 `备注/notes/version/版本/行政/admin`，大小写不敏感）
  **不参与分组**：行政文本不是版本化文档，防止不同项目的同名 `notes.txt` 被误判为版本链。
- **别名副本**（E2 判定为同内容的非正本）不参与分组，避免别名污染版本链。
- 词干不同即不连 E3 边——哪怕名字看起来"像"（如 `scan_old.pdf` 与 `scan_final.pdf`）。
  这种跨词干的替代关系只有 E1 行政备注（或模型裁定）能连。

## 已知边界

- 不剥离英文 `final/old/new/copy` 等词：误伤面大（如 `final_analysis` 可能是正式名），
  这类关系交给 E1 或模型裁定。
- `report_v10` 与 `report_v2` 的 mtime 相同仅靠字典序时 `v10 < v2`（字符串序），
  属于 mtime 失效场景，需 E1 或模型确认 latest。
