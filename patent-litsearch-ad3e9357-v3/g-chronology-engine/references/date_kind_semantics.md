# 日期口径语义：priority / filing / publication / grant

本技能把专利记录中的日期划分为互斥口径，并**严格禁止混用**。混用口径是专利检索中
最常见、也最隐蔽的错误之一：它直接污染新颖性/创造性判断的基准日、同族归并和期限推算。

## 各口径定义

| 口径 (kind) | 含义 | 常见文本线索（英/中） |
| --- | --- | --- |
| `priority` | 优先权日：本申请主张的最早在先申请的申请日，是评价新颖性/创造性的常用基准日 | priority date, claim of priority；优先权日、优先日、优先权 |
| `filing` | 申请日：本申请向受理局实际提交的日期，是保护期起算与程序期限的基准 | filing date, application filed；申请日 |
| `publication` | 公开日/公布日：申请文本向公众公开的日期（通常为申请日或优先权日起 18 个月，但仅为经验规律，不得反推） | publication date, published；公开日、公布日 |
| `grant` | 授权日：专利被授权公告的日期（美国专利常见 “Date of Patent”）；维持费窗口自该日起算 | date of patent, granted, issue date；授权日、授权公告日、颁证 |
| `unknown` | 无法从邻近文本判定口径的日期——诚实的兜底类别，**不是缺陷** | （无可靠线索） |

论文另有 online（上线）与 print（见刊）日期，两者可能相差数月；若任务涉及论文，
亦应分别标注，且不得与上述专利口径混排（本技能的 kind 集合不含论文口径，
遇到论文日期应按 unknown 处理并在 uncertainty 中说明，或按任务要求另行标注）。

## 为什么混用是错误

1. **优先权日 ≠ 申请日**：一件 2019 年提交、主张 2018 年优先权的申请，
   其新颖性基准日通常是 2018 年优先权日，而 20 年保护期通常自 2019 年实际申请日起算。
   把两者混为一谈会同时算错“现有技术截止线”和“届满日”。
2. **公开日 ≠ 授权日**：公开只说明文本可见，授权才产生专利权；两者可相隔数年。
   用公开日推算维持费窗口必然错误。
3. **顺序基线只是启发式**：常规情形 `priority ≤ filing ≤ publication ≤ grant`。
   出现违反（如授权日早于申请日）通常意味着著录错误、OCR 错乱或成员归属错误，
   必须生成冲突记录并回查原文，而不是“顺手改正”。
4. **同族核查的法律意义**：主张同一优先权的成员应具有相同的优先权日；
   观测到不同优先权日即构成 `family_priority_conflict`。
   同时必须记住：**观测链接不构成完整同族**，一致性结论仅限观测范围，不得外推。

## 判定启发式（event_extract.py）

- 关键词表内置英中双语（可用 `--kind-keywords` JSON 覆盖）。
- 证据窗口：日期前 120 字符（在最近的句/行边界 `\n 。 . ! ? ； ;` 处截断，
  防止跨句串扰）+ 日期后 30 字符；就近命中优先，等距取长关键词，后向命中加惩罚。
- 无任何命中 → `unknown` + `UNKNOWN_EVENT_KIND` 警告，绝不猜测。
