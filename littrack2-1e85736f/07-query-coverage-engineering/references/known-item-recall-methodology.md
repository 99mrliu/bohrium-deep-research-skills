# 已知项覆盖验证（known-item recall check）方法学

`scripts/coverage_check.py` 实现的方法。核心思想：追踪链路的召回上限在检索式；
用案例材料中**保留的参考图谱 / 种子文献清单**（已知相关的文献）检验当前检索式
能不能把它们找回来。命中的种子是检索式召回能力的**可验证下界**；漏掉的种子
直接暴露检索式的缺陷，并给出可定位、可修复的诊断。

## 流程

1. **种子定位**：对每颗种子，在各源快照中按标识符精确匹配
   （crossref→doi；europepmc→pmid 然后 doi；arxiv→arxiv_id），
   兜底为规范化后的精确标题匹配。找不到 → `absent_from_snapshot`。
2. **窗口判定**：记录日期在 `case.json` 的窗口外 → `outside_window`（这是窗口问题，
   不是检索式问题）。
3. **查询模拟**：对命中的记录，取 `标题 + 摘要`，逐概念块判定
   "块内任一同义词命中"。块间 AND：全部块命中 → `hit`，否则 → `miss`。
4. **诊断**：对 `miss` 的种子，列出 `missed_blocks`（哪些块把它挡掉了），
   并对每个漏配块给出最小化修订建议（见下）。

## 状态语义（务必区分）

| 状态 | 含义 | 责任归属 |
|---|---|---|
| `hit` | 种子在该源快照存在且被当前检索式命中 | — |
| `miss` | 种子存在但检索式漏检 | **检索式缺陷**，可修复 |
| `absent_from_snapshot` | 种子在该源快照中不存在 | 源未收录或快照未覆盖，**非检索式问题**，须写入遗漏说明 |
| `outside_window` | 种子存在但日期在窗口外 | 窗口设定问题，须写入遗漏说明 |
| `no_snapshot` | 该源无快照数据 | 材料缺失，须写入遗漏说明并考虑 partial |

把 `absent_from_snapshot` 误报为"检索式漏检"是常见诚实性错误：漏检率会被高估，
修订建议也会无的放矢。

## 匹配规则（确定性）

- 大小写不敏感；
- 词边界：term 两侧不得紧邻字母/数字（`GNN` 可命中 `GNN-based`，不命中 `BGNNS`）；
- 词尾单复数容忍：`network` 命中 `networks`，`property` 命中 `properties`
  （规则：`辅音+y` 词尾 → `(?:y|ies)`；`s/x/ch/sh` 词尾 → `(?:es)?`；其余字母词尾 → `s?`）。

不做到这一步，`graph neural network` 会漏掉标题里的 `graph neural networks`，
造成假阴性诊断。

## 最小化修订建议的生成

对漏配块，从该种子记录的标题+摘要中确定性抽取候选新同义词：

1. 候选 = 文本中不含停用词的 n-gram（n=1..3）；
2. 要求与漏配块现有 term 至少共享 1 个 token（保证语义相关，而非随机词）；
3. 排除已是任意块 term 的候选；
4. 排序键：`(-共享 token 数, n 升序, 字典序)`——重叠最多者优先，同分时
   **更短者优先（最小修订）**，字典序保证确定性。
5. top-1 即最小化修订（向漏配块 OR 组追加该同义词）；top-3 作为备选列出。

修订**只增不删**（向 OR 组加同义词不会损害既有命中），因此修订后重跑覆盖验证，
原先 `hit` 的种子必然仍 `hit`——这给出一条免费的回归不变量，自检脚本可直接断言。

## 局限（必须写入 omissions）

- 已知项召回仅针对保留的种子清单；真实全量相关文献的召回率离线不可知，
  本验证是召回能力的可验证下界，不是完整召回证明。
- 建议的新同义词来自种子自身文本，存在"迎合种子"的过拟合风险；
  加入后应复核它是否明显引入噪声（可再跑 lint 的 QL003）。
- 模拟匹配基于 标题+摘要；正文级匹配离线不可行。
