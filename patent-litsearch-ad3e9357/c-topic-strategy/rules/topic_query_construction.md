# 规则：主题检索式构造（概念块方法）

## 1. 概念块方法

把技术主题/科研问题拆成 **2-5 个概念块**（主题模式强制，违反即 R8）：

- 每个概念块对应主题的一个**独立侧面**：通常是 对象/材料、手段/机制、应用/用途、
  问题/效果 中的若干项。块数少于 2 说明没有分解，多于 5 说明粒度过细。
- **块内词项为 OR**（同义词、近义词、上下位词、中英文、常见缩写与全称）；
  **块间为 AND**（每个侧面都必须出现，文献才相关）。
- 概念块分解是模型判断活，脚本不负责替你分块；`build_query.py draft` 只生成
  待补骨架，真正有价值的分解必须由你依据 task.md 与领域知识完成。

## 2. intent 纪律（R6）

每个词项必须带 `intent`：一句话说明**该词为何能识别相关文献**。这是检索式
可解释性的核心，也是与"把主题当关键词丢进搜索"的本质区别：

- 好：`{"term": "aeration", "intent": "membrane aeration 的上位表述，防改写漏检（查全兜底）"}`
- 坏：`{"term": "aeration", "intent": "相关词"}`（没有识别逻辑，视同缺 intent）

写 intent 时标注该词的角色：核心区分词 / 同义扩展 / 上位兜底 / 领域惯用写法 /
缩写全称对照。排除词（NOT）的 intent 必须说明误检来源。

## 3. spec 格式

```json
{
  "topic": "主题一句话",
  "version": "1.0",
  "mode": "topic",
  "blocks": [
    {"name": "块名", "terms": [{"term": "词项", "intent": "识别依据"}]}
  ],
  "facets": {
    "classification": ["C12M 1/00"],
    "applicant": ["某公司"],
    "year_range": ["2015", "2026"]
  }
}
```

- `mode: "topic"`（2-5 块）或 `"number_lookup"`（恰好 1 块，号码精确匹配，R9）。
- 分面可省略；classification 接受 IPC/CPC 截面格式（如 `A01N 63/00`、`C12M1/00`）；
  year_range 为 `[起始年, 截止年]`。

## 4. 结构校验 R1-R9（违规则 exit 2）

| 规则 | 含义 |
| --- | --- |
| R1 | 空块（块无词项/缺块名） |
| R2 | 块内空 OR（词项为空串） |
| R3 | 未声明字段（spec/块/词项/分面出现白名单外键） |
| R4 | 裸 NOT（NOT 前无同块正向词项，或整块皆为 NOT） |
| R5 | 引号不成对 |
| R6 | 词项缺 intent |
| R7 | 分面值格式非法（分类号/年份/申请人） |
| R8 | 主题模式块数越界（须 2-5） |
| R9 | 号码模式必须恰好 1 块 |

## 5. 查全/查准迭代协议

检索式是版本化产物，每次迭代记入 templates/query_log.md：

1. **v1 查全优先**：每块 2-4 个词项，含上位词兜底；不放或只放宽 year_range 分面。
2. **看 search 输出迭代**：
   - 某块零命中（zero_hit_blocks）→ 补同义词/换领域写法/检查语料语言；仍零命中则
     保留该块并在 omissions 如实声明（不得悄悄删块）。
   - 命中过多 → 不是删块，而是提高查准阈值（screen 的 `--min-blocks`）或收窄分面。
   - 误检集中在某干扰主题 → 在同块内正向词之后加 `NOT 干扰词`（R4 禁止裸 NOT）。
3. **停止判据**（满足其二即可停）：
   - 连续两轮迭代命中集合稳定（纳入集合无变化）；
   - 每个概念块要么有命中、要么有书面的零命中说明；
   - PRISMA 计数重算一致，且每条纳入/排除都有理由代码。
4. 版本号递进（1.0→1.1…），result.json 只写最终版，历史版留在 query_log。

## 6. 禁令

- 不得预置任何真实案例的答案、专利号、论文结论进检索式或脚本。
- 不得为追求命中数而删除有 intent 依据的概念块；零命中是**发现**，不是失败。
- 不得把主题整句作为单个关键词使用（那不是检索式，是文本匹配）。
