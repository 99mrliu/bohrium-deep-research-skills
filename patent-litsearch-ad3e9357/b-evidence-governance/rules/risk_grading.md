# 结论风险分级：触发规则与分级口径

> 本文件是 `scripts/risk_grade.py` 规则引擎（R-G1～R-G8）的人读版本。两者保持一致。

## 1. 触发规则与分值

| 规则 | 名称 | 触发条件 | 分值 |
|---|---|---|---|
| R-G1 | 字段缺失 | 结论缺少必需字段（quote / locator / source_kind / status / query_date / sources） | +2/缺项，至多 +4 |
| R-G2 | 状态过期 | 法律状态 query_date 距今 >180 天（90–180 天减半） | +2（90–180 天 +1） |
| R-G3 | 同族口径不明 | family_scope_known=false（观察到的链接不构成完整同族却未声明口径） | +1 |
| R-G4 | 语料覆盖不全 | corpus_coverage=partial（+1）/ unknown（+2）；有限语料未覆盖全部查询目标 | +1 / +2 |
| R-G5 | OCR 不确定 | ocr_uncertain=true，或引文以 match_mode=ocr_tolerant 通过 | +1 |
| R-G6 | 单一来源 | source_count ≤ 1 | +1 |
| R-G7 | 引文未核验 | evidence_verified=false（结论所附引文未通过 quote_audit 回核） | +3 且**强制 low** |
| R-G8 | 法律状态未知 | status_value=未知 | +2 |

## 2. 分级口径

| 置信等级 | 条件 | 输出要求 |
|---|---|---|
| **high** | 总分 0 | 可正常陈述；仍须携带引文与查询日期 |
| **medium** | 总分 1–3 | 陈述时附触发规则说明；复核清单中的事项建议完成后再定稿 |
| **low** | 总分 ≥4，或 R-G7 触发 | 结论必须降级措辞（"初步""待复核"），未完成复核事项前不得作为最终结论；引文未核验的结论**根本不得进入输出** |

## 3. 人工复核清单映射

每条触发规则对应一条复核动作（脚本自动生成 review_checklist.md）：

- R-G1 → 补齐缺失字段；补不齐的写入 uncertainty；
- R-G2 → 重新查询官方登记簿，更新 query_date 与 staleness；
- R-G3 → 写明"仅观察到的链接，不构成完整同族"；必要时人工核查官方同族记录；
- R-G4 → 列出未覆盖的语料缺口，结论限缩到已覆盖范围；
- R-G5 → 回到原件渲染页人工比对 OCR 存疑引文；
- R-G6 → 补第二独立来源；补不到则结论标注"单一来源"；
- R-G7 → 先修引文（重跑 quote_audit），再重新分级；
- R-G8 → 执行登记优先查询；仍未知则保持"未知"措辞。

## 4. 使用要点

1. 风险分级对象是**每条结论**而不是整个案件；同一案件可同时有 high 与 low 结论；
2. 分级报告与复核清单是**交付物的一部分**（写入 /app/output），不是内部草稿；
3. 结论的任何字段变更后必须重新分级，并把变化追加到 result.json 的 change_records；
4. 分级口径刻意从宽到严：拿不准的输入（如 corpus_coverage 填不出）按 unknown 从严计分。
