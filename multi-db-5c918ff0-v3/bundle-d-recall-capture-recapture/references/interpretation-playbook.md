# 解读手册：如何阅读 recall_estimate.json 与 recall_report.md

## 1. 置信区间优先于点估计

点估计 N̂（Chapman 或 Chao1）是「在假设成立时最可辩护的单个数字」，
但决策应基于区间：

- 引用时永远成对：`unseen ≈ 1.6 条（95% CI [0.22, 11.79]）`；
- 区间很宽（上界是点估计数倍）是小样本/弱重叠的正常现象，**不是**
  计算错误；此时结论应落在区间下界（「至少漏了约 X 条」）而非点估计；
- CI 下界被钳在 max(n_i, n_j)（Chapman）或 S_obs（Chao1 对数构造）是
  设计行为：总数不可能小于已观测值。

## 2. 「unseen ≈ 0」证明了什么、没证明什么

- **证明了**：在当前重叠结构下，没有统计证据表明存在大量未检出簇；
  单例很少（f1 小）说明各库互相印证程度高。
- **没证明**：真的没有遗漏。若存在一类文献**所有库都检不到**
  （例如三库共同缺失某地区期刊），它们不进入任何捕获历史，
  capture–recapture 对它们**结构性不可见**。这正是 Chao1 只是下界、
  以及遗漏陈述必须附「画像外来源」限定语的原因。
- 因此「unseen≈0」的合规表述是：「按现有来源的重叠结构，未检出估计
  约为 0（95% CI 上界 k 条）；但不排除存在所有现来源系统性缺失的
  文献类」。

## 3. 来源画像与等可捕获性

- **广谱索引**（crossref 类）vs **利基出版商订阅源**（publisher 类）
  的检出概率天然不同——这不违反假设（模型允许逐库异质），Chao1 用
  f1/f2 对此稳健。
- 真正危险的是**画像差异大到重叠结构不含信息**：例如利基库检出的簇
  几乎全是单例（与任何库不重叠），m_ij ≈ 0，Chapman 无定义，Chao1
  被单例主导而爆炸。此时本技能的做法：**只报告观测重叠事实**
  （捕获历史普查 + 条件覆盖），明说「重叠结构不足以支持可靠点估计」，
  不给漂亮数字。
- 两个库若共享上游索引（收录强相关），违反「无行为响应」，m_ij 虚高、
  unseen 被系统性低估——把两库当作一个来源重跑更诚实。

## 4. 模糊键簇的读法

`fuzzy_only_cross_source_clusters` 列出的簇仅靠 标题+年份+第一作者姓
跨源连接。每一个这样的簇若归并错误（实为两篇不同文献），S_obs 虚减 1、
单例虚增 2，unseen 被低估。报告中的数字对其敏感；复核这些簇是 Agent
在步骤 5 的义务。

## 5. 遗漏陈述模板（必须含数字锚点）

禁止：「可能还有遗漏」「建议再查一些库」这类无量陈述。
合规模板（尖括号内替换为 recall_estimate.json 的实际数字）：

**模板 A（估计可用，descriptive_only=false）**：

> 基于 <k> 个来源的捕获-再捕获分析：去重后观测到 S_obs=<S_obs> 条
> （f1=<f1>，f2=<f2>）。Chao1 下界估计总相关数 N̂=<N̂>
> （95% CI [<lo>, <hi>]），即估计约 <unseen> 条未被任何来源检出
> （95% CI [<ulo>, <uhi>]；点估计≠真实总数，Chao1 为下界）。
> 新增一个检出强度与现有库相近的来源，预期独有贡献约 <r·n̄> 条，
> 参考上限 <uhi> 条。若假设（封闭总体、重叠结构含信息、无行为响应、
> 归并正确）不成立，以上数字失效，仅观测重叠事实有效。

**模板 B（descriptive-only 降级）**：

> 小样本降级（<理由>）：仅报告观测事实——<k> 个来源共检出 <S_obs>
> 个去重簇，f1=<f1>，f2=<f2>；样本量不足以支持统计估计，不能给出
> 未检出数的点估计，遗漏情况无法量化，建议扩充检索来源后重新评估。

**模板 C（重叠结构不含信息 / 估计量分歧）**：

> 观测事实：<k> 个来源检出 <S_obs> 个去重簇，捕获历史为 <模式:计数>；
> 库对 <A>×<B> 零重叠（或估计量分歧 >50%），重叠结构不含可靠的
> 未检出信息，**不给点估计**；如需量化遗漏，须补充与现有来源画像
> 不同且存在真实重叠的数据库。

脚本 finalize 自动生成模板 A/B 的基线版；Agent 改写（含改用模板 C）
须写入 /app/work/omission_statement.md，并将登记于 change_records。

## 6. 真值对照（仅合成示例）

`--truth` 仅用于合成示例验证：报告 N̂ 与真值的误差、真值是否落入
95% CI。真实案例**没有**真值文件——若你在真实案例里「知道」总数，
那它本身就是待估计的对象，不得用作校准。合成示例中 Chao1=16.6 vs
真值 20（误差 −3.4，真值在 CI 内）展示的是 Chao1 的典型下界行为，
不是技能缺陷。
