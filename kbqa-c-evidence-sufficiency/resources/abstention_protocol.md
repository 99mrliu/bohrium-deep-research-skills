# 拒答与冲突处置规程（abstention protocol）

## 何时必须拒答（UNSUPPORTED）

- coverage_matrix 对该问题零可用命中；
- 检索到的片段仅与问题表面相似（同名不同物），经核对不构成证据；
- 证据只存在于"疑似相关但无法核验逐字"的位置。

拒答模板（写进 answer 字段）：

> 库中无依据：本问题要求【所需信息】，但知识库内【已检索范围说明，如"全部 12 份文档、共 1.2 万行文本"】未检索到可核验的逐字证据。缺失：【缺哪类文件/哪个版本/哪个字段】。如需回答，请补充【具体建议】。

## 何时必须并列冲突（CONFLICTED）

- 不同来源（或同一版本链的不同成员）对同一事实给出不同值，且无权威依据可裁决。

冲突模板：

> 库内证据相互冲突：来源 A【坐标】给出 X=【值1】；来源 B【坐标】给出 X=【值2】。两份证据均为可读当前版本，任务说明未指定权威版本，本工作不作取舍。建议人工核对【分歧点，如"转化率定义或测量批次"】。

允许裁决的唯一情况：任务说明或行政版本备注（"以 X 为准"）明确指定权威版本——此时按权威版本作答，被否方移入 caveat 并保留坐标。

## INACCESSIBLE 写法

> 证据疑似存在于【文件名】（如 raw_data/results_2022.csv），但该文件【无读权限/无文本层/格式无法解析】，本工作未引用其内容。需要：【提权 / OCR / 专用解析器】。在获得访问前，本问题按不可答处理。

## 复查顺序（模型作答时的固定顺序）

1. 先看 coverage_matrix 的 `suggested_grade` 与 `sources`；
2. 再看 conflicts.json 是否命中本问题；
3. 然后才决定作答、部分作答、并列冲突还是拒答；
4. 最后在 answers.json 声明裁决，交给 suff_verdict.py 校验——**声明不允许高于机器状态支持的级别**（高于会被降级并记录）。

## 诚实性红线

- 不得把"检索命中"写成"证实"；覆盖不足 0.5 的材料至多支持 PARTIAL。
- 不得编造 missing 的具体内容；不知道缺什么时写"需组织方补充说明该问题所需证据类型"并保留 UNSUPPORTED。
- 不得删除被脚本降级的记录；change_log 中的降级记录原样保留在 result.json。
