# 筛选标准目录（criterion catalog）

稳定 id，决定行的 `criterion` 字段只能取下列值（`apply_decisions.py` 内嵌同一目录做校验）。
一条决定给**最主要**的一条标准；补充理由写进 `rationale`。

| id | 名称 | 含义 | 典型用法 |
|---|---|---|---|
| C-POP | 研究人群/对象 | 人群、物种、样本与任务规定不匹配 | 排除：人群不符；纳入：人群精确匹配 |
| C-TOP | 主题相关性 | 主题/暴露/结局与检索问题不相关 | 排除：跑题；纳入：直接命中研究问题 |
| C-DESIGN | 研究设计 | 设计类型不符（如要求 RCT 而实为观察性/体外） | 排除：设计不符；纳入：设计要求命中 |
| C-DATE | 发表时间窗口 | 发表年份落在任务规定窗口之外 | 仅排除用（窗口内不是纳入理由，只是前提） |
| C-LANG | 语言 | 正文语言不在允许范围 | 仅排除用 |
| C-RTYPE | 文献类型 | 类型不符（综述/社论/会议摘要/预印本等按任务口径） | 仅排除用（除非任务专门征集该类型） |
| C-DUP | 重复记录 | 与已保留记录重复 | 一般由 init_ledger.py 去重处理；人工发现残余重复时用 |
| C-OTHER | 其他 | 以上均不适用 | **必须**在 `rationale` 中给出具体自由文本理由（≥10 字），空泛理由会被拒 |

## 纳入 vs 排除的用法

- **排除**只需一条成立的标准（一票否决），但必须配证据引句。
- **纳入**需要任务规定的全部必要条件同时满足；criterion 填最关键的命中项
  （通常 C-TOP 或 C-DESIGN），其余命中点写进 rationale / rank_rationale。
- C-DATE、C-LANG、C-RTYPE 是“前提筛”：通过它们不构成纳入理由，不通过则构成排除理由。

## 弃权规则（abstain）

- 元数据不足以判断（缺摘要、标题歧义、年份缺失无法判 C-DATE 等）→
  `decision=uncertain`，criterion 填最相关的存疑维度，rationale 说明**缺什么信息**，
  evidence_quote 引用能体现该缺口的现有文本（引标题亦可）。
- **绝不猜测**：宁可 uncertain 进待定列表，也不要把猜测包装成 include/exclude。
- uncertain 不丢人：flow_check 会把待定清单自动写进 omissions，build_result 据此给
  status=partial（除非剩余候选均已有决定）。

## 证据引句（evidence_quote）规则

- 必须逐字摘自**该候选自身**的标题或摘要；脚本按 NFKC + casefold + 空白折叠归一化后
  做子串核验，通不过就拒绝。
- 长度建议 5–30 个词：足以支撑判断，不整段照抄。
- 引句要“指得出”决定依据：排除跑题文献就引体现跑题的短语，不要引无关句。

## 排序理由（rank_rationale）指引

对 include 的候选给出相对排序理由，写清**为什么它比其他纳入项更相关/更可信**，可用维度：
人群匹配度 > 设计强度（RCT > 队列 > 病例系列）> 结局直接性 > 样本量/随访 > 时效（窗口内较新）。
排序理由写进决定行的 `rank_rationale` 字段（可选但建议）；build_result 会带入 result.json。
不要写“很重要”“很经典”这类无信息量措辞；要引用可核查的元数据（年份、设计、样本量）。
