# 六分面覆盖：最低检查点与状态值

SPEC 要求的六个分面必须**全部轮查一遍**。每个分面核查后，Agent 在答题纸
`facet_coverage` 区填入状态值与说明，并置 `"agent_filled": true`；
未填写的分面由 finalize 保守推导为 `unable_to_check`（除非有 accepted
findings 落在该分面，则推导为 `issues_found`）。

## 状态值定义

| 状态值 | 含义 |
| --- | --- |
| `checked_clean` | 该分面全部最低检查点已逐项核查，未发现问题 |
| `issues_found` | 已核查，且至少一条 accepted finding 落在该分面 |
| `partially_checked` | 只完成部分检查点（如超长只抽查、部分材料缺失），须说明查了哪些、没查哪些 |
| `unable_to_check` | 无法核查（抽取失败、材料缺失、超出能力），须如实说明原因 |

## 六分面最低检查点

### 1. 事实核验
- 摘要与正文的数字、结论是否一致（样本量、百分比、p 值、效应量逐一比对）；
- 图表数值与正文叙述是否一致；
- 内部一致性：方法部分描述的流程与结果部分呈现的内容是否对应；
- 明显的事实性/常识性错误（单位、量级、术语误用）。

### 2. 引用支持
- 每个关键论断是否有引用支撑，引用是否真的支持该论断（能核对范围内）；
- 引用条目信息是否完整（作者、年份、期刊/会议），有无明显残缺；
- 是否存在"引用堆砌"或与论断不匹配的引用；
- 禁止编造：核对不了的引用标 `partially_checked` 并说明，不得臆断其内容。

### 3. 方法设计
- 研究设计是否回答研究问题（对照、随机化、盲法是否必要且交代）；
- 样本来源、纳入排除标准是否明确；
- 实验/数据流程是否可复现（参数、工具、版本是否给出）；
- 是否存在明显的设计缺陷（选择偏倚、混杂未控制、循环论证）。

### 4. 统计报告
- 统计方法是否写明（检验名称、显著性阈值、软件）；
- 效应量、置信区间、精确 p 值是否报告（而非只报 "p<0.05"）；
- 样本量依据（功效分析）是否交代；
- 多重比较校正、缺失数据处理是否说明。

### 5. 论证链
- 引言提出的问题 → 方法 → 结果 → 结论是否首尾呼应；
- 结论是否被结果实际支持，有无过度外推（相关当因果、小样本推广总体）；
- 局限性是否如实讨论；
- 反方证据/替代解释是否被处理而非回避。

### 6. 学术规范
- 数据可用性声明、代码可用性声明是否按要求给出；
- 利益冲突、伦理审批（涉及人/动物时）是否声明；
- 作者贡献声明、经费声明是否齐全（按目标期刊要求）；
- 查重/一稿多投/署名等红线问题：只能提示线索，不下定性结论；
- **注意豁免规则**：期刊格式差异与学科惯例不判缺陷
  （见 false_positive_suppression.md）。
