# 信任模型：先取证，再筛查

核心命题：**筛查的可靠性上限 = 输入数据的可靠性上限。** 一条带夹具标记的记录
混入候选集，再精确的术语命中也毫无意义。因此本技能把记录分成两个互不相交的
集合，且分离发生在任何相关性判断之前。

## 三个集合

| 集合 | 定义 | 去向 |
|-|-|-|
| 已解析记录 | 从快照文件中成功解析出的全部记录 | 取证报告的计数基础 |
| 可信记录（trusted） | 通过信任门的记录 | 唯一进入筛查的集合 |
| 隔离记录（quarantine） | 带夹具标记或结构残缺的记录 | 不筛查，但逐条登记去向并嵌入 result.json |

## 信任门判据（forensics.py `trust_gate`，按序判定）

1. **夹具标记**：记录含 `synthetic_duplicate` / `duplicate_of` /
   `conflict_opinion` / `is_fixture` / `fixture` / `synthetic` 任一键 → 隔离。
   类别细分：`fixture_synthetic_duplicate`、`fixture_conflict_opinion`、
   `fixture_labelled`（其余标记）。
2. **结构残缺**：无标题（`title` 为空）→ 隔离，类别 `malformed_no_title`。
   理由：标题是记录身份的最小凭据，无法核验身份的记录不可信。
3. 其余 → 放行。**注意**：缺年份/缺 DOI/缺期刊不触发隔离，而是记入
   `metadata_warnings`，在筛查台账中以 `metadata_warning:*` 理由码随行——
   元数据缺失是"可信度折扣"，不是"不相关"。

## 为什么夹具记录不直接删除

- 它们是**输入事实**：评测方刻意注入的重复/冲突标记本身就是题目的一部分，
  静默删除会让复核者无法区分"没遇到"与"遇到了但藏起来"。
- 隔离登记册为每条记录写明 `disposition`（去向）与 `note`（一句人话理由），
  并作为 `quarantine_register` 字段进入 result.json——**登记即交付**。
- 冲突意见（conflict_opinion）只登记为争议证据，**不做学术裁决**；
  裁决属于人工复核，脚本越权裁决比漏报更糟。

## 文件级取证

每个输入文件登记 sha256、字节数、行数、解析出的记录数、键分布直方图、
异常行（JSONL 坏行、非对象行、表格残缺行、RIS 非标签行）。sha256 让任何
复核者可以验证"我看到的快照与你筛查的快照是同一个文件"；键分布让结构
漂移（如同名字段拼写变化）一眼可见；异常行保证坏数据有据可查而非静默丢弃。

## 状态与信任的关系

- 解析后零记录 → `blocked`（无可信输入，任何结果都是臆造）。
- 存在隔离记录/异常行/法证不一致 → `partial`（如实声明保留项）。
- 全部记录可信、清单全部 authentic、无异常 → 才允许 `complete`。
