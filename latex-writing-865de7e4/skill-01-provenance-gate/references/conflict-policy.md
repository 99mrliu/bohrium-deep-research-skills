# 冲突与缺口处置策略

coverage 报告中的 `conflict` 与 `unmatched` 不是"待清除的报错"，而是需要
Agent 显式处置并留痕的事实状态。本策略规定处置顺序与写法。

## 1. conflict（口径冲突）的处置顺序

1. **task.md 优先**：任务书若指定口径（如"以 data.csv 为准""采用复测值"），
   直接遵循，并在 change_log 记录裁定依据（task.md 行号）。
2. **材料优先级**：无任务指定时按可信顺序裁定——原始数据（.csv/数据文件）
   > 正式论文/PDF > 工程内既有 .tex > 笔记/草稿（.md/.txt）。优先级只是
   默认顺序，Agent 可结合语义反证（如笔记日期更新）推翻，但必须写明理由。
3. **显式标注另一口径**：采用某一口径后，另一口径不得悄悄消失。在正文
   （脚注或括号）或稿件注释中写明"另有材料 X 记载为 Y（file:line）"。
4. **无法裁定**：保留原值并在文中显式标注"口径存疑"，change_log 与
   result.json 的 uncertainty 中各记一条。

## 2. unmatched（材料外内容）的处置

1. **先判断性质**：是常识性表述、Agent 自己引入的推断，还是疑似笔误？
2. **疑似笔误**：弱匹配候选中若存在语义对应的材料条目（如把 92.4% 误写为
   96.0%），由 Agent 确认后改为材料值，change_log 记录"原文→改为→依据"。
   弱匹配只是线索，改之前必须人工打开材料锚点核对原文。
3. **确需保留的材料外事实**：在稿件中显式标注来源缺口（如脚注"该数值未见
   于所提供材料"），并在 change_log 与 uncertainty 记录。
4. **无法佐证又无必要保留**：删除，change_log 记录删除原因。
5. **未知 cite 键**：不得批量替换为脚本给出的相近键。先确认材料 .bib 中
   是否真有对应文献（按标题/作者语义核对）；无对应文献时移除该 \cite 或
   标注缺失，绝不静默改键。

## 3. 缺口（gaps）的处置

- matscan 的 gaps（材料路径不存在、pdftotext 缺失致 PDF 未提取、文件不可读）
  意味着对应材料**未参与取证**：源自这些材料的事实一律按"未核验"对待。
- Agent 应尽量人工阅读可读的缺口材料弥补；无法弥补时在 result.json 的
  uncertainty 中逐条说明影响范围（例如"PDF 未提取，文中 X 处引自该 PDF 的
  数据未经脚本核验，已人工核对/未能核对"）。
- 缺口存在时 finalize 的 status 给 partial 是正常且诚实的结果，不得为了
  "complete"而隐瞒缺口。

## 4. 留痕要求

每处事实性处置（采用、修改、标注、删除）都要能在 change_log.md 中找到
一行，且 source_map.md 中对应条目的「Agent 确认」列已填写。评审应能沿着
`稿件行号 → coverage 条目 → 材料 file:line` 完整回溯。
