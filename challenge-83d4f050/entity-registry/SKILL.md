# Entity Registry

This Skill treats **identity and naming as the primary model**. A picture is a view of the registry, never the authority for resolving biological identity. It is not an evidence-anchor implementation and does not infer claims from pixels.

## Formal run contract

```bash
python3 scripts/entity_registry.py run \
  --input-dir /input --work-dir /app/work --output-dir /app/output
```

The runner reads `/input/case.json`, `/input/task.md`, and `/input/figure-workorder.json` (also accept `/input/artifacts/figure-workorder.json`). Because `/input` is authoritative and may be read-only, copy needed inputs to `/app/work/staged`, preserve the original `case_id` and full `output_contract`, and add the curated `registry`/`mentions` only to the staged case; run with `--input-dir /app/work/staged`. Keep source paths and hashes in the result. It inventories the complete input tree, extracts text (not claims) from paper PDFs with PyMuPDF, reads `figure03*` original/caption text files, and inventories CSV/TSV/JSON data. Put the original at `input/figure03.svg` (preferred), its caption at `input/figure03.caption.txt`, real data under `input/data/`, and papers under `input/papers/`. Optional exact input paths may also be listed in `case.source_files`. An original SVG is retained in `work/original/`, its XML subtree is preserved, and a generated registry layer is appended.

`case.registry` contains the registry described in [references/registry-schema.md](references/registry-schema.md); `case.mentions` contains observed labels and optional species/kind context. Input JSON is the sole source of normalized biological assertions. **No external database, paper text, model prior, or label heuristic silently adds identity.** Read [references/sourcing-and-export.md](references/sourcing-and-export.md) before a production run.

The runner writes `/app/output/result.json` in a minimal `partial` state immediately after reading the case. Final `result.json` dynamically contains every field declared by `case.output_contract`, including unrecognized custom fields (null when no built-in value exists). The usual fields are `case_id`, `status`, `editable_source`, `export_artifact`, `content_map`, `compliance_checks`, and `exceptions`; `sources`, `uncertainty`, and `change_records` are always added. `status` is `success` only when validation, disambiguation, SVG generation, and both exports succeed. Recoverable validation/export runs end `partial` and return 2; fatal input errors end `failed` and return 1. Never interpret a pre-existing result as success.

Outputs include `editable_source.svg`, `export.png`, `export.pdf`, `registry.json`, `registry-audit.json`, `content-map.json`, and `result.json`. SVG strings are generated by Python 3 standard library code. PNG and PDF are regenerated with PyMuPDF (`pymupdf`, with legacy `fitz` fallback). External-network access is neither needed nor used.

## Procedure

1. Load the case and work order; create the partial result before model validation.
2. Audit every canonical ID, required kind-specific name, species, member, locator, alias, and interaction endpoint.
3. Normalize aliases by Unicode NFKC, trimmed/collapsed whitespace, and case folding. **Normalization never merges canonical records.**
4. Resolve mentions only by exact normalized alias plus supplied species and/or kind. Ambiguity is an exception and a nonzero result, not a guess.
5. Derive each glyph, typography, text, and member panel directly from its registry kind and fields. Human gene symbols are italic; proteins (including TP53 protein) are upright; mouse Trp53 remains a distinct mouse gene record.
6. Preserve the supplied SVG source, append the generated layer, export PNG/PDF, and write the audit/content map. Record every source and transform.

## Runnable SYNTHETIC demonstrations

Every example is **SYNTHETIC — NOT A SCIENTIFIC CLAIM**. From this bundle directory:

```bash
python3 scripts/entity_registry.py demo --destination /tmp/entity-registry-validation
# Expected success: 0; deliberate ambiguous/failing case: nonzero.
```

The success example disambiguates the shared normalized alias `p53` using both species and kind. The failure example leaves that alias ambiguous and also verifies rejection. To run either example manually:

```bash
python3 scripts/entity_registry.py run --synthetic \
  --input-dir examples/synthetic/input --work-dir /tmp/er-work --output-dir /tmp/er-output
python3 scripts/entity_registry.py run --synthetic \
  --input-dir examples/synthetic-failure/input --work-dir /tmp/er-fail-work --output-dir /tmp/er-fail-output
```

Production inputs must have `"synthetic": false`; adding `--synthetic` to real work is forbidden. These miniature labels and locators are test fixtures only, not reusable biological conclusions.

## Limits

A registry can attest internal consistency, not biological correctness. PDF extraction is for review and provenance, not automated scientific extraction. Multiple context-free meanings must remain unresolved until the source supplies context or a curator chooses distinct aliases. Automatically positioned SVG is a starting layout; semantic validity does not guarantee publication-quality typography.
