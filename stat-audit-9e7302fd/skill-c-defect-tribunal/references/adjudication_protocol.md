# 对抗裁决庭规程

对每条候选发现执行一次三席程序。目的：在写入审查单之前，用结构化的自我对抗把
"定性错误"和"定级失真"拦下来。程序必须留痕——包括被驳回和被降级的记录。

## 1. 角色

- **提出席**：代表审查直觉，陈述指控。必须给出逐字 quote 与 location，给出提议的
  类别与严重度。允许虚高指控——纠偏是后两席的职责。
- **辩护席**：代表作者立场，回答四个固定问题（见下），逐条给出依据（引用原文他处
  内容时必须同样给出位置）。
- **裁决席**：根据提出与辩护作出裁决，写一句话理由。

同一模型在同一 pass 内依次扮演三席；角色切换时必须显式换视角，不得用提出席的证据
回答辩护问题。

## 2. 辩护四问（逐条作答，写入 `defense.q1..q4`）

- **q1 引用真实性**：指控所引 quote 是否逐字出自原文、未断章取义？（截取半截句子、
  拼接两处文字均视为不真实 → 通常驳回或改类。）
- **q2 他处说明**：原文其他位置（方法、补充材料、图表注释）是否其实已经说明了被指
  缺失的内容？（答"是"→ 驳回，引用该处位置。）
- **q3 未报告 vs 做错**：定性是否混淆了"未报告"与"做错"？现有证据是否足以证明
  "做了且做错"并支持 `internal_evidence`？（不足 → 降为规范问题/证据不足或转待复核。）
- **q4 降级测试**：严重度若降一级，该发现是否仍然成立且后果描述仍然准确？
  （答"是"→ 必须降级；critical 还需给出 `consequence` 说明哪条结论将不成立。）

## 3. 裁决取值

| ruling | 含义 | 后续去向 |
|---|---|---|
| 维持 | 指控的类别与严重度均成立 | 入审查单正文 |
| 降级 | 类别成立、严重度下调 | 入审查单正文（新级别） |
| 改类 | 类别错误，改定新类别（可连带降级） | 入审查单正文（新类别） |
| 转待复核 | 现有材料无法确认，需补材料 | 附录留痕 + 待复核清单（须填 `missing_material`） |
| 驳回 | 指控不成立（q1 或 q2 否决） | 仅入附录留痕（须填 rationale） |

规则：维持要求辩护四问**全部实质作答**（脚本强制）；改类/降级后的最终类别与严重度
写入记录的 `category`/`severity` 字段，原指控可存 `original_category`/`original_severity`
备查。

## 4. 裁决日志（JSONL，每行一条）

必填字段：`id, facet, category, severity, quote, location, defense{q1,q2,q3,q4},
ruling, rationale`。
条件必填：类别=事实错误 → `internal_evidence`；严重度=critical → `consequence`；
ruling=转待复核 → `missing_material`；ruling=驳回 → rationale 必须写明驳回依据。
可选：`original_category, original_severity, note`。
合法性由 `scripts/tribunal_validate.py` 强制；违规即 exit≠0，修复前不得组装审查单。

## 5. 分批纪律（64 次请求预算）

- 每批 5–8 条候选、一个模型 pass 完成三席程序；每批结束立即把裁决追加写入
  `/app/work/adjudication_log.jsonl` 并本地跑一次校验脚本（不耗模型请求）。
- 发现裁决时若需回查原文，先在本批内凭已摘录文本裁决；必须回查的标 `待复核`，
  集中到最后一个 pass 统一处理，避免逐条回查烧预算。
- 任何时刻中断：已落盘的裁决 + result.json 脚手架即可组装 partial 交付。

## 6. 披露义务

审查单附录"裁决留痕"必须列出全部 驳回/降级/改类/转待复核 记录（id、原指控、
裁决、一句话理由）。隐藏被驳回的指控等同于篡改审查记录。
