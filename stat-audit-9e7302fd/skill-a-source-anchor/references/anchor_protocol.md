# 引用优先锚定协议(Quote-First Anchoring Protocol)

本协议是本技能的核心纪律:**无锚不立案**。任何一条审查发现,在写入审查单之前,
必须通过 `scripts/anchor_verify.py` 的机器核验,取得三级锚点。模型凭记忆复述的
"原文"一律视为不可信。

## 1. 三级锚点结构

每条发现必须挂载三级定位,缺一不可:

1. **页**:发现所在 PDF 页码(以提取文本中的换页符 `\f` 分页为准);
2. **章节/表图号**:如「方法-纳入标准」「结果-表2」「讨论-局限性」;
3. **原句摘录**:`quote` 字段,从提取文本中**复制粘贴**的逐字片段,
   并附带核验返回的 `{char_start, char_end, context}`。

审查单的「原文位置」一栏按 `P{页} L{行} › {章节}` 格式填写,
行号取自 `anchor_verify` 输出。

## 2. 如何选取 quote

- **长度 12–40 个字符**:过短(如"P<0.05")会在全文多处命中、无法唯一定位;
  过长则容易因换行/空格差异匹配失败,且超出必要的举证范围。
- **要有区分度**:优先包含数字、专有名词、方法名称的片段
  (如「本研究未进行样本量估算,样本量根据同期门诊可及病例数确定」),
  避免「差异有统计学意义」这类高频套话单独成引。
- **禁止跨页**:quote 不得跨越换页符,否则页级锚点歧义;跨行(同页内)允许。
- **禁止手工转写**:必须从提取文本中复制粘贴。全角/半角差异、空白差异可由
  规范化吸收(见第 3 节),但**字词本身一个都不能改**——改了一个字,
  这条证据就不再是原文。
- 一句原文只能支撑与之直接相关的发现;不要把多条发现挂在同一句摘录上凑数。

## 3. 规范化规则(与 anchor_verify.py 完全一致)

匹配前对原文与 quote 施加同一变换:

1. 全角字符(U+FF01–U+FF5E)转半角;常用全角标点(、。「」""''【】《》—–等)映射半角;
2. 全角空格 U+3000 视为空白;
3. 任意连续空白(空格/制表/换行/换页/全角空格)折叠为单个半角空格,首尾空白去除。

规范化维护「规范化下标 → 原文下标」的可逆映射,因此核验返回的
`char_start/char_end` **始终索引原始提取文本**,可直接用于回查与 context 截取。
规范化只吸收排版差异,**不**做同义词、繁简、错字宽容——字词不一致即判失败。

## 4. 核验失败时的处置(三选一,严禁第四种)

当某条发现的 quote 核验失败(写入 rejects):

1. **重提取**:怀疑是提取失真(乱码、换行错乱)时,回到上游重新提取该页后再引;
2. **重摘录**:回到锚点文本中重新复制粘贴正确的原文片段,再次送检;
3. **降级为「待复核」**:若证据本身只能间接支撑(如原文语义相关但无逐字句),
   将发现明确标注 `待复核`,在「依据」栏说明"未能取得逐字锚点,依据为段落语义",
   并在 uncertainty 中披露。

**严禁**:静默丢弃(审查单看起来"没问题"是最危险的假象)、
静默保留(无锚发现混入审查单)、或手工编造偏移量。

## 5. Rejects 留痕与完备性声明

- `rejects.jsonl` 是交付物的一部分,必须随审查单归档,不得删除;
- 审查单末尾必须附**完备性声明**,内容包括:
  - 送检发现总数、通过数、拒绝数;
  - 每条 reject 的 ID 与拒绝原因;
  - 对每条 reject 的最终处置(重提取成功/重摘录成功/已降级为待复核);
  - 提取保真度判定(引用 source_integrity 的 verdict 及受损项)。
- 声明的意义:让评审者能区分"论文没有缺陷"与"缺陷因取证失败而未能呈现"。
