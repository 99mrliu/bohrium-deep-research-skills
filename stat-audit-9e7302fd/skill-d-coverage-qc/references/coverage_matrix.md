# 覆盖矩阵与裁决语义(coverage_matrix)

本文件定义本套件的三张固定表:六审查面、五态裁决语义、缺陷分类×严重度表,
以及 ledger_check.py 强制执行的完备性规则。裁决时以此文件为准,不得临场发挥。

## 一、六审查面(scoring surfaces)

| 审查面 | 定义 | 典型问题 |
|--------|------|----------|
| 事实核验 | 文中数值、引文事实、内外部一致性能否被核实 | 摘要与正文数值打架;样本量前后不一致 |
| 引用支持 | 被引文献是否真实支持其所在论断 | 引文张冠李戴;综述被当原始证据 |
| 方法设计 | 设计类型、随机化/盲法/对照、变量测量等设计质量 | 设计声称与实际执行不符;混杂未控制 |
| 统计报告 | 统计方法选择、效应量/CI/P 值、多重性等报告质量 | 只报 P 值;检验前提未说明 |
| 论证链 | 从结果到结论的推理是否成立、是否越界 | 相关当因果;结论超出数据 |
| 学术规范 | 伦理、注册、利益冲突、数据共享、报告规范遵循 | 无伦理批件;未声明 COI |

评分会同时按六个审查面与五个检查面(design / variables / statistics /
sample_size / reporting)考察,因此台账单元 = 清单项 × (facet, surface),
每个单元必须落到五态之一,保证两面交叉处无静默遗漏。

## 二、五态裁决语义(five-state adjudication)

| 状态 | 语义 | 理由要求(强制) |
|------|------|------------------|
| 通过 | 已检查,原文满足该检查项 | 建议给出原文位置依据 |
| 问题 | 已检查,确认存在缺陷 | 必须关联至少一个 finding(id 存在于 findings 表) |
| 待复核 | 已尝试检查,但现有材料无法判定 | 必须写明缺什么材料、为何无法判定(非空 reason) |
| 不适用 | 该检查项对此研究设计/情形不适用 | 必须写一句理由(单行,非空 reason) |
| 未检查 | 因预算或材料限制本轮未执行 | 必须写明原因(非空 reason) |

- 五态互斥且穷尽:每个台账单元恰好一个状态。
- 禁止"静默跳过":任何未落入台账的检查项视同流程缺陷。
- "全通过"与"大量未检查"同样可疑,须在审查单完备性声明中解释。

## 三、缺陷分类 × 严重度固定表

四类缺陷(互斥,取最主要的一类):

| 类别 | 高 | 中 | 低 | 提示 |
|------|----|----|----|------|
| 事实错误 | 影响主要结论的数值/事实错误 | 影响次要结论或重要表述 | 细节数值或文字出入 | 轻微不一致,不影响理解 |
| 证据不足 | 核心论断缺乏证据支撑 | 重要论断证据薄弱或间接 | 辅助论断证据不足 | 可补充更直接证据 |
| 规范问题 | 违反伦理/报告规范核心条款 | 违反报告规范常规条款 | 格式与呈现类不规范 | 建议性规范未遵循 |
| 建议 | (不用) | (不用) | 可明显提升质量的改进 | 可选的润色性改进 |

- "建议"类只允许低/提示两档;其余三类四档均可。
- 无法证实真伪的疑似缺陷不得定级,归入"待复核"状态处理。
- 严重度一经按上表确定,不得因"感觉"上调或下调。

## 四、完备性规则(ledger_check.py 强制,违反即不得交付)

1. 五数对账:counts 中五态计数必须与 cells 实算一致,且五数之和 = 单元总数。
2. 每个声明的 facet 至少有一个台账单元。
3. 同一清单项 ID 不得重复裁决(no double-adjudicated item)。
4. "问题"单元必须引用 findings 表中已存在的 finding id。
5. "待复核"/"未检查"单元的 reason 非空。
6. "不适用"单元的 reason 非空且为单行。
7. 每条 finding 的 原文位置(location)非空。
8. 单元状态必须属于五态;surface 属于六面;facet 属于五个检查面;
   finding 的类别/严重度属于上表。
