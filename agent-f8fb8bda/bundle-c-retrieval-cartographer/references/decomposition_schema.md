# 问题拆解规范（decomposition schema）

`scripts/decompose.py` 用确定性启发式从 task.md 抽取研究问题六要素并生成 SQ 骨架；
本文件定义各字段语义与人工补齐规则。

## 1. 六要素定义

| 键 | 中文 | 定义 |
|---|---|---|
| research_object | 研究对象 | 综述聚焦的体系/材料/人群/问题域，须具体到可检索的实体 |
| mechanism_intervention | 机制/干预 | 作用机制、处理手段或调控策略（回答"怎么起作用/做了什么"） |
| comparison | 对照 | 比较的基线或对照对象；无对照的综述可为空集，但须显式说明 |
| outcomes | 结局指标 | 评判效果的可度量指标（性能、效率、稳定性等） |
| time_range | 时间范围 | 证据的发表时间窗（如 2018-2025、近五年） |
| evidence_requirements | 证据要求 | 纳入的证据类型与质量门槛（如同行评审实验研究、综述仅作背景） |

抽取不到的要素置 `TO_FILL` 并在 stdout 提醒。**TO_FILL 不是合法终态**：
Agent 必须结合 case.json 与材料文件人工补齐后才能进入检索规划。

## 2. SQ 验收标准（acceptance_criteria）写法

验收标准回答"什么样的一条文献算回答本 SQ"，必须写成可判定的纳入/排除条件：

- 纳入条件示例："实验研究；报道 {outcomes} 中至少一项；体系属于 {research_object}；
  发表时间在 {time_range} 内"；
- 排除条件示例："纯计算无实验验证；无对照组；指标仅定性描述"；
- 每条标准须引用六要素中的具体取值，禁止"相关即可""质量较好"等不可判定措辞。

## 3. 为什么禁止把原句改写成关键词式拆解

把任务原句直接拆成关键词堆叠（如 "HEO 负极 相变 性能"）会丢失六要素之间的
逻辑关系：哪个是对象、哪个是对照、按什么指标评判。后果是检索式边界漂移、
验收标准无从判定、覆盖矩阵无法映射回研究问题。SQ 的 statement 必须是由要素
拼装成的**完整可检索问句**，关键词只进入 query_cn/query_en 字段。

## 4. 依赖标注规则（depends_on）

- **仅当构造某 SQ 的检索式确实需要另一 SQ 的结果时**才标注依赖。典型情形：
  需要 SQ-1 的背景检索先给出标准术语/同义词表，才能写出 SQ-2 的检索式。
- 不要因为"读起来有先后感"而标注依赖；无真实依赖的 SQ 应保持并行（W2），
  否则浪费波次并可能触发 P4 冲突。
- 依赖构成有向无环图（DAG），成环将被 plan_check P1 判违例并打印环路径。
- 模板默认 `depends_on: []`；人工补依赖时同步检查波次安排（P4）。
