# 取证发现的处置规程

每个 finding 只有三种合法处置，且必须写明定位与理由：

1. **确认为真异常**：回原始文件逐点核对（文件/行/列），确认后进入异常点结论，
   并给出异常程度（偏离量）与判定阈值。
2. **排除为伪迹**：给出排除证据（如饱和段对应设备量程上限的设备日志记录），
   受影响结论降级或限定适用范围。
3. **保留为歧义**：无法确认也无法排除（典型：单位歧义），结论中显式保留两种
   解读，写入 uncertainty，并列入专家确认项。

禁止第四种：忽略。

## 各 finding 的典型解释方向（候选，非结论）

| finding | 常见真实原因 | 常见伪迹 |
|-|-|-|
| identical_files | 同一批次重复导出 | 拷贝覆盖错误 |
| duplicate_data_rows | 采样保持（设备真实行为） | 导出脚本 bug |
| saturation_suspects | 量程截断 | 传感器饱和 |
| constant_columns | 通道失效 | 该列本为设计常量 |
| unit_ambiguity | 不同批次用不同单位 | 表头复制错误 |
| cross_file_overlap | 同源数据两个视图 | 重复提交 |
| hidden_sheets | 中间计算 | 被排除的数据 |

处置时必须用材料内证据（日志、方法段、批次记录）区分左右两列，
不得仅凭「看起来合理」。
