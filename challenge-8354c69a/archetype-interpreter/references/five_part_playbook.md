# 五段结论撰写规程（archetype-interpreter 配套）

每条结论 = 判断 + 数值 + 定位 + 阈值。缺任何一项，该条不算完成。

## 1. 结果趋势
- 写走势（升/降/平台/拐点），不写读数复述。
- 给出所依据的区间、对照、拟合/统计方式（如「峰值 mean±std，IQR 区间 [lo, hi]，见 archetype_findings.json → peak_stats」）。
- 偏离幅度用倍数或标准差倍数表达（「高出对照均值 2.3σ」），不用「明显偏大」。

## 2. 异常点
- 定位到具体对象：样本/批次/通道/孔位/时间点（bending: 具体 trace 文件名；iris: split 编号 × estimator；cefixime: sheet+单元格区域）。
- 异常程度 = 与对照/重复/总体的偏离量；判定阈值必须引用 findings 的 `thresholds` 字段。
- 正常波动不得报为异常：IQR 内的离散不报；脚本未标记的对象若 Agent 自行标记，须给出比脚本阈值更强的理由。

## 3. 可能原因
- 候选清单按证据强度排序；每条候选写：支持证据（定位）、排除证据（做过什么检验）、相关误当因果的风险。
- 只允许三类依据：数据证据（脚本输出/原始文件回查）、材料明示信息（task.md/PDF/日志）、公开常识性方法学（须标注为方法学假设）。
- 没有排除过程的机理猜测，标 `hypothesis_untested` 并写入 uncertainty。

## 4. 复核步骤
- 每条写成第二人可执行的动作：「回查文件 X 的字段/行 Y」「重跑 run_all.py 比对 peak_stats」「对批次 B2 加做 3 个平行重复」。
- 禁止「检查数据质量」「确认实验过程」这类不可执行表述。

## 5. 后续实验建议
- 针对原因候选与证据缺口给改动：补对照、加密采样点、调整参数范围、扩大重复数。
- 每条建议写明它要区分哪两个原因候选、预期观测到什么。

## 契约字段映射提示
output_contract 字段名各异：含「趋势/trend」→第 1 段；「异常」→第 2 段；「原因」→第 3 段；「复核/核查」→第 4 段；「后续/建议/方案」→第 5 段或方案设计；「依据/风险」→证据与风险登记；「确认」→专家确认项（安全、伦理、设备可用性、单位约定）。无法映射的字段不得留空——写清「该字段在本案例中的对应内容与证据」。
