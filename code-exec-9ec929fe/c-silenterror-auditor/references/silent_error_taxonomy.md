# 静默错误分类法与拦截点（silenterror-auditor）

静默错误 = 退出码 0、产物齐全、但结论错误。以下每类给出形态、后果与
本 Skill 的拦截方式。

## 1. 缺失值被当 0（或空串）参与统计

- 形态：`NA`/`--`/空串被 pandas 读成 NaN 后 `fillna(0)`，或 SQL 中
  `COALESCE(col,0)`；均值偏低、std 偏小。
- 拦截：`scan` 报告每列缺失数与"若当 0 均值偏移量"试算；`audit` 的
  `mean/std` claim 口径为**非缺失值**，任何含 0 填充的结果都会 MISMATCH。

## 2. 重复记录未去重就做分组统计

- 形态：仪器重传、多批次合并产生完全重复行或同一样品多行；分组 count
  偏大、均值被重复权重拉偏。
- 拦截：`scan` 报完全重复行数与 SQLite 主键重复；`row_count` claim 与
  分组 count claim 双重钉住行数。

## 3. 哨兵值混入数值列

- 形态：仪器用 -999/999 标记超量程，被当作真实测量；极值与均值全错。
- 拦截：`scan` 报哨兵值计数；`min/max/mean` claim 从原始列重算时若哨兵
  未剔除会暴露（复核者一眼看到 min=-999）。

## 4. 统计检验前提未检查

- 形态：小样本方差悬殊仍用 Student t；非正态硬用参数检验；n<3 报 p 值。
- 拦截：审计不替你选检验——要求在 result.json 中显式写明检验名称、
  前提与检查结果；`count_where`/分组 `count` claim 钉住每组 n，使前提
  是否满足可复核。

## 5. SQL 口径错误

- 形态：`COUNT(col)` 忽略 NULL 与 `COUNT(*)` 混用；JOIN 缺 ON 条件放大
  行数；WHERE 漏一个字段；空结果当正常答案。
- 拦截：`scan` 报各表 NULL 计数、主键重复与无主键表；`sql_scalar` claim
  用只读连接独立重跑同一查询；查询为空时必须在 anomalies 说明已核对
  表名/连接键/WHERE。

## 6. 单位与口径不一致

- 形态：同一列混用 MPa 与 kgf/cm²；有效数字不同导致分组键分裂；清洗
  前后列名变化使图轴与数据字典不符。
- 拦截：单位只能来自数据字典；`distinct_count` claim 钉住分组键基数，
  基数异常（如 178 个样品出现 200 个键）立即暴露。

## 7. 索引与类型错位

- 形态：按位置取列遇上列序变化；数值列混入文本使转换静默丢行；
  浮点 `==` 比较分组键。
- 拦截：`scan` 报混合类型列及文本样例；`audit` 一律按列名取列，任何
  按位置口径的错位都会 MISMATCH。

## 使用纪律

1. 写进 result.json 的每个数字必须有 claim；没有 claim 的数字不许写。
2. MISMATCH 的修法是回到分析步骤，不是改 claim 的 value，更不是调
   tolerance。tolerance 仅用于吸收合法的浮点舍入（默认 1e-9 相对）。
3. UNVERIFIABLE（源文件缺失、列不存在、查询为空）同样是阻断项：它说明
   你的结论无法被复核，等同于没有结论。
