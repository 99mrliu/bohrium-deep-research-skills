# 证据台账格式（evidence_ledger.jsonl）

台账是本技能的核心物证：每行一个 JSON 对象，描述"综述中打算使用的一条证据"。

## 1. 研究问题结构化（阶段 1 产出要素）

| 要素 | 说明 |
|---|---|
| 研究对象 | 谁/什么被研究，写到可指认的粒度 |
| 关键变量 | 自变量、因变量、主要混杂变量 |
| 比较基线 | 与什么比较（现有最佳方法/安慰剂/无干预） |
| 预期结论方向 | 可检验的方向性预期 |
| 可证伪条件 | 观察到什么结果就推翻设想 |

任务文本未给的要素标 `未指定`，并说明该缺失对筛选与结论的影响。

## 2. 台账记录字段

```json
{
  "id": "E1",
  "claim": "准备在综述中使用的陈述（自己的话）",
  "source_file": "paper1.txt",
  "quote": "从来源文件复制粘贴的逐字片段，未做任何改写",
  "locator": "page 3, sec 2.1",
  "char_offset": 1234,
  "check_fields": {"title": "论文标题原文", "year": "2024"}
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 台账内唯一，结论引用它 |
| `claim` | 是 | 综述陈述本身，供人读对照 |
| `source_file` | 是 | 相对 `--sources` 目录的文件路径 |
| `quote` | 是 | 逐字引文；核验的客体；建议 15–80 字，过短易不唯一 |
| `locator` | 是 | 人读定位（页码/小节/行号），信息性字段 |
| `char_offset` | 否 | 归一化全文中的偏移；给出则强制核验 |
| `check_fields` | 否 | 元数据抽查键值，值也必须在来源中找到 |

## 3. 写作纪律

- `quote` 一律从来源文件中**复制粘贴**，禁止手动重打；跨段拼接的引文拆成两条记录。
- 一条记录只装一个可判定的证据点；复合陈述拆开。
- 冲突证据同样入台账，不得选择性登记。
- 结论相反的证据在 `claim` 中如实写其方向，综合阶段再处理取舍。
