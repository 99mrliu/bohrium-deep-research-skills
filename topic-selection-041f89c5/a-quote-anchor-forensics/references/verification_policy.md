# 核验判定规则（anchor_audit.py 的判定依据）

## 归一化

比对前对来源全文与 quote 做同一归一化：Unicode NFKC → 空白折叠（连续空白字符合并为单个空格、去首尾）。这吸收全角/半角差异与换行差异，但不原谅任何字词差异——**改一个字就 FAIL**。

## 判定

| 判定 | 条件 |
|---|---|
| PASS | 归一化 quote 是指定来源归一化全文的子串；出现次数为 1；locator 非空；给出的 char_offset 与 check_fields 全部吻合 |
| FAIL | quote 找不到子串匹配 / 出现多次（锚点不唯一）/ 缺 locator / char_offset 或 check_fields 不吻合 |
| ERROR | source_file 不在来源目录、来源不可解析、JSONL 行解析失败 |

## 常见 FAIL 原因与修复

1. **转述冒充引文**：claim 写成引文样式但字词有出入——回原文重新复制 quote。
2. **跨段拼接**：quote 跨越原文中被省略的段落——拆成两条记录。
3. **记错出处**：quote 真实存在于另一篇文献——改 source_file 并重跑。
4. **锚点不唯一**：短引文在全文出现多次——加长 quote 至唯一。
5. **PDF 提取噪声**：连字符断行、页眉页脚混入——清理提取文本（清理动作本身登记在 inventory），仍对不上则该来源标 `unreadable`。

## 处置纪律

- FAIL/ERROR 记录**不得进入证据矩阵与结论**；修复后重跑，全部 PASS 才允许进入综合阶段。
- 确实修不好的记录：台账中保留并标 `unusable`，在 result.json 的不确定性字段登记条数与原因。
- 退出码 1 表示存在未通过记录；不要把退出码 1 的运行当作"核验完成"。
