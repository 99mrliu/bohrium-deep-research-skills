# 修复审批手册与恢复后语义层清单

## 审批阈值

| 评分 | 处置 |
|---|---|
| ≥ 0.8 且证据自洽 | 可批准（before/after 样本合理、与字典术语吻合） |
| 0.5–0.8 或 ambiguous=true | 必须对照数据字典/工单/单位规则核定；无法核定 → 不批准，相关行/列隔离并写入 review 清单 |
| < 0.5 | 默认隔离，写明原因 |

审批时逐条写一句理由（一行即可），理由进入交付物；这是"每个字段的处理是否有
明确规则和依据"的评分点。`input_sha256` 必须与固证一致，不一致说明文件被换，
立即停止并重新诊断。

## 隔离（quarantine）策略

隔离不是删除：原字面值保留在恢复表中，并在交付物里给出
`{位置, 原值, 故障类型, 未修复原因}` 清单。隔离项计入 result.json 的
不确定性/异常说明字段。

## 可逆性承诺

- 所有批准操作由 `repair_apply.py` 确定性执行，before/after 计数入 `repair_log.json`。
- `roundtrip_check.py` 用独立代码路径重算全流程并比对 sha256；mojibake 修复另做
  字节级往返（修复文本 → encode('utf-8') → decode('latin-1') → 必须等于修复前）。
- 任一核验失败 ⇒ 当次修复作废，回退到审批步骤；**绝不在核验失败时交付恢复表**。

## 恢复后语义层清单（在 recovered.csv 上按工单执行）

1. **缺失分类**：按数据字典把哨兵 token 分类为 未检测/低于检出限/录入缺失/真值 0；
   默认动作是"标记"（增加分类列或按工单置空），**不是填补**。仅当工单对某字段
   显式下令填补且给出规则时才执行，并在台账写明依据。
2. **单位规范化**：只做字典/规则给定的可乘线性换算（如 mg/L ↔ μg/mL 数值相同、
   mg/L → μg/L ×1000）；换算逐格留痕（原值、因子、新值）；未知单位→保留原值并标记。
3. **去重**：按工单指定主键；大小写/空格/全半角归一后比对；键冲突的行**全部保留**
   并写入复核队列，不静默删除。
4. **异常标记**：按 QC 规则的物理上下限标记；分布诊断（如 IQR）只作辅助证据；
   保留/剔除/盖帽的理由逐条写明。
5. **质量报告**：每个数字（缺失率、异常条数、重复组数、转换条数）由脚本从
   清洗产物与台账重算；报告数字必须与结果表一致。
6. **交付**：清洗表、台账、故障报告、roundtrip_verdict.json、result.json
   （含 case_id 与 output_contract 全部字段、status、不确定性说明）。
