# 升级触发器（T1–T6）

模型判定分两类：**可以直接采信的**与**只能作为待复核建议的**。
触发器决定一条记录落入哪类。凡命中任一触发器，模型判定降级为
`pending_human_confirmation`，在人工回填前禁止作为最终结论交付。

| 触发器 | 条件 | 优先级 | 理由 |
|---|---|---|---|
| T1 no_abstract | 摘要缺失（abstract_present=false 或 boundary_flags 含 no_abstract） | P1 | 题录筛选的证据基础不存在，任何方向的建议都是猜 |
| T2 language_mismatch | 语种不符资格标准 | P2 | 资格性判断影响可审性，且可能误排可翻译文献 |
| T3 partial_overlap | 人群/干预/结局部分重叠的边界情形 | P2 | 重叠程度是否构成"符合"是科学判断，非文本匹配 |
| T4 screener_disagreement | 两位标注者标签冲突 | P1 | 实质性争议，禁止用平均或多数掩盖；须第三人仲裁 |
| T5 low_evidence | included 建议但无证据片段 | P3 | 纳入建议的证据链不完整，采信门槛应更高 |
| T6 criteria_ambiguous | 判定注明标准歧义 | P3 | 标准本身待澄清，判定可能随标准版本变化 |

## 优先级排序

队列按 P1→P3 排序：P1 决定综述结论走向（无证据基础或实质性争议），
P2 是资格边界，P3 是证据与标准的完整性。预算有限时先清 P1。

## 触发器的诚实使用

- 触发器只增不减：拿不准时把记录放进队列的成本远低于错误采信；
- 队列规模本身是流程健康指标：queue/total 超过约一半通常意味着标准
  定义不良或材料质量差，应在 result.json 的 uncertainty 中说明，而不是
  悄悄放宽触发器；
- 未命中触发器的记录登记 `auto_accepted_below_gate`——"自动放行"也是
  一条审计记录，不是无记录。
