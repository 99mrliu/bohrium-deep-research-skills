# 等级 → 结论权重映射协议（grade_rules）

## 1. 映射哲学

质量评价的最终目的不是给研究打分，而是**决定每篇研究在结论中能说多重的话**。
本 bundle 采用三档默认语义（可在 rubric.json 中按问题调整，但语义必须写进
`implication`）：

| 等级 | 总分区间（默认） | 结论权重 |
|---|---|---|
| low（低偏倚风险） | [0.8, 1.0] | **可作主证**：结论可以由它独立支撑 |
| some_concerns（有顾虑） | [0.4, 0.8) | **可作支持性证据**：作为主证时需有低危研究同向结论复核 |
| high（高偏倚风险） | [0.0, 0.4) | **只作佐证、不作主证**：正文可提及方向一致性，但任何论断的支撑集不能只靠它；剔除后须重算结论（sensitivity.py） |

核心纪律：**高风险研究不作主证**。如果一条论断在剔除 high 级研究后
支撑清零（unsupported），该论断不得作为综述结论出现——必须改写为
更弱的表述或移入 uncertainty（见 sensitivity_guide.md）。

## 2. implication 写法

`implication` 是写给"综合写作环节"看的指令，要求三条俱全：

1. **能不能当主证**（允许/限制/禁止）；
2. **在正文里怎么标注**（如"证据质量：低危研究为主"）；
3. **触发什么下游动作**（如 high → 触发敏感性分析剔除重算）。

反例（不合格，R3 会拦下空 implication，但拦不下空话）：

- `"该等级研究质量较差"` —— 没有说对结论的影响。
- `"谨慎对待"` —— 不可操作。

正例：

- `"高偏倚风险：只作佐证、不作主证；剔除后须重算结论支撑（敏感性分析）。"`

## 3. 阈值设计建议

- 区间必须无缝覆盖 [0,1]、不重叠（R3 硬校验）；引擎按 `[min, max)` 解释，
  最顶层右端点闭合，因此边界值（如 0.8）归属高一级。
- 阈值要有**方法学理由**并写进 rubric 的注释或 README：例如 0.8 意味着
  "至多一个维度判 some（权重 0.2 时）"。让阈值对应的判定组合可枚举，
  评审者才能复核。
- 不要把 high 的区间设得过宽（如 [0, 0.7)）来"保险"：这会掏空证据库，
  导致大量论断 unsupported，综述退化为"没有结论"。阈值反映的是
  "哪些偏倚大到足以扭曲效应方向"的判断。

## 4. 与 result.json 的衔接

- 每研究的 grade 与逐维度得分进 `evidence_matrix`（经 appraise.py 产出）；
- 综合结论中每条论断标注支撑研究的等级构成；
- 等级→结论权重的实际执行情况进 `checks`（如
  `"no_high_grade_as_primary_evidence": true`）。
