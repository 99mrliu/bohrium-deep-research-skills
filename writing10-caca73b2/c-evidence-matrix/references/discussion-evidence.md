# 讨论证据写法：论断类型学、锚点要求与语气模板

讨论部分的可信度来自"每条论断都能回溯"。本参考给出六类论断的锚点要求
与语气模板，以及"只堆引用"的改法和不一致文献的处理流程。

## 一、论断类型学

### 1. 本研究发现的重述
- **功能**：把结果章节的核心发现以论断形式带入讨论。
- **锚点要求**：至少 1 个自数据锚点 [Dnn]；凡出现数值，锚点须指向
  承载该数值的图/表/统计输出。
- **语气**：直陈。
- **模板**：`本研究中 <发现> [Dnn]。` / `<指标> 在 <条件> 下最高（<数值>）[Dnn]。`

### 2. 与文献一致
- **功能**：把本研究发现放进已有知识坐标，增强可信度。
- **锚点要求**：自数据锚点 + 文献锚点成对出现（[Dnn][Lnn]），
  relation=一致；句中必须出现"一致/相符/吻合/印证"类措辞。
- **语气**：直陈（双方证据都直接）。
- **模板**：`<发现> 与 <作者/文献> 的报道一致 [Dnn][Lnn]，说明 <共性解释>。`

### 3. 与文献不一致 + 可能原因
- **功能**：讨论最有价值的部分；回避不一致是重大减分项。
- **锚点要求**：自数据锚点 + 文献锚点成对出现，relation=不一致；
  句中必须明说"不一致/不符/相悖"；**必须**紧跟可能原因分析，
  原因本身若有依据也要挂锚。
- **语气**：事实部分直陈（"与 Lnn 不一致"），原因部分初步或推测。
- **模板**：
  `值得注意的是，<本研究结论> 与 <文献结论> 不一致 [Dnn][Lnn]。可能原因有：<原因一：材料/方法差异>；<原因二：条件窗口差异>。该不一致提示 <边界条件>。`

### 4. 机制推测
- **功能**：解释为什么观察到这个现象。
- **锚点要求**：挂支撑现象的自数据锚点；若有文献提供机制线索，
  挂文献锚点 relation=机制解释。
- **语气**：推测（单一来源、无直接证据时）或初步（有间接证据时）。
  **不得**因文献支持就升级为直陈。
- **模板**：`据此本文推测，<机制> 可能通过 <路径> 导致 <现象> [Dnn][Lnn]，但尚待 <验证手段> 确认。`

### 5. 局限
- **功能**：诚实声明证据边界。
- **锚点要求**：挂暴露局限的自数据锚点（如样本量来自统计输出 [Dnn]）。
- **语气**：初步或直陈（局限本身是事实，其影响是推断）。
- **模板**：`本研究 <局限事实> [Dnn]，<对结论强度的影响>，故 <相关论断> 仍属初步推断。`

### 6. 结论边界 / 背景定位
- **功能**：说明方法学可比性、结论适用范围。
- **锚点要求**：标准/方法类文献 relation=背景；边界声明挂相应自数据锚点。
- **语气**：直陈（事实）或初步（外推）。
- **模板**：`<方法> 遵循 <标准> [Lnn]，结果具备与同类研究比较的基础。`

## 二、"只堆引用"的反例与改法

**反例**：
> 固化温度显著影响力学性能 [D01]。许多研究关注过固化工艺
> [L01][L02][L03][L04]。

问题：四个文献锚点没有一条说明与本研究是什么关系，属于装饰引用；
build_matrix.py 会以"装饰引用"和"关系未措辞化"报错。

**改法**：逐条建立关系，用不上的文献不引：
> 固化温度对拉伸强度的影响显著（F(2,12)=18.7，p=0.0002）[D03]。
> 孔隙率随温度升高而上升的趋势与 Kumar 等的报道一致 [D04][L02]；
> 但本研究 80 °C 最优的结论与 L03 报道的 100 °C 最优不一致 [D01][L03]，
> 可能原因是树脂体系固化动力学与升温速率不同。
> （L01、L04 与本文论断无直接关系，不引用，由 cite_check.py 记为"未使用"。）

未使用文献如实记 INFO，远好于强行堆砌——堆砌会被审计捕获，
诚实不会。

## 三、不一致文献的处理流程

1. **确认锚点**：本研究结论挂 [Dnn]，对方结论挂 [Lnn]，两者成对出现；
2. **明说关系**：句中写明"与 Lnn 不一致"（relation=不一致），
   不用"略有差异""不尽相同"等含糊措辞绕过审计；
3. **列可能原因**：从材料差异（体系、批次）、方法差异（升温速率、
   测试标准）、条件窗口（温度区间、样本量）三个方向排查，
   每个原因尽量挂锚；无依据的原因标为推测语气；
4. **给出边界**：说明该不一致把结论限制在什么范围内
   （"最优温度可能依赖工艺窗口，而非普适结论"）；
5. **登记台账**：在 claims.json 中 relation=不一致、strength 按
   证据强度定；审计若报"关系未措辞化"，回到第 2 步改措辞，不改台账充数。
